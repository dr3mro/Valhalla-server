Detailed Description

Reusable persistence engine for the API's CRUDS (Create/Read/Update/Delete/Search) operations.

Sits below the request-facing controllers (EntityController and its derived classes). It owns the single DatabaseController obtained from the Store singleton, turns an entity's SQL-builder methods into parameterized statements, executes them, and maps results or failures onto an HTTP status/body pair delivered through a CALLBACK_. Every operation has a synchronous variant (which calls the blocking DatabaseController methods) and a drogon::Task coroutine variant (which awaits the *Coro methods on the Drogon IO loop). 

     Entities are passed by non-const reference because their

getSql*Statement(pqxx::params&) methods fill the parameter bag used by the query; the controller does not take ownership of them. The callback is moved into the operation and is invoked exactly once on every path that returns normally, including validation and database failures. CALLBACK_ is std::function<void(int, const std::string&)>, so the first argument is an HTTP status code and the second a response body (usually serialized JSON). 

     This class is copyable/movable by design: copies share the same

DatabaseController through a std::shared_ptr. No mutable per-instance state is touched after construction, so concurrent use of distinct instances is independent; the thread-safety of the shared DatabaseController itself is not specified here.

Runs one entity statement: builds the parameterized SQL, executes it and reports the result.

Invokes (entity.*sqlstatement)(params); a missing statement maps to 400. A present result that is non-empty maps to 200 with its JSON serialization; empty or absent results map to 400 with a diagnostic body. The chosen func decides whether this is a write or a read. Exceptions are routed through CRITICALMESSAGERESPONSE, which answers 503 for DatabaseBusy and 500 otherwise.
