Detailed Description

Definitions for AppointmentController and its explicit template instantiations.

Each operation is a pure forwarder to EntityController; instantiations at the end of the file make the concrete specializations available to the appointments route layer. 

     In plain words, this file contains the bodies of the small

forwarding methods that were only declared in the header. Each body just passes its arguments on to EntityController, which does the real work (parsing, validation, permission checks, SQL and JSON output). The block of macros at the end forces the compiler to build a concrete version of the class for each appointment type, so the route layer can link to them. There is no extra logic here.

WHY THIS FILE MATTERS IN THE SERVER: Without these definitions and the explicit instantiations, the route registry's shared_ptr<AppointmentController<T>> objects would be declared but never actually compiled, and the program would fail to link (the compiler would report "undefined reference"). This file is called by the appointments route layer through AppointmentControllerBase and calls into EntityController for every job. It turns the appointment interface into working, linkable code.

CONCEPTS TO LEARN (for beginners):

  • Explicit template instantiation (forcing the compiler to build a concrete version): https://en.cppreference.com/w/cpp/language/template_instantiation
  • std::move (transferring ownership instead of copying): https://en.cppreference.com/w/cpp/utility/move
  • C++20 coroutines (functions that pause and resume with co_await/co_return): https://en.cppreference.com/w/cpp/language/coroutines
