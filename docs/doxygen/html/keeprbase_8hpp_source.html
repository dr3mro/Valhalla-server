1/**
2 * @file keeprbase.hpp
3 * @brief Shared base for session/token managers offering session-table and JWT
4 * helpers.
5 * @details This header declares KeeprBase, a base class holding the database
6 * and JWT code that both SessionManager and TokenManager need. It can read and
7 * update session rows, format UTC timestamps, fetch password hashes, and
8 * decode/verify JWTs. It keeps a cached copy of the token parameters (including
9 * the signing secret) and reaches the database through a shared
10 * DatabaseController, so derived managers reuse the same connection pool rather
11 * than opening their own.
12 *
13 * WHY THIS FILE MATTERS IN THE SERVER:
14 * SessionManager and TokenManager both need to touch the session tables and
15 * both need to reason about JWTs. Instead of duplicating that SQL and JWT
16 * logic, they inherit these helpers from KeeprBase. GateKeeper calls those
17 * managers, which call these helpers. Without this shared base, the same
18 * session-table mapping and token-verification rules would be copy-pasted in
19 * two places and could drift apart. The class is abstract-ish (meant to be
20 * inherited), and its members are protected so only derived managers can use
21 * them.
22 *
23 * CONCEPTS TO LEARN (for beginners):
24 * - Inheritance / base class:
25 * https://en.cppreference.com/w/cpp/language/derived_class
26 * - JWT and HS256 signing: https://jwt.io/introduction
27 * - SQL prepared / parameterized statements (avoiding SQL injection):
28 * https://en.wikipedia.org/wiki/Prepared_statement
29 * - std::optional ("a value that may be missing"):
30 * https://en.cppreference.com/w/cpp/utility/optional
31 * - Coroutine / co_await: https://en.cppreference.com/w/cpp/language/coroutines
32 * - Singleton / service locator:
33 * https://en.wikipedia.org/wiki/Singleton_pattern
34 * - RAII (resources tied to object lifetime):
35 * https://en.cppreference.com/w/cpp/language/raii
36 * - [[nodiscard]] (compiler warns if the return value is ignored):
37 * https://en.cppreference.com/w/cpp/language/attributes
38 *
39 * @author Amr Osman <dr3mro@gmail.com>
40 * @date 2026-11-16
41 */

67 /**
68 * @class KeeprBase
69 * @brief Shared base for session/token managers offering session-table and
70 * JWT helpers.
71 * @details KeeprBase centralizes the SQL and JWT logic used by both
72 * SessionManager and TokenManager: reading/updating session rows,
73 * formatting UTC timestamps, decoding and verifying JWTs, and loading
74 * password hashes. It is stateless apart from a cached copy of
75 * TokenManagerParameters; database access goes through a cached
76 * DatabaseController obtained from Store, so instances share the
77 * same pool.
78 * @note Assignment is disabled because the token parameters are cached at
79 * construction; copying/moving is allowed so derived managers can use
80 * normal value semantics.
81 * @see SessionManager, TokenManager
82 * @details For a beginner: this is a "toolbox base class". The two managers
83 * inherit it so they automatically have all these helpers. It caches the
84 * token settings once at construction, which is why assignment is removed -
85 * assigning could silently replace those cached settings. Copy/move
86 * construction is fine because it just carries the settings and the shared
87 * config handle along.
88 */

97 */
