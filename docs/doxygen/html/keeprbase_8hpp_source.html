1/**
2 * @file keeprbase.hpp
3 * @brief Shared base for session/token managers offering session-table and JWT helpers.
4 * @details This header declares KeeprBase, a base class holding the database and JWT code that
5 * both SessionManager and TokenManager need. It can read and update session rows,
6 * format UTC timestamps, fetch password hashes, and decode/verify JWTs. It keeps a
7 * cached copy of the token parameters (including the signing secret) and reaches the
8 * database through a shared DatabaseController, so derived managers reuse the same
9 * connection pool rather than opening their own.
10 *
11 * WHY THIS FILE MATTERS IN THE SERVER:
12 * SessionManager and TokenManager both need to touch the session tables and both need to reason
13 * about JWTs. Instead of duplicating that SQL and JWT logic, they inherit these helpers from
14 * KeeprBase. GateKeeper calls those managers, which call these helpers. Without this shared
15 * base, the same session-table mapping and token-verification rules would be copy-pasted in two
16 * places and could drift apart. The class is abstract-ish (meant to be inherited), and its
17 * members are protected so only derived managers can use them.
18 *
19 * CONCEPTS TO LEARN (for beginners):
20 * - Inheritance / base class: https://en.cppreference.com/w/cpp/language/derived_class
21 * - JWT and HS256 signing: https://jwt.io/introduction
22 * - SQL prepared / parameterized statements (avoiding SQL injection): https://en.wikipedia.org/wiki/Prepared_statement
23 * - std::optional ("a value that may be missing"): https://en.cppreference.com/w/cpp/utility/optional
24 * - Coroutine / co_await: https://en.cppreference.com/w/cpp/language/coroutines
25 * - Singleton / service locator: https://en.wikipedia.org/wiki/Singleton_pattern
26 * - RAII (resources tied to object lifetime): https://en.cppreference.com/w/cpp/language/raii
27 * - [[nodiscard]] (compiler warns if the return value is ignored): https://en.cppreference.com/w/cpp/language/attributes
28 *
29 * @author Amr Osman <dr3mro@gmail.com>
30 * @date 2026-11-16
31 */

51 /**
52 * @class KeeprBase
53 * @brief Shared base for session/token managers offering session-table and JWT helpers.
54 * @details KeeprBase centralizes the SQL and JWT logic used by both SessionManager and
55 * TokenManager: reading/updating session rows, formatting UTC timestamps, decoding
56 * and verifying JWTs, and loading password hashes. It is stateless apart from a
57 * cached copy of TokenManagerParameters; database access goes through a cached
58 * DatabaseController obtained from Store, so instances share the same pool.
59 * @note Assignment is disabled because the token parameters are cached at construction;
60 * copying/moving is allowed so derived managers can use normal value semantics.
61 * @see SessionManager, TokenManager
62 * @details For a beginner: this is a "toolbox base class". The two managers inherit it so
63 * they automatically have all these helpers. It caches the token settings once at
64 * construction, which is why assignment is removed - assigning could silently
65 * replace those cached settings. Copy/move construction is fine because it just
66 * carries the settings and the shared config handle along.
67 */

72 * @brief Caches the configurator and its token parameters from the Store singleton.

74 * avoids repeated lookups and freezes the signing settings for this object.
75 */
76 KeeprBase() : configurator_(Store::getObject<Configurator>()), tokenManagerParameters_(configurator_->get<Configurator::TokenManagerParameters>()) {} // Fetch the shared config, then copy the token settings out of it.
77 KeeprBase(const KeeprBase& other) = default; // Copy is fine: it copies the cached settings and shared handle.
