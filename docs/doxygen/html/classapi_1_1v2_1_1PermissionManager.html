Detailed Description

Central authorization facade: answers "may this requester perform this operation on this entity?".

Overloads are grouped by the concept constraining the entity type (Client_t, Service_t, Case_t, Appointment_t). Most checks load the entity's permission JSON (through PermissionManagerPrivate::getPermissionsOfEntity) and apply the service owner/admin/staff rules; the plain client checks only assert that the requester's group and id match the target client. Every *Async overload is the coroutine counterpart of a synchronous check; those needing permission data use the async (database/cached) lookup. On denial, error receives a status and reason.

Note
Each overload is explicitly instantiated for the supported entity types at the bottom of permissionmanager.cpp; this header only declares them. In everyday words: think of this class as a receptionist who checks ID before letting someone do something. It does not fetch data itself; it asks PermissionManagerPrivate for the facts and then decides.
