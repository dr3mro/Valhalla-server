1/**
2 * @file patient.hpp
3 * @brief Case entity for the `patients` table; the patient record owned by a
4 * clinic.
5 * @details This header declares the Patient class, a small C++ type that stands
6 * for one patient in the `patients` database table. A patient belongs directly
7 * to a clinic, so this class stores the clinic id in a create payload and
8 * checks it directly against the `clinics` table. It holds no data of its own;
9 * it names the table and leaves SQL generation to its parent Case. It is also
10 * the only case entity that builds a "get visits" query, and it supplies
11 * permission-checking SQL helpers for create, read, update and delete.
12 *
13 * WHY THIS FILE MATTERS IN THE SERVER:
14 * Patient is a central clinic-owned "case" type exposed through the clinic
15 * routes as ClinicController<Patient> under the `patients` service type; those
16 * routes also cover search and getvisits. When a client adds or changes a
17 * patient, PermissionManager uses the static getPermissionsQueryFor* helpers
18 * here to confirm the requester belongs to the clinic named in the payload. The
19 * GetVisits helpers return the SQL that lists a patient's visits, used by the
20 * visits feature. Without this file there would be no C++ type connecting the
21 * `patients` table to the CRUD, permission and visits machinery, so patient and
22 * visit endpoints could not work.
23 *
24 * CONCEPTS TO LEARN (for beginners):
25 * - static constexpr: a value fixed at compile time that belongs to the class,
26 * not to one object. https://en.cppreference.com/w/cpp/language/static
27 * - JSON: a text format used to carry request data; this project uses the
28 * jsoncons library to read it. https://jsoncons.github.io/jsoncons/
29 * - `= delete`: explicitly forbidding an operation such as copying, so the
30 * compiler rejects it with a clear error. https://en.cppreference.com/w/cpp
31 *
32 * @author Amr Osman <dr3mro@gmail.com>
33 * @date 2026-11-16
34 */

66/**
67 * @class Patient
68 * @brief Case entity for the `patients` table; the patient record owned by a
69 * clinic.
70 * @details A thin value type binding the generic Case/Entity CRUD machinery to
71 * one table. SQL generation is inherited; this class fixes the table name and
72 * overrides create authorisation: because a patient belongs directly to a
73 * clinic, the create payload's `clinic_id` is checked against `clinics` without
74 * the patient-table join used by the other Case types. This is also the only
75 * Case that builds a visits query; the controller uses it in
76 * GetVisits/GetVisitsAsync (guarded by `requires std::is_same<T, Patient>`).
77 * The static getPermissionsQueryFor* helpers are passed to
78 * PermissionManager for api::v2::Case_t T. The type is registered as
79 * ClinicController<Patient> under the `patients` serviceType, which also owns
80 * search and getvisits routes. Ownership: the wrapper is copied into Entity and
81 * is const thereafter; no mutable state and no locking of its own. Copy and
82 * move are explicitly deleted: create a fresh instance per operation.
83 * @note No default constructor: Entity needs a data wrapper to build statements
84 * from.
85 * @see Case, Entity, PermissionManager, ClinicController
86 */

159 /**
160 * @brief Builds the SELECT that lists all visits of this patient.
161 * @details Resets `params`, binds the patient id held in the Data_t
162 * wrapper, and returns the query over `clinics_visits`.
163 * Controller::GetVisits / GetVisitsAsync execute it with those same params
164 * and serialise the rows back to the caller.
165 * @param[in,out] params Bound parameters, cleared before the patient id is
166 * appended.
167 * @return The `SELECT * FROM clinics_visits WHERE patient_id = $1;`
168 * statement.
169 * @pre The entity must hold a Data_t with an id.
170 * @throws std::bad_variant_access if the stored wrapper is not a Data_t.
171 * @throws std::bad_optional_access if that wrapper has no id.
172 * @note These exceptions are not caught here; the controller's handler
173 * catches them.
174 */

176 // bound id separately.
177 std::optional<std::string> getSqlGetVisitsStatement(pqxx::params& params) {
178 params = {}; // Reset the parameter list so no value from an earlier
179 // call leaks into this query.
180 params.append(
181 std::get<Data_t>(getData())
182 .get_id()
183 .value()); // Pull the Data_t wrapper from Entity, take its id,
184 // and bind it as the first query parameter ($1).

187 // injection.

189 }

191 /**
192 * @brief Builds the SQL that resolves the owning clinic for a create
193 * request.
194 * @details Reads `clinic_id` from `data_j` and calls the Case base's
195 * patient-specific helper, which selects owner/admin/staff directly from
196 * `clinics` where id equals that value. PermissionManager runs the returned
197 * SELECT before the insert; no insert occurs here.
198 * @param[in] data_j Create payload; must be engaged and contain an
199 * unsigned-integer clinic_id (the optional is dereferenced without a
200 * has_value() check).
201 * @return The SELECT statement, or std::nullopt if reading or converting
202 * the key throws; the exception is logged via CRITICALMESSAGE.
203 * @see Case::getPermissionsQueryForCreatePatientImpl
204 */
205 // Returns a query string, or nothing if the payload is
206 // malformed.
207 static std::optional<std::string> getPermissionsQueryForCreate(
208 const std::optional<jsoncons::json>& data_j) {
209 uint64_t id; // Will hold the clinic id pulled from the JSON payload.
210 // Reading JSON can fail (missing field or wrong type), so guard
211 // it.
212 try {
213 // Dereference the optional payload, look
214 // up "clinic_id" and convert it to an
215 // integer.
216 // Any read/conversion problem lands here.
217 id = data_j->at(CREATE_KEY).as<uint64_t>();
218 } catch (const std::exception& e) {
219 CRITICALMESSAGE // Log the failure (macro uses the caught
220 // exception) so the problem is visible in server
221 // logs.
222 return std::nullopt; // No trustworthy id means no safe query
223 // can be built, so report failure to the
224 // caller.
225 }
226
227 return getPermissionsQueryForCreatePatientImpl(
228 id); // Patients own their clinic link directly, so no join table
229 // is needed; Case builds the SELECT from `clinics`.
230 }
