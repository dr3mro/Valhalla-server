Detailed Description

Login, credential and identity data types used by the gatekeeper subsystem.

This header defines two small plain-data structs that act as "containers" passed between the login, session and token helpers. Credentials holds the raw username/password typed by a client. ClientLoginData is a larger bag of optional fields that grows as a login or authentication request moves through the system: some fields come from the request, some from the database, and some are produced when a token is created. Nothing here does any work; it just gives the different helpers a shared vocabulary for the data they exchange.

WHY THIS FILE MATTERS IN THE SERVER: This file belongs to the gatekeeper (the security/identity part of the server). GateKeeper reads the request body into Credentials, then creates a ClientLoginData and passes it to SessionManager (session database rows) and TokenManager (JWT creation/validation). Almost every security function takes a ClientLoginData by reference, so without these types the helpers would need long, duplicated parameter lists and could not share state. Fields are optional because they are filled in at different stages - a field that is nullopt simply means "not known yet" at this stage of the pipeline.
