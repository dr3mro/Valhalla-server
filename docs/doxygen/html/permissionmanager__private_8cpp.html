Detailed Description

The helper functions that turn permission JSON into allow/deny answers. (Originally: "Implementation for permissionmanager_private: Requires staff membership plus the @p powerlevel capability bit.").

These functions look up the requester in a service's owner/admin/staff fields, decode the numeric permission mask, validate creation payloads, and combine the basic checks into rules like "owner, admin, or staff with CAN_READ". Every denial is explained through an Http::Error.

WHY THIS FILE MATTERS IN THE SERVER: It is the engine behind PermissionManager. Keeping the detailed JSON parsing and identity comparisons here means every entity family gets identical rules. Without it, the public manager would have no way to interpret the database's permission document.
