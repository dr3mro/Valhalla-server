Detailed Description

Implementation for logger.

Implements Logger. The constructor reads the server configuration, initialises spdlog's async thread pool, builds a coloured console sink and a rotating file sink with the same pattern, enables only the sinks the config asks for, then registers the logger and wires it into Trantor. log() maps a Trantor severity to the matching spdlog call, and get_color returns the ANSI escape code for each colour name.

WHY THIS FILE MATTERS IN THE SERVER: This is where logging is actually set up and driven. Every log call in the process ultimately reaches these sinks, so the chosen format, file-rotation limits and non-blocking behaviour are decided here. Doing the setup once in the constructor keeps configuration in one place and makes logging fast (messages are queued and written by background threads). Without it, Drogon/Trantor would log with default settings and there would be no unified file output.
