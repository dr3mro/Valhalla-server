2 * @file controller.hpp
3 * @brief Reusable persistence engine for the API's CRUDS (Create/Read/Update/Delete/Search) operations.
4 * @details This header defines the `Controller` class, a template-heavy helper that turns an entity object into SQL
5 * and turns the database's answer into an HTTP status plus a response body. It offers both ordinary
6 * blocking methods (Create, Read, ...) and coroutine versions (CreateAsync, ReadAsync, ...) for the async
7 * server loop. It is meant to be read from top to bottom: first the constructor, then the public CRUDS
8 * helpers, then the two shared `cruds`/`crudsAsync` implementations near the bottom.
9 *
10 * WHY THIS FILE MATTERS IN THE SERVER:
11 * It is the storage engine that sits underneath the request-facing handlers. When an HTTP request arrives, Drogon
12 * routes it to an EntityController / ClientController / ClinicController, and those classes call this Controller to
13 * do the actual work. This class in turn calls DatabaseController (see databasecontroller.hpp) to run parameterized
14 * SQL against PostgreSQL. Without this file the handlers would have no way to insert, read, update, delete or search
15 * rows, and the callback that finally answers the client would never be invoked.
16 *
17 * CONCEPTS TO LEARN (for beginners):
18 * - Templates: https://en.cppreference.com/w/cpp/language/templates
19 * - Pointer-to-member function (used to pick an entity's SQL builder at runtime): https://en.cppreference.com/w/cpp/language/pointer
20 * - std::optional (a value that may be missing): https://en.cppreference.com/w/cpp/utility/optional
21 * - std::shared_ptr (shared ownership of the database service): https://en.cppreference.com/w/cpp/memory/shared_ptr
22 * - Move semantics (std::move / std::forward): https://en.cppreference.com/w/cpp/language/move_constructor
23 * - Coroutines (co_await / drogon::Task): https://en.cppreference.com/w/cpp/language/coroutines
24 * - Lambda expressions: https://en.cppreference.com/w/cpp/language/lambda
25 * - virtual functions / polymorphism: https://en.cppreference.com/w/cpp/language/virtual
26 *
27 * @author Amr Osman <dr3mro@gmail.com>
28 * @date 2026-11-16
29 */

68/**
69 * @class Controller
70 * @brief Reusable persistence engine for the API's CRUDS (Create/Read/Update/Delete/Search) operations.
71 * @details Sits below the request-facing controllers (EntityController and its derived classes). It owns the
72 * single `DatabaseController` obtained from the `Store` singleton, turns an entity's SQL-builder methods
73 * into parameterized statements, executes them, and maps results or failures onto an HTTP status/body pair
74 * delivered through a `CALLBACK_`. Every operation has a synchronous variant (which calls the blocking
75 * `DatabaseController` methods) and a `drogon::Task` coroutine variant (which awaits the `*Coro` methods
76 * on the Drogon IO loop).
77 *
78 * Entities are passed by non-const reference because their `getSql*Statement(pqxx::params&)` methods fill
79 * the parameter bag used by the query; the controller does not take ownership of them. The callback is
80 * moved into the operation and is invoked exactly once on every path that returns normally, including
81 * validation and database failures. `CALLBACK_` is `std::function<void(int, const std::string&)>`, so the
82 * first argument is an HTTP status code and the second a response body (usually serialized JSON).
83 *
84 * This class is copyable/movable by design: copies share the same `DatabaseController` through a
85 * `std::shared_ptr`. No mutable per-instance state is touched after construction, so concurrent use of
86 * distinct instances is independent; the thread-safety of the shared `DatabaseController` itself is not
87 * specified here.
88 * @see EntityController, DatabaseController
89 */
90class Controller

94 * @brief Resolves the shared `DatabaseController` service from the `Store` singleton.
95 * @details All operations depend on that service; resolving it here lets derived request-scoped controllers
96 * stay cheap to construct. `Store::getObject` may create the singleton on first use.
97 * @throws std::runtime_error if the database controller cannot be obtained (a critical message is logged first).
98 */
99 Controller()
100 {
101 try

106 {

108 throw std::runtime_error("Failed to initialize database controller"); // Without a DB gateway this object is useless, so stop construction.
109 }

247 /**
248 * @brief Runs @p entity's search statement and returns a paginated JSON envelope through @p callback.
249 * @details The response object always contains `more` (bool, initially false), `offset` (initially 0) and
250 * `results` (an array; empty when no query or no rows). The search query is built from the `Search_t`
251 * held by the entity. When the returned row count exceeds the requested `limit`, one extra probe row is
252 * fetched (the entity's search builder binds `limit + 1`): it is removed, `more` is set to true and
253 * `offset` advances by `limit`.
254 * @tparam T Entity type exposing `getSqlSearchStatement(pqxx::params&)` and `getData()` convertible to Search_t.
255 * @param[in,out] entity Borrowed entity carrying limit/offset and the search criteria.
256 * @param[in,out] callback Invoked once with 200 and the serialized envelope (or a mapped error status).
257 * @note Exceptions (including `DatabaseBusy`) are turned into an HTTP status by `CRITICALMESSAGERESPONSE`.
258 * @see executeSearchQuery (DatabaseController)
259 */
260 template <typename T>
261 void Search(T& entity, CALLBACK_&& callback)
262 {
263 jsoncons::json response_json;
264 response_json["more"] = false; // Assume no further page until the row-count probe proves otherwise.
265 response_json["offset"] = 0; // Start the envelope at offset zero; a real offset is set when 'more' is true.
266
267 std::optional<jsoncons::json> query_results_json_array; // Holds the rows once the search returns; empty means no query ran.
268 std::optional<std::string> query; // Holds the built SQL; empty means the entity produced nothing to run.
269
270 try
271 {
272 pqxx::params params; // The bag of values bound to the SQL placeholders ($1, $2, ...).
273 // The entity builds both the parameterized statement and its bound values.
274 query = entity.getSqlSearchStatement(params); // Ask the entity to build the SQL and fill the parameter bag.
275
276 if (query.has_value())
277 {
278 query_results_json_array = databaseController->executeSearchQuery(query.value(), params); // Blocking search that maps rows to a JSON array.
279
280 if (query_results_json_array.has_value() && !query_results_json_array->empty())
281 {
282 size_t results_count = query_results_json_array->size(); // Count rows to detect the extra probe row (limit + 1).
283 // More rows than requested means an over-fetch: drop the extra row and advertise the next page.
284 if (results_count > std::get<Search_t>(entity.getData()).limit)
285 {
286 response_json["more"] = true; // An extra row exists, so tell the client another page is available.
287 response_json["offset"] = std::get<Search_t>(entity.getData()).offset + std::get<Search_t>(entity.getData()).limit; // Next page starts after this page's limit.
288 query_results_json_array->erase(query_results_json_array->array_range().end() - 1); // Remove the probe row so the client sees only 'limit' rows.
289 }
290 }
291 }
292 // Absent results still yield a well-formed envelope with an empty array.
293 if (query_results_json_array.has_value())
294 {
295 response_json["results"] = std::move(query_results_json_array.value());
296 }
297 else
298 {
299 response_json["results"] = jsoncons::json::array(); // Guarantee an empty array instead of a null when nothing was found.
300 }
301
302 // Marshal the envelope and answer once.
303 std::move(callback)(api::v2::Http::Status::OK, response_json.as<std::string>());
304 }
305 catch (const std::exception& e)
306 {
307 CRITICALMESSAGERESPONSE // Log a critical error and answer through the callback with a mapped status.
308 }
309 }

598 /**
599 * @brief Runs one entity statement: builds the parameterized SQL, executes it and reports the result.
600 * @details Invokes `(entity.*sqlstatement)(params)`; a missing statement maps to 400. A present result that is
601 * non-empty maps to 200 with its JSON serialization; empty or absent results map to 400 with a
602 * diagnostic body. The chosen `func` decides whether this is a write or a read. Exceptions are routed
603 * through `CRITICALMESSAGERESPONSE`, which answers 503 for `DatabaseBusy` and 500 otherwise.
604 * @tparam S Pointer-to-member type of the entity's SQL builder (deduced).
605 * @tparam T Entity type (deduced); must outlive this call.
606 * @param[in,out] entity Entity whose builder populates @p params.
607 * @param[in] sqlstatement Pointer to the entity builder method to use.
608 * @param[in] func Pointer to the `DatabaseController` executor method (e.g. dbexec/dbrexec).
609 * @param[in,out] callback Invoked exactly once on any returning path.
610 * @note Shared implementation for every synchronous CRUDS helper.
611 */
612 template <typename S, typename T>
613 void cruds(T& entity, S& sqlstatement, std::optional<jsoncons::json> (DatabaseController::*func)(const std::string&, const pqxx::params&),
614 CALLBACK_&& callback)
615 {
616 std::optional<jsoncons::json> results_j; // Will hold the single result object returned by the DB helper.
617 pqxx::params params;
618 try
619 {
620 std::optional<std::string> query = (entity.*sqlstatement)(params); // Call the chosen builder on the entity; it also fills params.
621 // A nullopt statement means the entity could not describe the operation: reject before touching the DB.
622 if (!query.has_value())
623 {
624 std::move(callback)(api::v2::Http::Status::BAD_REQUEST, fmt::format("Failed to get SQL statement for {}.", entity.getTableName()));
625 return;
626 }
627
628 // Dispatch through the selected executor; params are bound placeholders, not string-interpolated values.
629 results_j = (*databaseController.*func)(query.value(), params); // Run SQL through the chosen read/write executor.
630 if (results_j.has_value())
631 {
632 if (!results_j->empty())
633 {
634 std::move(callback)(api::v2::Http::Status::OK, results_j.value().as<std::string>());
635 return;
636 }
637
638 std::move(callback)(api::v2::Http::Status::BAD_REQUEST, "Query returned empty result, please recheck your parameters.");
639 return;
640 }
641
642 std::move(callback)(api::v2::Http::Status::BAD_REQUEST, "Failed to create sql query");
643 }
644 catch (const std::exception& e)
645 {
646 CRITICALMESSAGERESPONSE // Log a critical error and answer through the callback with a mapped status.
647 }
648 }
