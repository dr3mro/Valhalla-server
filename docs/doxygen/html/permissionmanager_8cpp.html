Detailed Description

The implementations of all the permission-check methods. (Originally: "Implementation for permissionmanager: Client creation is unrestricted; see PermissionManager::canCreate.").

Each method here follows the same recipe: work out the service or table name, fetch that entity's permission JSON (through the private helpers), then ask the helper that matches the required right. The Async versions do the same using coroutines.

WHY THIS FILE MATTERS IN THE SERVER: This is where the actual allow/deny decisions are executed for every route. Controllers call these methods before touching data. The bottom of the file explicitly builds the concrete template versions the linker needs. Without it, no request would be authorized.

CONCEPTS TO LEARN (for beginners):

  • Explicit template instantiation: https://en.cppreference.com/w/cpp/language/template_instantiation
  • Coroutines (co_await / co_return): https://en.cppreference.com/w/cpp/language/coroutines
  • Preprocessor macros: https://en.cppreference.com/w/cpp/preprocessor
  • The facade pattern: https://en.wikipedia.org/wiki/Facade_pattern
