Detailed Description

The single place that answers "may this person do this thing to this record?". (Originally: "Central authorization facade: answers "may this requester perform this operation on this entity?".").

This header declares PermissionManager, a class full of canCreate, canRead, canUpdate and canDelete checks. Each check is written once as a template and works for several entity types. Every check also has an Async coroutine twin used by the non-blocking routes.

WHY THIS FILE MATTERS IN THE SERVER: Controllers call these checks before changing or returning data, so this is the gate that stops one client reading another client's records. It decides who may manage staff, view services, and edit cases or appointments. Without it, authorization rules would be scattered and easy to get wrong.
