Detailed Description

Type-erased interface for appointment-entity CRUD+S operations.

Declares a synchronous callback form and a coroutine (drogon::Task<void>) form of every operation. The appointments route registry reaches concrete controllers through this base via a std::variant, so its virtual functions are the dispatch point used by a single route handler for all appointment entity types.

In plain words: "synchronous" means the answer arrives through a callback function, while the coroutine (drogon::Task<void>) versions can be paused with co_await so the server can do other work meanwhile. "Virtual functions" mean a call made through this base runs the real object's version. A std::variant is a box that can hold one of several controller types.

Invocation contract shared by every method:

  • callback is std::function<void(int, const std::string&)>, it is moved through the call chain and, by contract, invoked once on each completion path, including failures. Its first argument is an api::v2::Http::Status code, its second a response body.
  • requester is the authenticated caller identity consulted for authorisation.
  • data is a non-owning view of the raw JSON request body, valid only for the call.
  • _id is the optional target id; absence is handled by the concrete implementation.

The *Async methods must be co_awaited; the HTTP layer wraps them in drogon::async_run and turns the callback result into a reply.

Note
The interface itself is stateless; behaviour lives in AppointmentController.
