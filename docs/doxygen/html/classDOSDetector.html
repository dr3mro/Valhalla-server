Detailed Description

Per-IP abuse detector combining static lists with sliding-window request counting.

Instances classify requests as whitelisted, blacklisted, rate-limited, banned or allowed. State is kept in several maps, each guarded by its own mutex, and a background cleanup thread periodically prunes expired timestamps and block entries. The detector is shared process-wide through Store and consulted by the RateLimit filter via GateKeeper::isDosAttack. Configuration and the clock are injectable for deterministic tests without changing production behaviour.

Note
Thread-safety: per-map mutexes serialize access to the corresponding state; matcher lists are compiled once at construction and are thereafter immutable. The detector is non-copyable and non-movable because it owns a background thread and mutexes.
See also
GateKeeper::isDosAttack, Filters::RateLimit

For a beginner: imagine a bouncer with three lists. The whitelist never gets counted, the blacklist is refused immediately, and everyone else is counted. If an IP sends many different requests quickly it is rate-limited; if it repeats the same request too often it is banned. Separate locks protect separate lists so different threads can check different lists at the same time. The "injectable clock" simply means tests can supply a fake time source instead of the real one.

Compiles a configuration pattern into an IP matcher.

Compiles a configuration pattern string into an IP predicate.

Recognizes re: regular expressions, IPv4 CIDR notation, * dot-segment wildcards and exact strings, in that priority order. A malformed CIDR yields a matcher that never matches.

Supports four forms, checked in order: re: regex (std::regex_search), IPv4 CIDR, dot-separated * wildcards, and exact match. template<typename Range>
std::uint64_t DOSDetector::hashHeaders ( const Range & headers)
inlinestatic

Hashes a range of key/value pairs into a single header fingerprint.

Only the values are hashed, and the per-value XXH3 digests are combined with XOR, so the result is independent of insertion order and of header names. Callers must keep the underlying value storage alive for the duration of the call.

Template Parameters
RangeRange of pairs whose second element is convertible to a byte span.
Parameters
[in]headersHeader collection (for example Drogon's request headers).
Returns
Combined 64-bit hash (zero for an empty range).

XOR is used to combine the digests because a XOR b equals b XOR a; that makes the result order-independent, which is useful because HTTP header order is not meaningful. It also means duplicate headers cancel each other out.

DOSDetector::Status DOSDetector::is_dos_attack ( const Request & request)

Classifies a request against whitelist, blacklist and abuse counters.

Evaluation order: whitelist, blacklist, rate-limit, ban, then counting. A rate-limited IP is still recorded via processRequest() so it can escalate to a ban. Any exception is caught and yields Status::ERROR.

Parameters
[in]requestRequest snapshot whose IP and header/body fingerprint are examined.
Returns
The applicable Status verdict.

Classifies request, checking static lists before dynamic abuse state. Whitelisted IPs are never counted; blacklisted IPs are rejected immediately. Rate-limited IPs continue to be counted so repeated abuse can escalate to a ban, while banned IPs are short-circuited with no further bookkeeping. Any exception is logged and mapped to Status::ERROR. request: Request snapshot to classify. Returns The applicable Status verdict.

◆ processRequest()

DOSDetector::Status DOSDetector::processRequest ( const Request & request)
private

Records a request and applies the fingerprint-count thresholds.

Records a request and decides whether to rate-limit, ban or allow it.

Prunes timestamps outside the period, appends the current time, then checks distinct fingerprints first (rate-limit) and repeat count second (ban).

Under request_mutex_ it prunes timestamps outside the configured period, appends the current time to the per-IP/per-fingerprint queue, then applies two thresholds: too many distinct fingerprints yields RATELIMITED; too many repeats of one fingerprint yields BANNED. Rate-limit and ban state are written under their own mutexes. The distinct-fingerprint check runs first, so an IP can be rate-limited before it is eventually banned.

Parameters
[in]requestRequest to record.
Returns
ALLOWED, RATELIMITED, BANNED, or ERROR on internal failure.
