Detailed Description

template<typename T>
class BlockingPool< T >

Thread-safe fixed set of reusable items leased one caller at a time.

Items are added with release() and leased with acquire(), which waits up to a timeout and returns nullptr if nothing becomes free. The pool is independent of the database so it can be unit tested with plain objects. Used by DatabaseConnectionPool to hand out Database connections; DatabaseHanndler models the matching RAII lease. 

     Thread-safety: a single mutex protects the deque, a condition

variable wakes waiting acquirers, and all methods may be called concurrently.

Template Parameters
TType of the pooled items (held via std::shared_ptr).

template<typename T>
template<typename Func, typename Finish>
void BlockingPool< T >::forEachIdle ( Func && func,
Finish && finish )
inline

Visits every idle item with func, then calls finish, under the pool lock.

Holding the lock across both callbacks prevents acquire() from handing out an item while it is being operated on (e.g. reconnected) or before the follow-up work in finish has completed.

Template Parameters
FuncCallable taking std::shared_ptr<T>&.
FinishCallable invoked once after all items were visited.
Parameters
[in,out]funcPer-item operation.
[in,out]finishFinal operation, typically waiting for async work started by func.
Note
Keeping finish inside the lock is intentional; a callback that tries to acquire from the same pool would deadlock.
