Detailed Description

Writes the CORS response headers onto every outgoing response.

CORS response headers, written in exactly one place (the pre-sending advice in server.cpp). Drogon stores headers in a map keyed by the lower-cased name, and addHeader replaces an existing value (HttpResponseImpl.h:194-210), so a header can never appear twice.

◆ apply()

void Cors::apply ( const drogon::HttpRequestPtr & req,
const drogon::HttpResponsePtr & resp )
inline

Decorates a response with CORS headers; invoked once per response from the pre-sending advice.

If the response already carries Access-Control-Allow-Origin: "*", it is left untouched. Otherwise the current cors_allowed_origins setting is read from the Configurator. An exact match to the request's Origin is reflected back with Allow-Credentials and Vary: Origin; if origins are configured but none match, the first configured origin is used without credentials; if the setting is "*", the wildcard is used. For OPTIONS requests a sanitized echo of Access-Control-Request-Headers replaces the default header list, and Max-Age plus Vary are added. Every write uses HttpResponse::addHeader, which replaces an existing value rather than duplicating it.

Parameters
[in]reqRequest being answered; supplies Origin and, for preflights, the requested headers.
[in,out]respResponse to decorate.
Note
No shared mutable state is modified here; the configuration is read through Store's thread-local cache.
See also
CorsTokens::sanitizeRequestedHeaders(), CorsTokens::mergeVary()

Splits the comma-separated cors_allowed_origins setting into individual origins.

Spaces are skipped and empty tokens discarded, so a trailing comma or whitespace after a comma does not create a bogus origin. Order is preserved because apply() falls back to the first entry.
