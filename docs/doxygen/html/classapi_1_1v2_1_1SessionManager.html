Detailed Description

Owns the client login flow and the in-memory session cache.

Login is deliberately split into fetchPasswordHash() (database reads, account activation check) and completeLogin() (password verification, then login-time write). GateKeeper invokes the two parts separately so the expensive password check can run on a PasswordWorker; a wrong password therefore never updates the stored login time. Sessions live in a shared MemCache keyed by "<group>_<id>" and carry an expiry. All operations report failures through a human-readable message (or a callback for logout).

See also
KeeprBase In everyday words: logging in is like showing ID at a desk. First we look up your account and check it is active; then we check your password; only then do we record that you logged in and hand you a session.

bool SessionManager::storeSession ( std::optional< Types::ClientLoginData > & clientLoginData,

Inserts the client's session into the cache with a TTL taken from expireTime.

Parameters
[in,out]clientLoginDataSession data; keyed by group and client id.
[out]messageHuman-readable failure reason.
Returns
True on insertion.
Note
The TTL forwarded to MemCache::insert is expireTime — the JWT exp claim as a system_clock duration since the epoch (set by decodeToken), not an interval remaining until expiry. Consequently the effective cache lifetime is that absolute value rather than a short time-until-expiry.

Caches the session under "<group>_<id>", using expireTime as the MemCache TTL. expireTime is the JWT exp claim as a system_clock duration since the epoch (populated by decodeToken), so the value handed to MemCache::insert is that absolute duration, not a remaining-lifetime interval. message: Receives the failure reason. Returns True when the session was inserted. Throws DatabaseBusy: Propagated to the caller for retry/back-off.
