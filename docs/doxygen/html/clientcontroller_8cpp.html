Detailed Description

Definitions and explicit instantiations for ClientController<User> and ClientController<Provider>.

The synchronous Create/Update paths offload password hashing to a bounded PasswordWorker; all other CRUDS operations forward to EntityController. Session bookkeeping (login/logout, suspend, delete) is owned by GateKeeper.

WHY THIS FILE MATTERS IN THE SERVER: This file is where account behaviour is actually assembled. Slow password work is handed to a worker so the IO loop stays responsive, while session side effects are attached by wrapping callbacks. The coroutine CRUDS methods simply reuse EntityController. Explicit instantiation at the bottom makes all of this linkable for User and Provider, the two supported client types.
