1/**
2 * @file communicate.hpp
3 * @brief Synchronous HTTP helper for service-to-service requests.
4 * @details Declares the Communicate class, a static-only wrapper around libcurl
5 * for making outbound HTTP calls. sendRequest builds a URL from a
6 * server, port and path, sends a JSON content-type header, and performs either
7 * a GET or a POST. Two private helpers do the work: handleResponse runs the
8 * cURL transfer and WriteCallback receives the returned bytes. All
9 * calls are blocking and failures are reported as an empty std::optional.
10 *
11 * WHY THIS FILE MATTERS IN THE SERVER:
12 * When one part of the system needs to talk to another service over HTTP (for
13 * example a separate microservice), it uses Communicate instead of calling
14 * libcurl itself. That keeps the awkward C-style cURL setup in one place and
15 * gives callers a simple, safe interface: pass the address and data, get back
16 * an optional string. Without it, every caller would repeat handle setup,
17 * cleanup and error handling.
18 *
19 * CONCEPTS TO LEARN (for beginners):
20 * - libcurl C API: https://curl.se/libcurl/c/
21 * - std::optional: https://en.cppreference.com/w/cpp/utility/optional
22 * - Callbacks / function pointers:
23 * https://en.cppreference.com/w/cpp/language/pointer#Pointers_to_functions
24 *
25 * @author Amr Osman <dr3mro@gmail.com>
26 * @date 2026-11-16
27 */

40/**
41 * @class Communicate
42 * @brief Thin static-only wrapper around libcurl for outbound HTTP calls.
43 * @details Builds `server:port/path`, sends a JSON content-type header and
44 * performs either a GET or a POST with the supplied body. There is no
45 * instance state: each call creates and cleans up its own CURL handle,
46 * and failures are reported to the console via Message and signalled
47 * to the caller by an empty optional rather than by an exception.
48 * @note Only GET and POST are supported; all calls are blocking.
49 */
50// A class used only through static functions; it has no
51// instance state.
52class Communicate {
53 public:
54 /**
55 * @brief Sends an HTTP request and returns the response body.
56 * @param[in] server Host name or address of the target service.
57 * @param[in] port TCP port of the target service.
58 * @param[in] path Request path, including any query string.
59 * @param[in] method HTTP verb; only Get and Post are recognised.
60 * @param[in] data Request body, used for POST (ignored for GET).
61 * @return Response body on success, `std::nullopt` on any failure.
62 * @note All exceptions (init failure, unsupported method, cURL error, empty
63 * body) are caught internally, logged via Message and converted to
64 * `std::nullopt`; nothing is thrown to the caller.
65 * @warning `data` is passed to libcurl by pointer, so it must outlive the
66 * call; this holds for normal synchronous use.
67 */
68 static std::optional<std::string>

70 // empty on failure.

75 const std::string& data); // Arguments describe where to send, which
76 // verb to use and what body to send.
