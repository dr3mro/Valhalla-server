2 * @file patientdrugs.hpp
3 * @brief Case entity for the `patients_drugs` table (a patient's drug record).
4 * @details This header declares the PatientDrugs class, a small C++ type that
5 * stands for the drug record of one patient in the `patients_drugs` database
6 * table. There is at most one such record per patient because the patient id is
7 * the table's primary key. The class itself holds no data; it names the table
8 * and leaves SQL generation to its parent Case. It also supplies small helper
9 * functions that build permission-checking SQL for create, read, update and
10 * delete operations.
11 *
12 * WHY THIS FILE MATTERS IN THE SERVER:
13 * PatientDrugs is one of the clinic-owned "case" types exposed through the
14 * clinic routes as ClinicController<PatientDrugs> under the `patientdrugs`
15 * service type. When a client wants to add or change a patient's drug record,
16 * PermissionManager calls the static getPermissionsQueryFor* helpers here to
17 * build a SELECT that finds which clinic owns the patient, then checks whether
18 * the requesting user is that clinic's owner, admin or staff. Without this file
19 * there would be no C++ type connecting the `patients_drugs` table to the CRUD
20 * and permission machinery, so patient-drug endpoints could not work.
21 *
22 * CONCEPTS TO LEARN (for beginners):
23 * - static constexpr: a value fixed at compile time that belongs to the class,
24 * not to one object. https://en.cppreference.com/w/cpp/language/static
25 * - JSON: a text format used to carry request data; this project uses the
26 * jsoncons library to read it. https://jsoncons.github.io/jsoncons/
27 * - Foreign key / ON DELETE CASCADE: a column that points to a row in another
28 * table, with the database automatically deleting this row when that parent row
29 * is deleted. https://en.cppreference.com/w/cpp
30 *
31 * @author Amr Osman <dr3mro@gmail.com>
32 * @date 2026-11-16
33 */

131 /**
132 * @brief Builds the SQL that resolves the owning clinic for a create
133 * request.
134 * @details Reads the patient id from `data_j` using CREATE_KEY and
135 * delegates to the Case base, which joins `clinics` with `patients` on
136 * clinic_id. PermissionManager runs the returned SELECT before the insert
137 * to check owner/admin/staff rights; no insert is performed here.
138 * @param[in] data_j Create payload; must be engaged and contain an
139 * unsigned-integer CREATE_KEY (the optional is dereferenced without a
140 * has_value() check).
141 * @return The SELECT statement, or std::nullopt if reading or converting
142 * the key throws; the exception is logged via CRITICALMESSAGE.
143 * @see Case::getPermissionsQueryForCreateImpl
144 */
145 // Returns a query string, or nothing if the payload is
146 // malformed.
147 static std::optional<std::string> getPermissionsQueryForCreate(
148 const std::optional<jsoncons::json>& data_j) {
149 uint64_t id; // Will hold the patient id pulled from the JSON payload;
150 // an unsigned 64-bit integer matches database ids.
151 // Reading JSON can fail (missing field or wrong type), so guard
152 // it.
153 try {
154 // Dereference the optional payload, look
155 // up the "id" field and convert it to an
156 // integer.
157 // Any read/conversion problem lands here.
158 id = data_j->at(CREATE_KEY).as<uint64_t>();
159 } catch (const std::exception& e) {
160 CRITICALMESSAGE // Log the failure (macro uses the caught
161 // exception) so the problem is visible in server
162 // logs.
163 return std::nullopt; // No trustworthy id means no safe query
164 // can be built, so report failure to the
165 // caller.
166 }
167
168 return getPermissionsQueryForCreateImpl(id,
169 KEYREFTABLENAME); // Hand the id
170 // and `patients`
171 // table to Case,
172 // which writes
173 // the join SQL
174 // that finds the
175 // owning clinic.
176 }
