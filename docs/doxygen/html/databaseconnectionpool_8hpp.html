Detailed Description

Owns the fixed set of synchronous Database connections and leases them to callers.

This header declares DatabaseConnectionPool, the manager for a fixed number of Database objects. It builds every connection up front at startup, stores idle ones in a BlockingPool, leases them with get_connection(), and takes them back with return_connection(). It also exposes reconnect_all() to refresh idle links after a database outage, and emits warnings when the pool is saturated.

WHY THIS FILE MATTERS IN THE SERVER: The pool is the gatekeeper for the server's synchronous database capacity. Controllers and the watchdog do not create connections themselves; DatabaseHanndler leases one from here for each request, and the HTTP layer turns a timeout into 503 when no connection is free. The pool reads its size and timeout from Configurator, and delegates the actual hand-out/return mechanics to BlockingPool. Without it, every request would open its own connection, which is slow, unbounded, and would exhaust the database's connection limit.
