1/**
2 * @file databaseconnectionpool.hpp
3 * @brief Owns the fixed set of synchronous Database connections and leases them
4 * to callers.
5 * @details This header declares DatabaseConnectionPool, the manager for a fixed
6 * number of Database objects. It builds every connection up front at startup,
7 * stores idle ones in a BlockingPool, leases them with get_connection(), and
8 * takes them back with return_connection(). It also exposes reconnect_all() to
9 * refresh idle links after a database outage, and emits warnings when the pool
10 * is saturated.
11 *
12 * WHY THIS FILE MATTERS IN THE SERVER:
13 * The pool is the gatekeeper for the server's synchronous database capacity.
14 * Controllers and the watchdog do not create connections themselves;
15 * DatabaseHanndler leases one from here for each request, and the HTTP layer
16 * turns a timeout into 503 when no connection is free. The pool reads its size
17 * and timeout from Configurator, and delegates the actual hand-out/return
18 * mechanics to BlockingPool. Without it, every request would open its own
19 * connection, which is slow, unbounded, and would exhaust the database's
20 * connection limit.
21 *
22 * CONCEPTS TO LEARN (for beginners):
23 * - RAII (a lease is acquired in a constructor and returned in a destructor):
24 * https://en.cppreference.com/w/cpp/language/raii
25 * - std::atomic (a value safe to read/write from several threads):
26 * https://en.cppreference.com/w/cpp/atomic/atomic
27 * - std::chrono (time points and durations):
28 * https://en.cppreference.com/w/cpp/chrono
29 * - std::shared_ptr (shared ownership of an object):
30 * https://en.cppreference.com/w/cpp/memory/shared_ptr
31 * - Exception specifications via @throws (used by Doxygen, not C++ itself)
32 *
33 * @author Amr Osman <dr3mro@gmail.com>
34 * @date 2026-11-16
35 */

58/**
59 * @class DatabaseConnectionPool
60 * @brief Owns the fixed set of synchronous Database connections and leases them
61 * to callers.
62 * @details Connections are created in parallel at construction and stored in a
63 * BlockingPool. Callers obtain a connection with get_connection() and must give
64 * it back with return_connection(); in practice DatabaseHanndler does this via
65 * RAII. The acquire timeout is read once from configuration at startup. When a
66 * wait for a connection expires, get_connection() throws DatabaseBusy, which
67 * the HTTP layer maps to 503.
68 *
69 * Thread-safety: connection hand-out and return are serialised by
70 * BlockingPool; the slow-wait warning rate limiter is atomic. Non-copyable and
71 * non-movable.
72 * @warning A failed initialisation is fatal: the constructor logs and calls
73 * `exit(EXIT_FAILURE)`.
74 * @see BlockingPool, DatabaseHanndler, DatabaseBusy
75 */
