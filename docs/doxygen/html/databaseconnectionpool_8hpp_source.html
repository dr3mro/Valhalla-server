1/**
2 * @file databaseconnectionpool.hpp
3 * @brief Owns the fixed set of synchronous Database connections and leases them to callers.
4 * @details This header declares DatabaseConnectionPool, the manager for a fixed number of
5 * Database objects. It builds every connection up front at startup, stores idle ones
6 * in a BlockingPool, leases them with get_connection(), and takes them back with
7 * return_connection(). It also exposes reconnect_all() to refresh idle links after a
8 * database outage, and emits warnings when the pool is saturated.
9 *
10 * WHY THIS FILE MATTERS IN THE SERVER:
11 * The pool is the gatekeeper for the server's synchronous database capacity. Controllers and
12 * the watchdog do not create connections themselves; DatabaseHanndler leases one from here for
13 * each request, and the HTTP layer turns a timeout into 503 when no connection is free. The
14 * pool reads its size and timeout from Configurator, and delegates the actual hand-out/return
15 * mechanics to BlockingPool. Without it, every request would open its own connection, which is
16 * slow, unbounded, and would exhaust the database's connection limit.
17 *
18 * CONCEPTS TO LEARN (for beginners):
19 * - RAII (a lease is acquired in a constructor and returned in a destructor): https://en.cppreference.com/w/cpp/language/raii
20 * - std::atomic (a value safe to read/write from several threads): https://en.cppreference.com/w/cpp/atomic/atomic
21 * - std::chrono (time points and durations): https://en.cppreference.com/w/cpp/chrono
22 * - std::shared_ptr (shared ownership of an object): https://en.cppreference.com/w/cpp/memory/shared_ptr
23 * - Exception specifications via @throws (used by Doxygen, not C++ itself)
24 *
25 * @author Amr Osman <dr3mro@gmail.com>
26 * @date 2026-11-16
27 */

41/**
42 * @class DatabaseConnectionPool
43 * @brief Owns the fixed set of synchronous Database connections and leases them to callers.
44 * @details Connections are created in parallel at construction and stored in a BlockingPool.
45 * Callers obtain a connection with get_connection() and must give it back with
46 * return_connection(); in practice DatabaseHanndler does this via RAII. The acquire
47 * timeout is read once from configuration at startup. When a wait for a connection
48 * expires, get_connection() throws DatabaseBusy, which the HTTP layer maps to 503.
49 *
50 * Thread-safety: connection hand-out and return are serialised by BlockingPool;
51 * the slow-wait warning rate limiter is atomic. Non-copyable and non-movable.
52 * @warning A failed initialisation is fatal: the constructor logs and calls `exit(EXIT_FAILURE)`.
53 * @see BlockingPool, DatabaseHanndler, DatabaseBusy
54 */
