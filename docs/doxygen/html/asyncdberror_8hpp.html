Detailed Description

Maps exceptions from the Drogon async database path to the HTTP statuses of the synchronous path.

This header declares three small helpers that inspect an exception. One decides whether the error means "the database is busy", one turns that decision into an HTTP status code, and one throws the project's DatabaseBusy exception so the rest of the server can keep a single error-handling path.

WHY THIS FILE MATTERS IN THE SERVER: The controller methods that use Drogon coroutines catch errors as the generic std::exception type, so they lose the specific Drogon exception class. These helpers recover the important distinction: a busy pool or a timeout means "try again later" (HTTP 503 Service Unavailable), while any other failure is a normal internal error (HTTP 500). They let the async database path answer failures exactly the same way the older synchronous path does. Without this file, a temporary database overload would be reported as a generic server error instead of a retryable one, and callers would not know to back off.
