1/**
2 * @file asyncdberror.hpp
3 * @brief Maps exceptions from the Drogon async database path to the HTTP
4 * statuses of the synchronous path.
5 * @details This header declares three small helpers that inspect an exception.
6 * One decides whether the error means "the database is busy", one turns that
7 * decision into an HTTP status code, and one throws the project's DatabaseBusy
8 * exception so the rest of the server can keep a single error-handling path.
9 *
10 * WHY THIS FILE MATTERS IN THE SERVER:
11 * The controller methods that use Drogon coroutines catch errors as the generic
12 * std::exception type, so they lose the specific Drogon exception class. These
13 * helpers recover the important distinction: a busy pool or a timeout means
14 * "try again later" (HTTP 503 Service Unavailable), while any other failure is
15 * a normal internal error (HTTP 500). They let the async database path answer
16 * failures exactly the same way the older synchronous path does. Without this
17 * file, a temporary database overload would be reported as a generic server
18 * error instead of a retryable one, and callers would not know to back off.
19 *
20 * CONCEPTS TO LEARN (for beginners):
21 * - C++20 coroutines: https://en.cppreference.com/w/cpp/language/coroutines
22 * - Exceptions and std::exception:
23 * https://en.cppreference.com/w/cpp/error/exception
24 * - dynamic_cast (checking an object's real type at runtime):
25 * https://en.cppreference.com/w/cpp/language/dynamic_cast
26 * - HTTP 503 status:
27 * https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/503
28 * - Drogon DbClient: https://drogon.docsforge.com/master/database/
29 *
30 * @author Amr Osman <dr3mro@gmail.com>
31 * @date 2026-11-16
32 */

53 * statuses of the synchronous path.
54 * @details An exhausted pool or timeout is "busy" and maps to 503, matching

60 /**
61 * @brief Tests whether an exception represents a busy database (pool
62 * exhaustion or timeout).
63 * @details First checks for a `DatabaseBusy` by dynamic type; otherwise
64 * performs a case-sensitive substring search of `what()` for "timeout",
65 * "pool", "too many clients" and "connection". The message check is a
66 * heuristic used because callers catch exceptions as `std::exception`,
67 * where the specific Drogon type may not be available.
68 * @param[in] error Exception to classify; need not outlive the call.
69 * @return True if the exception looks like a busy/timeout condition.
70 * @warning "connection" is a broad match: an unrelated error whose message
71 * mentions a connection is classified as busy.
72 */
73 [[nodiscard]] bool isBusy(
74 const std::exception&
75 error); // `[[nodiscard]]` forces callers to use the answer;
76 // `const&` inspects without copying.
