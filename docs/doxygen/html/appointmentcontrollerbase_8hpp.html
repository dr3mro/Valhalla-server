Detailed Description

Type-erased interface for appointment-entity CRUD+S operations.

In plain words, this file lists the jobs every "appointment entity" must support. Those jobs are: Create a new appointment, Read one, Update one, Delete one, and Search through many — together called "CRUD+S". "Type-erased" is a fancy word for hiding the exact type: the rest of the server can call these jobs without knowing which kind of appointment is actually behind them. Each job appears twice: an ordinary version that reports its result through a callback (a "call me when you are done" function), and an "async" version that uses a coroutine (a function that can pause and resume later). This file only declares the jobs; the real work lives in the class that inherits from it.

WHY THIS FILE MATTERS IN THE SERVER: This is the doorway the appointments HTTP routes use to reach every appointment controller. Because the functions here are "virtual", one route handler can serve clinics, pharmacies, laboratories and radiology-center appointments alike — the call is forwarded to the right concrete object (chosen with a std::variant, a box that can hold one of several types). This file calls into nothing itself, but it is called by the appointments route registry and it is the contract AppointmentController fulfils. Without it, each appointment route would need separate code for every entity type.

CONCEPTS TO LEARN (for beginners):

  • Virtual functions (calling the right version through a base pointer): https://en.cppreference.com/w/cpp/language/virtual
  • C++20 coroutines (functions that pause and resume with co_await/co_return): https://en.cppreference.com/w/cpp/language/coroutines
  • std::optional (a value that may be absent): https://en.cppreference.com/w/cpp/utility/optional
