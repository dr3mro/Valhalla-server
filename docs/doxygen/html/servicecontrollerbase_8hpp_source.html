1/**
2 * @file servicecontrollerbase.hpp
3 * @brief Type-erased interface for service-entity (clinic, pharmacy, laboratory, radiology center) CRUD+S operations.
4 * @details In everyday language, this file lists the jobs every "service entity" (a clinic, a pharmacy, a
5 * laboratory or a radiology center) must be able to do. Those jobs are: Create a new one, Read one,
6 * Update one, Delete one, and Search through many — together called "CRUD+S". "Type-erased" is a
7 * fancy word for hiding the exact type: the rest of the server can call these jobs without knowing
8 * which kind of entity is actually behind them. Each job appears twice: an ordinary version that
9 * reports its result through a callback (a "call me when you are done" function), and an "async"
10 * version that uses a coroutine (a function that can pause and resume later). This file only
11 * declares the jobs; the real work is written in the class that inherits from this one.
12 *
13 * WHY THIS FILE MATTERS IN THE SERVER:
14 * This is the doorway the HTTP routing layer uses to reach every service controller. Because all the job
15 * functions here are "virtual", one single route handler can serve clinics, pharmacies, laboratories and
16 * radiology centers without knowing which one it is talking to — the call is automatically forwarded to
17 * the right concrete controller. This file calls into nothing itself, but it is called by the services
18 * route registry and it is the contract that @ref ServiceController fulfils. Without it, every route would
19 * need separate code for each entity type and adding a new service type would mean rewriting the routes.
20 *
21 * CONCEPTS TO LEARN (for beginners):
22 * - Virtual functions (calling the right version through a base pointer): https://en.cppreference.com/w/cpp/language/virtual
23 * - C++20 coroutines (functions that pause and resume with co_await/co_return): https://en.cppreference.com/w/cpp/language/coroutines
24 * - C++20 concepts / requires (compile-time checks on template arguments): https://en.cppreference.com/w/cpp/language/constraints
25 *
26 * @author Amr Osman <dr3mro@gmail.com>
27 * @date 2026-11-16
28 */

44/**
45 * @class ServiceControllerBase
46 * @brief Type-erased interface for service-entity (clinic, pharmacy, laboratory, radiology center) CRUD+S operations.
47 * @details Declares both a synchronous, callback-driven form of every operation and a coroutine
48 * (`drogon::Task<void>`) form. The HTTP layer reaches concrete controllers through this
49 * base via a `std::variant` in the services route registry, so virtual dispatch here is
50 * what makes one route handler serve all service entity types.
51 *
52 * In plain words: "synchronous" means the caller gets the answer through a callback function;
53 * "coroutine" (`drogon::Task<void>`) means the caller can pause the operation with co_await and
54 * let the server do other work meanwhile. "Virtual dispatch" means that when the route code calls
55 * `Create` through this base type, C++ automatically runs the version belonging to the real object
56 * (for example the clinic controller). A `std::variant` is a variable that can hold one of several
57 * different types — here it holds whichever concrete service controller was selected.
58 *
59 * Invocation contract shared by every method:
60 * - `callback` is `std::function<void(int, const std::string&)>`, moved by the caller and
61 * forwarded down the call chain. By contract it is invoked once on each completion
62 * path, including failures; the first argument is an @ref api::v2::Http::Status code, the second a
63 * response body (serialized row(s) on success, diagnostic text on failure).
64 * - `requester` is the authenticated caller identity, used by implementations for the
65 * permission decision before any database work is done.
66 * - `data` is a non-owning view of the raw JSON request body; it must outlive the call.
67 * - `_id`, where present, is the optional target entity id; a missing value is rejected
68 * by the concrete implementation rather than by this interface.
69 *
70 * The `*Async` methods perform the same operation but must be co_awaited; the route layer
71 * wraps them in `drogon::async_run` and converts the callback result into an HTTP reply.
72 * @note Implementations here are supplied by @ref ServiceController; the interface itself adds no state.
73 * @see ServiceController, EntityControllerBase, Controller
74 */
