1/**
2 * @file servicecontrollerbase.hpp
3 * @brief Type-erased interface for service-entity (clinic, pharmacy,
4 * laboratory, radiology center) CRUD+S operations.
5 * @details In everyday language, this file lists the jobs every "service
6 * entity" (a clinic, a pharmacy, a laboratory or a radiology center) must be
7 * able to do. Those jobs are: Create a new one, Read one, Update one, Delete
8 * one, and Search through many — together called "CRUD+S". "Type-erased" is a
9 * fancy word for hiding the exact type: the rest of the server can
10 * call these jobs without knowing which kind of entity is actually behind them.
11 * Each job appears twice: an ordinary version that reports its result through a
12 * callback (a "call me when you are done" function), and an "async" version
13 * that uses a coroutine (a function that can pause and resume later). This file
14 * only declares the jobs; the real work is written in the class that inherits
15 * from this one.
16 *
17 * WHY THIS FILE MATTERS IN THE SERVER:
18 * This is the doorway the HTTP routing layer uses to reach every service
19 * controller. Because all the job functions here are "virtual", one single
20 * route handler can serve clinics, pharmacies, laboratories and radiology
21 * centers without knowing which one it is talking to — the call is
22 * automatically forwarded to the right concrete controller. This file calls
23 * into nothing itself, but it is called by the services route registry and it
24 * is the contract that @ref ServiceController fulfils. Without it, every route
25 * would need separate code for each entity type and adding a new service type
26 * would mean rewriting the routes.
27 *
28 * CONCEPTS TO LEARN (for beginners):
29 * - Virtual functions (calling the right version through a base pointer):
30 * https://en.cppreference.com/w/cpp/language/virtual
31 * - C++20 coroutines (functions that pause and resume with co_await/co_return):
32 * https://en.cppreference.com/w/cpp/language/coroutines
33 * - C++20 concepts / requires (compile-time checks on template arguments):
34 * https://en.cppreference.com/w/cpp/language/constraints
35 *
36 * @author Amr Osman <dr3mro@gmail.com>
37 * @date 2026-11-16
38 */

68/**
69 * @class ServiceControllerBase
70 * @brief Type-erased interface for service-entity (clinic, pharmacy,
71 * laboratory, radiology center) CRUD+S operations.
72 * @details Declares both a synchronous, callback-driven form of every operation
73 * and a coroutine
74 * (`drogon::Task<void>`) form. The HTTP layer reaches concrete
75 * controllers through this base via a `std::variant` in the services route
76 * registry, so virtual dispatch here is what makes one route handler serve all
77 * service entity types.
78 *
79 * In plain words: "synchronous" means the caller gets the answer
80 * through a callback function; "coroutine" (`drogon::Task<void>`) means the
81 * caller can pause the operation with co_await and let the server do other work
82 * meanwhile. "Virtual dispatch" means that when the route code calls `Create`
83 * through this base type, C++ automatically runs the version belonging to the
84 * real object (for example the clinic controller). A `std::variant` is a
85 * variable that can hold one of several different types — here it holds
86 * whichever concrete service controller was selected.
87 *
88 * Invocation contract shared by every method:
89 * - `callback` is `std::function<void(int, const std::string&)>`,
90 * moved by the caller and forwarded down the call chain. By contract it is
91 * invoked once on each completion path, including failures; the first argument
92 * is an @ref api::v2::Http::Status code, the second a response body (serialized
93 * row(s) on success, diagnostic text on failure).
94 * - `requester` is the authenticated caller identity, used by
95 * implementations for the permission decision before any database work is done.
96 * - `data` is a non-owning view of the raw JSON request body; it must
97 * outlive the call.
98 * - `_id`, where present, is the optional target entity id; a missing
99 * value is rejected by the concrete implementation rather than by this
100 * interface.
101 *
102 * The `*Async` methods perform the same operation but must be
103 * co_awaited; the route layer wraps them in `drogon::async_run` and converts
104 * the callback result into an HTTP reply.
105 * @note Implementations here are supplied by @ref ServiceController; the
106 * interface itself adds no state.
107 * @see ServiceController, EntityControllerBase, Controller
108 */
