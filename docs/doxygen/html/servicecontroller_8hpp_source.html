1/**
2 * @file servicecontroller.hpp
3 * @brief Service-entity controller that adapts @ref EntityController to @ref ServiceControllerBase.
4 * @details In plain words, this file defines a small "adapter" class for each kind of service entity
5 * (clinic, pharmacy, laboratory, radiology center). An adapter is a thin wrapper that passes a
6 * request straight through to another class that does the real work — here that class is
7 * @ref EntityController. Every job listed below (create, read, update, delete, search and their
8 * coroutine versions) simply forwards to the matching method of `EntityController<T>`. This class
9 * adds no behaviour of its own: validation, permission checks, building the database query,
10 * turning results into JSON and mapping errors to HTTP status codes all happen in that base.
11 *
12 * WHY THIS FILE MATTERS IN THE SERVER:
13 * It gives service entities their own interface, separate from appointment entities, so the route registry
14 * can pick the right controller family by name. The HTTP layer calls these methods through
15 * @ref ServiceControllerBase (using a `std::variant`), and each call lands here and is handed to
16 * @ref EntityController. If this file were missing, there would be no concrete class satisfying the service
17 * interface and no way to route a clinic/pharmacy/laboratory/radiology request to the real CRUD+S code.
18 *
19 * CONCEPTS TO LEARN (for beginners):
20 * - C++20 concepts / requires (compile-time checks on template arguments): https://en.cppreference.com/w/cpp/language/constraints
21 * - Templates (writing one class that works for many types): https://en.cppreference.com/w/cpp/language/templates
22 * - C++20 coroutines (functions that pause and resume with co_await/co_return): https://en.cppreference.com/w/cpp/language/coroutines
23 *
24 * @author Amr Osman <dr3mro@gmail.com>
25 * @date 2026-11-16
26 */

41/**
42 * @class ServiceController
43 * @brief Service-entity controller that adapts @ref EntityController to @ref ServiceControllerBase.
44 * @tparam T Service entity type; must satisfy @ref Service_t (derived from `Service`).
45 * @details A thin, stateless adapter: every CRUD+S entry point simply forwards to the same-named
46 * method of `EntityController<T>`, so validation, authorisation, entity construction,
47 * SQL execution, JSON marshalling and error→HTTP mapping all live in that base. The
48 * template parameter supplies the table name, SQL statements and permission queries used
49 * there. This class exists to give service entities a distinct interface (and therefore a
50 * distinct entry in the route registry) from appointment entities.
51 *
52 * Plain-language version: `T` is whichever entity class we are handling (say `Clinics`). The
53 * `Service_t` after `template` is a "concept" — a compile-time check that refuses to build this
54 * class unless `T` is really a service type. Because this class stores no data ("stateless"), its
55 * only job is to hand the arguments to `EntityController<T>` and let that base do everything.
56 *
57 * Explicit instantiations are provided for `Clinics`, `Pharmacies`, `Laboratories` and
58 * `RadiologyCenters`; the route layer stores `shared_ptr<ServiceController<T>>` values in
59 * a variant and dispatches to them through @ref ServiceControllerBase.
60 * @note Copy and move are disabled so each registered controller has a single identity.
61 * @see EntityController, ServiceControllerBase, Service_t
62 */
