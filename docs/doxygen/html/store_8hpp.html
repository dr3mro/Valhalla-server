Detailed Description

Process-wide service locator keyed by C++ type.

This file declares Store, the one place in the server that keeps a single shared object for each C++ type. Callers ask for an object by its type (for example "the database client"), and Store either hands back the object it already made or builds it the first time. It also offers a cheap per-thread cache for busy request code and a way to swap an object for a fake one during tests.

WHY THIS FILE MATTERS IN THE SERVER: Store is the server's service locator. Controllers and other long-lived objects call Store::getObject<T>() or Store::cachedObject<T>() to get shared helpers such as the database client instead of building their own. Because the object is built only once, expensive resources are never duplicated. Tests call replaceObject<T>() to install a fake without changing production code. Without Store, every caller would have to pass the same helper around by hand and could easily end up with a different copy.

CONCEPTS TO LEARN (for beginners):

  • Service locator: one well-known place you ask for shared objects, by type instead of by name. https://en.wikipedia.org/wiki/Service_locator_pattern
  • thread_local: storage that has one separate copy per running thread. https://en.cppreference.com/w/cpp/language/storage_duration
  • Atomic memory order: rules saying when one thread's writes become visible to another thread. https://en.cppreference.com/w/cpp/atomic/memory_order
  • RAII: using a small local object to lock a mutex and unlock it automatically at the end of a scope. https://en.cppreference.com/w/cpp/language/raii
