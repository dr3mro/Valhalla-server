Detailed Description

Macros for uniform critical-error logging and response generation.

Defines two preprocessor macros. CRITICALMESSAGE builds a detailed error string (message, function, file and line) and logs it at critical severity. CRITICALMESSAGERESPONSE does that logging and then answers the caller through a callback, choosing 503 for a busy database and 500 for anything else. Because they are macros, the error text picks up the caller's func, FILE and LINE automatically instead of always pointing here.

WHY THIS FILE MATTERS IN THE SERVER: Many controllers and entities can fail in the same way, and each one must both log the failure and send a sensible HTTP reply. These macros make that a single line at every catch site, so error handling looks and behaves the same across the whole API. They depend on statusForException (errorstatus.hpp) for the status code and on Message for the log. Without them, error handling would be duplicated and would drift apart over time.

CONCEPTS TO LEARN (for beginners):

  • Preprocessor macros: https://en.cppreference.com/w/cpp/preprocessor/replace
  • std::string: https://en.cppreference.com/w/cpp/string/basic_string
  • Compile-time macros func, FILE, LINE: https://en.cppreference.com/w/cpp/preprocessor/replace#Predefined_macros

Definition errorstatus.hpp:56

Logs a critical error and replies to the caller through callback.

First expands CRITICALMESSAGE, then invokes callback with the status from statusForException. For a busy database (503) the exception's own message is returned so the client knows to retry; for any other failure (500) the detailed critical_error string is returned and the raw exception text is kept out of the response.

Precondition
Requires e, a callable callback compatible with CALLBACK_, and the names used by CRITICALMESSAGE to be in scope.
See also
