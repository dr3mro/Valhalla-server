Detailed Description

Facade over authentication, authorization and per-IP abuse detection.

GateKeeper is the single "front desk" the rest of the server talks to for security. It exposes login/logout, session-or-JWT authentication checks, permission questions (create/read/update/delete and a few special cases, each in a normal and a coroutine version), and a request classifier used for abuse protection. It owns no algorithms of its own: every call is forwarded to a collaborator (SessionManager, TokenManager, DOSDetector, PermissionManager, PasswordWorker) fetched from the Store singleton. Because those collaborators are shared, separate GateKeeper objects all see the same sessions, tokens and counters.

WHY THIS FILE MATTERS IN THE SERVER: This is the public face of the gatekeeper/security subsystem. Drogon controllers and filters create or receive a GateKeeper and call it to log a user in, decide whether a request is authenticated, check permissions before touching data, and ask whether an IP is abusing the service. GateKeeper itself calls down into the five manager classes listed above. Without this facade every controller would have to know all five managers and wire them together correctly; with it, security is reached through one simple, stable interface. The header declares the interface (what can be asked); gatekeeper.cpp holds the implementation.
