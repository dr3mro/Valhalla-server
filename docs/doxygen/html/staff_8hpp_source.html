1/**
2 * @file staff.hpp
3 * @brief REST controller for managing staff membership of service entities.
4 * @details This file defines the Staff controller, which invites, adds and
5 * removes staff members of a service entity. The {serviceType} part of the URL
6 * (clinics, pharmacies, laboratories or radiologycenters) selects one concrete
7 * StaffController from a std::variant registry. Each handler translates the
8 * controller's numeric status into a standard JSON HTTP response and builds a
9 * Requester from the identity attributes set by Auth. Depending on the
10 * configuration it either awaits an async controller coroutine or uses
11 * executeControllerMethod for blocking database work. All routes are SECURE.
12 *
13 * WHY THIS FILE MATTERS IN THE SERVER:
14 * This controller is the HTTP front door for managing who works at each service
15 * provider. Drogon routes the /api/v2 staff URLs here; the handlers call the
16 * shared dispatcher, which reaches the staff controllers and the database. It
17 * depends on the Auth filter for identity and on the service locator for the
18 * executor and controllers. Without it there would be no API way to invite or
19 * change the staff of a clinic, pharmacy, laboratory or radiology center.
20 *
21 * CONCEPTS TO LEARN (for beginners):
22 * - REST routes and HTTP POST:
23 * https://developer.mozilla.org/en-US/docs/Web/HTTP/Methods
24 * - std::variant (a type-safe union):
25 * https://en.cppreference.com/w/cpp/utility/variant
26 * - HTTP filters/middleware: https://drogon.docsforge.com/master/filter/
27 * - CORS: https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS
28 *
29 * @author Amr Osman <dr3mro@gmail.com>
30 * @date 2026-11-16
31 */
