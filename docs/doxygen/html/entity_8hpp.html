Detailed Description

Short names for the CRUD value types and the variant they live in (see api::v2::Types).

This header defines the Entity class, the workhorse that turns a requested operation (create, read, update, delete or search) into a safe SQL statement. It first introduces short aliases for the value types defined in types.hpp so callers do not have to write the long namespace over and over. Entity stores one of those values plus a table name, and exposes five builders - one per operation - that produce SQL with $1, $2, ... placeholders.

WHY THIS FILE MATTERS IN THE SERVER: Entity is the concrete implementation behind the Base interface. Request controllers construct an Entity for the operation they need and call getSql*Statement() to obtain SQL that the database layer executes. More specialised entities (Client, Service, Case, Appointment) inherit from this class and override only what they must. Without it, every controller would have to know how to spell CREATE/READ/UPDATE/DELETE/SEARCH SQL for every table.

CONCEPTS TO LEARN (for beginners):

  • std::variant: https://en.cppreference.com/w/cpp/utility/variant
  • std::optional: https://en.cppreference.com/w/cpp/utility/optional
  • SQL parameter binding: put $1, $2, ... markers in the SQL and pass the real values separately; see https://en.cppreference.com/w/cpp or the libpqxx documentation.
  • A "type alias" (using X = Y) gives a long type a short local name; no new type is created.
