Detailed Description

Implementation for asyncdberror.

This file implements the three error-classification helpers. isBusy() first recognises our own DatabaseBusy exception and then looks for a few telling words in the error text (such as "timeout" or "pool"). toHttpStatus() turns that answer into an HTTP code, and throwIfBusy() re-raises the project's DatabaseBusy type so the shared HTTP error handler can produce a 503 response.

WHY THIS FILE MATTERS IN THE SERVER: Every coroutine-based database method in DatabaseController catches a plain std::exception when a query fails. This file is what lets those methods tell a temporary overload apart from a real bug. Because both the old synchronous pool and the new async path end up producing the same DatabaseBusy exception, the HTTP layer needs only one rule for answering 503 with Retry-After. Without this file, async database failures would all look alike and temporary outages would be reported as permanent server errors.
