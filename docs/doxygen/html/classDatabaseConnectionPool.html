Detailed Description

Owns the fixed set of synchronous Database connections and leases them to callers.

Connections are created in parallel at construction and stored in a BlockingPool. Callers obtain a connection with get_connection() and must give it back with return_connection(); in practice DatabaseHanndler does this via RAII. The acquire timeout is read once from configuration at startup. When a wait for a connection expires, get_connection() throws DatabaseBusy, which the HTTP layer maps to 503. 

     Thread-safety: connection hand-out and return are serialised by

BlockingPool; the slow-wait warning rate limiter is atomic. Non-copyable and non-movable.

Warning
A failed initialisation is fatal: the constructor logs and calls exit(EXIT_FAILURE).
See also
BlockingPool, DatabaseHanndler, DatabaseBusy

DatabaseConnectionPool::DatabaseConnectionPool ( )

Builds the pool from the Configurator, creating all connections up front.

Initialises the pool from the Configurator; failure terminates the process.

Reads the acquire timeout and DB_MAX_CONN, warns if the pool is smaller than SERVER_THREADS + 1, then creates connections concurrently with bounded retries and exponential backoff. Any creation failure is fatal (process exit).

Reads DB_MAX_CONN and the acquire timeout, warns when the pool is undersized, then starts all connections concurrently. Each slot retries with exponential backoff (MAX_RETRIES attempts); if any slot cannot be created, a runtime_error is raised and the catch block exits the process with EXIT_FAILURE.

◆ reconnect_all()

void DatabaseConnectionPool::reconnect_all ( )

Reconnects every idle connection in parallel.

Reconnects all currently idle connections in parallel.

Holds the pool lock for the whole operation so no idle connection can be handed out while it is being reconnected; busy connections are not touched.

Uses forEachIdle to hold the pool lock while the reconnect tasks run and until every task has been waited on, so no idle connection is handed out half-way through a reconnect. Busy (already leased) connections are not touched here.

Note
Each reconnect's success or failure (including exceptions) is logged; the method itself does not throw for an individual connection failure.
