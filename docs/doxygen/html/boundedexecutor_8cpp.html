Detailed Description

Implementation of BoundedExecutor: per-worker queues, work stealing and shutdown.

This file defines the worker pool's behaviour. The constructor creates all worker objects before starting any threads (so every worker can safely look at every queue), then each thread runs a loop that takes tasks, runs them, and sleeps when there is nothing to do. submit() picks a worker without ever waiting for space, and shutdown() stops new work, drains what is queued and joins the threads.

WHY THIS FILE MATTERS IN THE SERVER: This is where slow, blocking jobs (database calls, password hashing) actually get executed off Drogon's IO threads. It is called through BoundedExecutor::submit() and runOnExecutor() from the database and gatekeeper code. Because it refuses work when full and runs tasks inline with zero workers, it also controls how the server behaves under load and how the unit tests stay deterministic. Without it, slow work would block the web server or grow an unbounded backlog of queued requests.

CONCEPTS TO LEARN (for beginners):

  • thread_local: a variable with one separate copy per running thread. https://en.cppreference.com/w/cpp/language/storage_duration
  • Condition variables: a way for a thread to sleep until another thread wakes it with new work. https://en.cppreference.com/w/cpp/thread/condition_variable
  • Work stealing: an idle worker takes jobs from a busier worker's queue. https://en.wikipedia.org/wiki/Work_stealing
  • Atomic memory order: rules for when one thread's writes become visible to another. https://en.cppreference.com/w/cpp/atomic/memory_order
