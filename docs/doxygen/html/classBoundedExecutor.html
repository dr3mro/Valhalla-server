Detailed Description

Fixed-size worker pool with a shared bounded queue for slow, blocking work.

A fixed pool of threads with a bounded queue. It exists so that slow, blocking work (database calls, password hashing) never runs on a Drogon IO thread. submit() never blocks: it returns false when the queue is full, and the caller answers 503.

Every worker has its own queue and its own lock, so submitters and workers do not all contend on one mutex. submit() picks an idle worker if there is one (so a task never waits behind a slow one while another worker sleeps), otherwise the worker with the shortest queue, so the queues stay the same length and waiting time stays fair (plain round-robin left some queues long and some short, and the tasks in the long ones waited 20 times longer). Only an idle worker is woken (a busy one needs no wake-up, it looks at its queue when it finishes). A worker that has run out of work takes tasks from the other workers' queues before it sleeps. The queue limit is shared: at most queue_max tasks wait across all workers.

With zero workers every task runs inline, on the submitting thread. Unit tests use that so they stay synchronous.

In plain words: imagine a fixed number of chefs (worker threads) each with their own order ticket rack (queue). New orders go to a free chef, or to the shortest rack if nobody is free. A chef with no tickets peek at other racks and helps out before going to sleep ("work stealing"). There is one overall limit on how many tickets may wait; past that, submit() says "no" immediately so the caller can send HTTP 503 rather than let the backlog grow without bound.

Note
Not copyable or movable; instances are kept alive by shared_ptr, typically through the Store.

void BoundedExecutor::run ( std::size_t self)
private

Worker entry point: repeatedly take and run tasks until stopping and no work remains.

Sets the thread_local executor marker, catches exceptions thrown by tasks so they cannot kill the thread, and goes idle with a condition-variable wait when its queue and all stealable queues are empty.

Parameters
[in]selfIndex of this worker.

Worker loop: take tasks, run them, and sleep only when every queue is empty.

Marks the thread with the thread_local executor pointer, then loops taking and running tasks. A task that throws is logged and swallowed so one misbehaving task cannot end the worker thread. When no work is available the worker re-arms its idle flag on every pass before waiting, because a submit() may have claimed it while a thief took the task, leaving a wake-up with an empty queue; sleeping with idle cleared would hide the worker from every later submit(). The loop exits only when stopping is set and the worker's own queue is empty, at which point no new task can arrive. self: Index of this worker.

◆ shutdown()

void BoundedExecutor::shutdown ( )

Drains queued tasks, joins the workers and reports accumulated statistics once.

Stops accepting work, drains queued tasks and joins the workers.

Sets the stopping flag and wakes every worker, then joins those that are not the calling thread (so a task may call shutdown() on its own executor without deadlocking). A later submit() is rejected. Repeated calls are safe: the second pass finds no joinable threads and no un-reported counters.

Note
Must run before dependencies of the tasks (connection pool, Drogon) are destroyed.
See also
~BoundedExecutor()

The stopping flag is published with release semantics; the empty-lock/notify pair then wakes a worker that is either waiting or about to wait, and each worker checks the flag under its own mutex before sleeping. Join is skipped for the calling thread so a task may shut down its own pool. Statistics are logged only when there is something to report, and the counters are cleared so a second call does not log them again. ("Joining" a thread means waiting here until that thread's code has finished.)

◆ submit()

bool BoundedExecutor::submit ( std::function< void()> task)
nodiscard

Offers a task to the pool without waiting for capacity.

In inline mode task() runs synchronously here. Otherwise a slot in the shared queue limit is reserved first; if that limit is reached, or the pool is stopping, the task is discarded and false is returned. An idle worker is preferred, else the shortest queue is chosen, and only an idle worker is notified.

Parameters
[in]taskNullary callable to execute on a worker (or inline). "Nullary" means it takes no arguments.
Returns
true if the task ran inline or was queued; false if it was rejected.
See also
runOnExecutor()

Enqueues a task without blocking, preferring an idle worker and enforcing a shared queue limit.

Inline mode runs the task immediately on the caller. Otherwise the shared queued_ counter is reserved with acq_rel semantics and released if the pool turns out to be full or stopping. The target worker is chosen from a round-robin start: the first idle one, else the shortest queue. The stopping flag is checked again while holding that worker's mutex, matching the worker's own exit check. Only a worker that was idle is notified; a busy worker rechecks its queue when it finishes a task. task: Nullary callable to execute (takes no arguments). Returns true if the task ran inline or was queued; false if it was rejected.
