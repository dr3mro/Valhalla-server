Detailed Description

Maps caught exceptions to the HTTP status reported to API clients.

Provides one small helper, statusForException, that looks at an exception which was caught and decides which HTTP status code the client should receive. A "database busy" problem maps to 503 (try again later); every other problem maps to 500 (generic server error). The function is inline and header-only, so there is no separate .cpp file and no linking needed.

WHY THIS FILE MATTERS IN THE SERVER: When a controller fails while handling a request it must still send an HTTP answer. The CRITICALMESSAGERESPONSE macro (in global.hpp) calls this helper to choose that answer's status. Doing the choice in one place keeps every error response consistent: clients always get 503 specifically when the database was too busy, and 500 for anything else. Without it, each catch block would have to repeat the classification logic.
