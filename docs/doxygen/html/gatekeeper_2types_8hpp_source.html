1/**
2 * @file types.hpp
3 * @brief Login, credential and identity data types used by the gatekeeper
4 * subsystem.
5 * @details This header defines two small plain-data structs that act as
6 * "containers" passed between the login, session and token helpers. Credentials
7 * holds the raw username/password typed by a client. ClientLoginData is a
8 * larger bag of optional fields that grows as a login or authentication request
9 * moves through the system: some fields come from the request, some from the
10 * database, and some are produced when a token is created. Nothing here does
11 * any work; it just gives the different helpers a shared vocabulary for the
12 * data they exchange.
13 *
14 * WHY THIS FILE MATTERS IN THE SERVER:
15 * This file belongs to the gatekeeper (the security/identity part of the
16 * server). GateKeeper reads the request body into Credentials, then creates a
17 * ClientLoginData and passes it to SessionManager (session database rows) and
18 * TokenManager (JWT creation/validation). Almost every security function takes
19 * a ClientLoginData by reference, so without these types the helpers would need
20 * long, duplicated parameter lists and could not share state. Fields are
21 * optional because they are filled in at different stages - a field that is
22 * `nullopt` simply means "not known yet" at this stage of the pipeline.
23 *
24 * CONCEPTS TO LEARN (for beginners):
25 * - struct: https://en.cppreference.com/w/cpp/language/classes
26 * - std::optional ("a value that may be missing"):
27 * https://en.cppreference.com/w/cpp/utility/optional
28 * - std::chrono (time durations/time points):
29 * https://en.cppreference.com/w/cpp/chrono
30 * - JWT (a signed token carrying identity claims): https://jwt.io/introduction
31 * - std::uint64_t (a fixed 64-bit whole number):
32 * https://en.cppreference.com/w/cpp/types/integer
33 *
34 * @author Amr Osman <dr3mro@gmail.com>
35 * @date 2026-11-16
36 */

51 /**
52 * @struct ClientLoginData
53 * @brief Mutable accumulator that carries a client's identity through login
54 * and authentication.
55 * @details The same object is passed from GateKeeper into SessionManager,
56 * TokenManager and KeeprBase helpers. Fields are optional because they are
57 * populated at different stages: some arrive from the request (group,
58 * ip_address), some are read from the database (is_active, lastLogoutTime),
59 * and some are produced by token generation (token, expireTime). Call sites
60 * value-initialize this struct (for example `ClientLoginData{}`), so the
61 * non-optional scalar members start zero-initialized and are only
62 * meaningful once the corresponding helper sets them.
63 * @note `passwordHash` and `passwordMatch` are declared here but are never
64 * assigned in src/; the login flow carries the hash as a separate local
65 * value.
66 * @note Identity claims (username, clientId, group, ip_address,
67 * lastLogoutTime) are bound into the JWT and re-checked on validation, so
68 * changing one invalidates the token.
69 * @details In everyday terms, think of this struct as a "passport
70 * application form" that gets stamped at each desk. It begins nearly empty,
71 * the HTTP request fills in the group and IP, the database fills in the
72 * active flag and last logout time, and the token generator fills in the
73 * token and its expiry. `std::optional` is used for each field because "not
74 * filled in yet" is a normal state, not an error, and it lets helpers check
75 * `has_value()` before using a field. The two plain `bool` fields are not
76 * optional, so they start as `false` after `ClientLoginData{}` and
77 * must be explicitly set from the database before they mean anything.
78 */
79 using ClientLoginData = struct ClientLoginData {
80 std::optional<std::string>
81 token; /**< JWT issued on login; supplied by the client on
82 subsequent requests. Optional because it only exists after
83 token creation, and later requests send it back. */
84 std::optional<std::string>
85 username; /**< Authenticated user name, used as the JWT subject.
86 Optional until the database lookup or token decode
87 supplies it. */
88 std::optional<std::string>
89 group; /**< Client group ("users" or "providers"); selects the
90 session table and becomes a JWT claim. Optional until the
91 request or token says which group.
92 */
93 std::optional<uint64_t>
94 clientId; /**< Numeric client id, used as the JWT "jti" claim. A
95 64-bit unsigned number so it can hold large database
96 ids; optional until resolved. */
97 std::optional<std::string>
98 lastLogoutTime; /**< Last logout timestamp from the session table,
99 mirrored as the "llodt" claim to detect later
100 logouts. Stored as text because that is how it is
101 kept in the database. */
102 std::optional<std::string>
103 nowLoginTime; /**< Timestamp of the login currently being processed,
104 written to the session row. Optional until the
105 login helper generates the current UTC time. */
106 bool is_active; /**< Account active flag read from the client table;
107 gates token validation. A plain bool (zero-initialized
108 to false) so a suspended account fails closed. */
109 bool passwordMatch; /**< Declared but never assigned in src/; reserved
110 for login state. Kept as a plain bool for future
111 use. */
112 std::optional<std::string>
113 passwordHash; /**< Declared but never assigned in src/; the hash is
114 passed as a local value. Optional because this
115 struct does not actually carry it in the current
116 flow. */
117 std::chrono::system_clock::duration
118 expireTime; /**< Token expiry as a system_clock duration, compared
119 against the current time during decode. A duration
120 (not a string) makes the "now >= expiry" comparison
121 easy and exact. */
122 std::optional<std::string>
123 ip_address; /**< Client IP bound into the token and compared against
124 the request IP on validation. Optional until the
125 filter supplies it; binding it stops a stolen token
126 being reused elsewhere. */
127 };

129 /**
130 * @struct Credentials
131 * @brief Raw username/password pair parsed from a login request body.
132 * @details Held only until the slow password work is dispatched to the
133 * password worker.
134 * @details These are ordinary non-optional strings because a login request
135 * must have both values for parsing to succeed. The check that both keys
136 * exist is done by GateKeeper::parse_credentials before this struct is
137 * built, so by the time a Credentials object exists its fields are known to
138 * be present. It is a small value type on purpose: it gets moved into a
139 * lambda that runs on a worker thread, so keeping it cheap to copy/move
140 * avoids extra work.
141 */
142 using Credentials = struct Credentials {
143 std::string
144 username; /**< The user's username. Plain string because it is
145 required; used to look up the stored password hash. */
146 std::string password; /**< The user's password. Plain string because it is
147 required; compared against the stored hash on the
148 password worker, never stored here long-term. */
149 };
