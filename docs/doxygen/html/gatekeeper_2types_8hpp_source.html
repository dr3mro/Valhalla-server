1/**
2 * @file types.hpp
3 * @brief Login, credential and identity data types used by the gatekeeper subsystem.
4 * @details This header defines two small plain-data structs that act as "containers"
5 * passed between the login, session and token helpers. Credentials holds the
6 * raw username/password typed by a client. ClientLoginData is a larger bag of
7 * optional fields that grows as a login or authentication request moves through
8 * the system: some fields come from the request, some from the database, and
9 * some are produced when a token is created. Nothing here does any work; it just
10 * gives the different helpers a shared vocabulary for the data they exchange.
11 *
12 * WHY THIS FILE MATTERS IN THE SERVER:
13 * This file belongs to the gatekeeper (the security/identity part of the server). GateKeeper
14 * reads the request body into Credentials, then creates a ClientLoginData and passes it to
15 * SessionManager (session database rows) and TokenManager (JWT creation/validation). Almost
16 * every security function takes a ClientLoginData by reference, so without these types the
17 * helpers would need long, duplicated parameter lists and could not share state. Fields are
18 * optional because they are filled in at different stages - a field that is `nullopt` simply
19 * means "not known yet" at this stage of the pipeline.
20 *
21 * CONCEPTS TO LEARN (for beginners):
22 * - struct: https://en.cppreference.com/w/cpp/language/classes
23 * - std::optional ("a value that may be missing"): https://en.cppreference.com/w/cpp/utility/optional
24 * - std::chrono (time durations/time points): https://en.cppreference.com/w/cpp/chrono
25 * - JWT (a signed token carrying identity claims): https://jwt.io/introduction
26 * - std::uint64_t (a fixed 64-bit whole number): https://en.cppreference.com/w/cpp/types/integer
27 *
28 * @author Amr Osman <dr3mro@gmail.com>
29 * @date 2026-11-16
30 */

40 /**
41 * @struct ClientLoginData
42 * @brief Mutable accumulator that carries a client's identity through login and authentication.
43 * @details The same object is passed from GateKeeper into SessionManager, TokenManager and
44 * KeeprBase helpers. Fields are optional because they are populated at different
45 * stages: some arrive from the request (group, ip_address), some are read from the
46 * database (is_active, lastLogoutTime), and some are produced by token
47 * generation (token, expireTime). Call sites value-initialize this struct (for
48 * example `ClientLoginData{}`), so the non-optional scalar members start
49 * zero-initialized and are only meaningful once the corresponding helper sets them.
50 * @note `passwordHash` and `passwordMatch` are declared here but are never assigned in src/;
51 * the login flow carries the hash as a separate local value.
52 * @note Identity claims (username, clientId, group, ip_address, lastLogoutTime) are bound into
53 * the JWT and re-checked on validation, so changing one invalidates the token.
54 * @details In everyday terms, think of this struct as a "passport application form" that gets
55 * stamped at each desk. It begins nearly empty, the HTTP request fills in the group
56 * and IP, the database fills in the active flag and last logout time, and the token
57 * generator fills in the token and its expiry. `std::optional` is used for each field
58 * because "not filled in yet" is a normal state, not an error, and it lets helpers
59 * check `has_value()` before using a field. The two plain `bool` fields are not
60 * optional, so they start as `false` after `ClientLoginData{}` and must be explicitly
61 * set from the database before they mean anything.
62 */
63 using ClientLoginData = struct ClientLoginData
64 {
65 std::optional<std::string> token; /**< JWT issued on login; supplied by the client on subsequent requests. Optional because it only exists after token creation, and later requests send it back. */
66 std::optional<std::string> username; /**< Authenticated user name, used as the JWT subject. Optional until the database lookup or token decode supplies it. */
67 std::optional<std::string> group; /**< Client group ("users" or "providers"); selects the session table and becomes a JWT claim. Optional until the request or token says which group. */
68 std::optional<uint64_t> clientId; /**< Numeric client id, used as the JWT "jti" claim. A 64-bit unsigned number so it can hold large database ids; optional until resolved. */
69 std::optional<std::string> lastLogoutTime; /**< Last logout timestamp from the session table, mirrored as the "llodt" claim to detect later logouts. Stored as text because that is how it is kept in the database. */
70 std::optional<std::string> nowLoginTime; /**< Timestamp of the login currently being processed, written to the session row. Optional until the login helper generates the current UTC time. */
71 bool is_active; /**< Account active flag read from the client table; gates token validation. A plain bool (zero-initialized to false) so a suspended account fails closed. */
72 bool passwordMatch; /**< Declared but never assigned in src/; reserved for login state. Kept as a plain bool for future use. */
73 std::optional<std::string> passwordHash; /**< Declared but never assigned in src/; the hash is passed as a local value. Optional because this struct does not actually carry it in the current flow. */
74 std::chrono::system_clock::duration expireTime; /**< Token expiry as a system_clock duration, compared against the current time during decode. A duration (not a string) makes the "now >= expiry" comparison easy and exact. */
75 std::optional<std::string> ip_address; /**< Client IP bound into the token and compared against the request IP on validation. Optional until the filter supplies it; binding it stops a stolen token being reused elsewhere. */
76 };

78 /**
79 * @struct Credentials
80 * @brief Raw username/password pair parsed from a login request body.
81 * @details Held only until the slow password work is dispatched to the password worker.
82 * @details These are ordinary non-optional strings because a login request must have both
83 * values for parsing to succeed. The check that both keys exist is done by
84 * GateKeeper::parse_credentials before this struct is built, so by the time a
85 * Credentials object exists its fields are known to be present. It is a small
86 * value type on purpose: it gets moved into a lambda that runs on a worker thread,
87 * so keeping it cheap to copy/move avoids extra work.
88 */
89 using Credentials = struct Credentials
90 {
91 std::string username; /**< The user's username. Plain string because it is required; used to look up the stored password hash. */
92 std::string password; /**< The user's password. Plain string because it is required; compared against the stored hash on the password worker, never stored here long-term. */
93 };
