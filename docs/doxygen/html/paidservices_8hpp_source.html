2 * @file paidservices.hpp
3 * @brief Case entity for the `clinics_paidservices` table (a visit's paid
4 * services).
5 * @details This header declares the PaidServices class, a small C++ type that
6 * stands for the paid-services record of one visit in the
7 * `clinics_paidservices` database table. There is at most one such record per
8 * visit because the visit id is the table's primary key. The class itself holds
9 * no data; it names the table and leaves SQL generation to its parent Case. It
10 * also supplies small helper functions that build permission-checking SQL for
11 * create, read, update and delete operations.
12 *
13 * WHY THIS FILE MATTERS IN THE SERVER:
14 * PaidServices is one of the clinic-owned "case" types exposed through the
15 * clinic routes as ClinicController<PaidServices> under the `paidservices`
16 * service type. When a client wants to add or change a visit's paid services,
17 * PermissionManager calls the static getPermissionsQueryFor* helpers here to
18 * build a SELECT that finds which clinic owns the visit (via `clinics_visits`),
19 * then checks whether the requesting user is that clinic's owner, admin or
20 * staff. Without this file there would be no C++ type connecting the
21 * `clinics_paidservices` table to the CRUD and permission machinery, so
22 * paid-services endpoints could not work.
23 *
24 * CONCEPTS TO LEARN (for beginners):
25 * - static constexpr: a value fixed at compile time that belongs to the class,
26 * not to one object. https://en.cppreference.com/w/cpp/language/static
27 * - JSON: a text format used to carry request data; this project uses the
28 * jsoncons library to read it. https://jsoncons.github.io/jsoncons/
29 * - Foreign key / ON DELETE CASCADE: a column that points to a row in another
30 * table, with the database automatically deleting this row when that parent row
31 * is deleted. https://en.cppreference.com/w/cpp
32 *
33 * @author Amr Osman <dr3mro@gmail.com>
34 * @date 2026-11-16
35 */

134 /**
135 * @brief Builds the SQL that resolves the owning clinic for a create
136 * request.
137 * @details Reads the visit id from `data_j` using CREATE_KEY and delegates
138 * to the Case base, which joins `clinics` with `clinics_visits` on
139 * clinic_id. PermissionManager runs the returned SELECT before the insert;
140 * no insert occurs here.
141 * @param[in] data_j Create payload; must be engaged and contain an
142 * unsigned-integer CREATE_KEY (the optional is dereferenced without a
143 * has_value() check).
144 * @return The SELECT statement, or std::nullopt if reading or converting
145 * the key throws; the exception is logged via CRITICALMESSAGE.
146 * @see Case::getPermissionsQueryForCreateImpl
147 */
148 // Returns a query string, or nothing if the payload is
149 // malformed.
150 static std::optional<std::string> getPermissionsQueryForCreate(
151 const std::optional<jsoncons::json>& data_j) {
152 uint64_t id; // Will hold the visit id pulled from the JSON payload; an
153 // unsigned 64-bit integer matches database ids.
154 // Reading JSON can fail (missing field or wrong type), so guard
155 // it.
156 try {
157 // Dereference the optional payload, look
158 // up the "id" field and convert it to an
159 // integer.
160 // Any read/conversion problem lands here.
161 id = data_j->at(CREATE_KEY).as<uint64_t>();
162 } catch (const std::exception& e) {
163 CRITICALMESSAGE // Log the failure (macro uses the caught
164 // exception) so the problem is visible in server
165 // logs.
166 return std::nullopt; // No trustworthy id means no safe query
167 // can be built, so report failure to the
168 // caller.
169 }
170
171 return getPermissionsQueryForCreateImpl(
172 id,
173 KEYREFTABLENAME); // Hand the id
174 // and
175 // `clinics_visits`
176 // table to Case,
177 // which writes
178 // the join SQL
179 // that finds the
180 // owning clinic.
181 }
