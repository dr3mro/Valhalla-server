1/**
2 * @file cliniccontroller.hpp
3 * @brief Clinic-entity handler that specializes generic CRUDS behaviour per entity type via constrained helpers.
4 * @details Declares `ClinicController<T>`, which inherits storage from EntityController<T> and the clinic contract
5 * from ClinicControllerBase. Public methods are thin forwarders to private `...Impl` helpers; each helper has
6 * a C++20 `requires` clause so the compiler picks the right behaviour for the concrete entity type. For
7 * example, Patient/Visits use server-assigned ids and support Delete, while other types carry a client id
8 * and get a "not implemented" answer for Delete/Search/GetVisits.
9 *
10 * WHY THIS FILE MATTERS IN THE SERVER:
11 * Clinic data has type-specific rules that a single generic handler cannot express cleanly. This class centralizes
12 * those rules using compile-time constraints, so the public API stays uniform while the correct behaviour is chosen
13 * automatically for each entity. Without it, every clinic handler would need hand-written special cases.
14 *
15 * CONCEPTS TO LEARN (for beginners):
16 * - Requires clauses / constraints (C++20): https://en.cppreference.com/w/cpp/language/requires
17 * - Templates: https://en.cppreference.com/w/cpp/language/templates
18 * - `final` and virtual overrides: https://en.cppreference.com/w/cpp/language/virtual
19 * - Coroutines (co_await / drogon::Task): https://en.cppreference.com/w/cpp/language/coroutines
20 * - std::shared_ptr (sharing the GateKeeper): https://en.cppreference.com/w/cpp/memory/shared_ptr
21 *
22 * @author Amr Osman <dr3mro@gmail.com>
23 * @date 2026-11-16
24 */

36/**
37 * @class ClinicController
38 * @brief Clinic-entity handler that specializes generic CRUDS behaviour per entity type via constrained helpers.
39 * @details Inherits persistence from EntityController<T> and the clinic contract from ClinicControllerBase. Public
40 * methods are thin forwarders to private `...Impl` overloads selected by C++20 `requires` clauses. This
41 * lets the controller distinguish, for example, Patient/Visits (which use server-assigned ids and support
42 * Delete) from other clinic entities (which carry a client-supplied id and reject Delete/Search/GetVisits).
43 * @tparam T Clinic entity type; the constraints inside each helper decide which specialization applies.
44 * @note All public overrides are `final`. Coroutine variants borrow their arguments and must be awaited while alive.
45 * @see ClinicControllerBase, EntityController
46 */
