Detailed Description

Compile-time constraints tying generic API code to domain types.

Declares four C++20 "concepts" — named conditions that a type must satisfy before a template will accept it. Each one checks that a type is a particular domain class (Client, Service, Case or Appointment) or something derived from it. The classes themselves are only forward-declared here, so this header stays light and does not pull in heavy definitions. The checks happen during compilation, so a wrong type produces a clear compile error instead of a crash at runtime.

WHY THIS FILE MATTERS IN THE SERVER: The controllers are templates that work with several related entity types. These concepts act as a safety gate: they stop someone instantiating a controller with an unrelated type (for example, a std::string) by rejecting it at compile time. This keeps the generic API code flexible but still tied to the real domain objects. It is a header-only helper included where those generic templates are declared.
