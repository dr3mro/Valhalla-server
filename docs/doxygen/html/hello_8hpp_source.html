1/**
2 * @file hello.hpp
3 * @brief Minimal welcome endpoint used to confirm the API is reachable.
4 * @details This file defines the Hello controller with one tiny endpoint. When
5 * called it always sends back the same JSON greeting with status 200. It reads
6 * nothing from the request, touches no database and keeps no state, which makes
7 * it the simplest possible example of a Drogon route. Its main job is to act as
8 * a liveness check: if this endpoint answers, the server is up and the HTTP
9 * stack is working.
10 *
11 * WHY THIS FILE MATTERS IN THE SERVER:
12 * This is the "is the API alive?" endpoint. Operators and automated health
13 * checks call it to confirm the server is running without needing a login or
14 * any data. Drogon serves it at /api/v2/hello through the INSECURE chain, so it
15 * is rate-limited and timed but requires no token. It calls JsonHelper to build
16 * the greeting; without it there would be no quick way to verify basic
17 * connectivity.
18 *
19 * CONCEPTS TO LEARN (for beginners):
20 * - Health/liveness endpoint: a trivial URL used to check a service is running.
21 * - HTTP GET: https://developer.mozilla.org/en-US/docs/Web/HTTP/Methods
22 * - HTTP filters/middleware: https://drogon.docsforge.com/master/filter/
23 * - CORS: https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS
24 *
25 * @author Amr Osman <dr3mro@gmail.com>
26 * @date 2026-11-16
27 */
