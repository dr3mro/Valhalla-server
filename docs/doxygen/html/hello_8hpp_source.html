4 * @details This file defines the Hello controller with one tiny endpoint. When called it always sends
5 * back the same JSON greeting with status 200. It reads nothing from the request, touches no
6 * database and keeps no state, which makes it the simplest possible example of a Drogon
7 * route. Its main job is to act as a liveness check: if this endpoint answers, the server is
8 * up and the HTTP stack is working.
9 *
10 * WHY THIS FILE MATTERS IN THE SERVER:
11 * This is the "is the API alive?" endpoint. Operators and automated health checks call it to confirm
12 * the server is running without needing a login or any data. Drogon serves it at /api/v2/hello through
13 * the INSECURE chain, so it is rate-limited and timed but requires no token. It calls JsonHelper to
14 * build the greeting; without it there would be no quick way to verify basic connectivity.
15 *
16 * CONCEPTS TO LEARN (for beginners):
17 * - Health/liveness endpoint: a trivial URL used to check a service is running.

58 std::move(callback)(response); // Send the finished response to the client.
59 }
