Detailed Description

Drogon-free helpers for parsing and merging CORS header token lists.

Kept independent of the HTTP framework so token parsing can be reasoned about, and tested, on its own.

std::string CorsTokens::mergeVary ( std::string_view existing,
std::string_view value )
inline

Merges a token into an existing Vary header value, avoiding duplicates.

Tokens are compared case-insensitively. A "*" wildcard in the existing value means every response is already variable, so the value is returned unchanged; likewise when the token is already present. Otherwise the token is appended. The original string is returned unchanged when no edit is needed, which lets the caller skip the header write.

Parameters
[in]existingCurrent Vary header value.
[in]valueToken to add.
Returns
The merged Vary value.

◆ sanitizeRequestedHeaders()

std::string CorsTokens::sanitizeRequestedHeaders ( std::string_view requested)
inline

Filters a client-supplied Access-Control-Request-Headers value down to syntactically valid tokens.

Rejects the whole value when it is empty or longer than 1024 characters, then keeps only comma-separated tokens made entirely of token characters and rejoins them with ", ". This prevents a preflight request from echoing CRLF, quotes or arbitrary separators into Access-Control-Allow-Headers.

Parameters
[in]requestedRaw header value from the request.
Returns
A comma-and-space separated list of safe tokens, or an empty string when nothing is acceptable. An empty result tells Cors::apply() to fall back to the default header list.

◆ tokens()

auto CorsTokens::tokens ( std::string_view value)
inline

Lazily splits a comma-separated header value into trimmed, non-empty tokens.

The returned range is a view: it allocates nothing and borrows from value, so the caller must keep the underlying string alive while iterating. Empty list elements (including ones made only of whitespace) are filtered out.

Parameters
[in]valueHeader value to split.
Returns
