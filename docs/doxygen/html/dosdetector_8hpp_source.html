1/**
2 * @file dosdetector.hpp
3 * @brief Per-IP abuse detector combining static lists with sliding-window request counting.
4 * @details This header declares DOSDetector, a class that decides whether an incoming request
5 * should be allowed, is on a whitelist/blacklist, or is part of abusive traffic. It
6 * counts recent requests per IP address and per "fingerprint" (a hash of the request's
7 * headers and body) inside a moving time window. Too many different fingerprints means
8 * "rate limited"; too many repeats of one fingerprint means "banned". A background
9 * thread periodically removes counters and blocks that have expired.
10 *
11 * WHY THIS FILE MATTERS IN THE SERVER:
12 * This is the defence against denial-of-service and brute-force traffic. A Drogon filter
13 * (Filters::RateLimit) captures each request and calls GateKeeper::isDosAttack, which forwards
14 * to this detector's is_dos_attack(). Based on the returned Status the filter either lets the
15 * request through or sends an error. The detector is one shared object in Store, so all request
16 * threads see the same counters. Without it the server would have no way to notice or slow an
17 * attacker flooding it with requests.
18 *
19 * CONCEPTS TO LEARN (for beginners):
20 * - Mutex/lock (protecting shared data from simultaneous threads): https://en.cppreference.com/w/cpp/thread/mutex
21 * - Condition variable (a thread sleeping until told to wake): https://en.cppreference.com/w/cpp/thread/condition_variable
22 * - std::async / std::future (running a task in the background): https://en.cppreference.com/w/cpp/thread/async
23 * - std::atomic (a variable safe to read/write from many threads): https://en.cppreference.com/w/cpp/atomic/atomic
24 * - Sliding window / rate limiting: https://en.wikipedia.org/wiki/Rate_limiting
25 * - Denial-of-service attack: https://en.wikipedia.org/wiki/Denial-of-service_attack
26 * - Hash function (turning data into a fixed-size number): https://en.wikipedia.org/wiki/Hash_function
27 * - xxHash (the fast hash used here): https://github.com/Cyan4973/xxHash
28 * - Regular expression: https://en.cppreference.com/w/cpp/regex
29 * - CIDR notation (IP address + network prefix): https://en.wikipedia.org/wiki/Classless_Inter-Domain_Routing
30 *
31 * @author Amr Osman <dr3mro@gmail.com>
32 * @date 2026-11-16
33 */

57/**
58 * @class DOSDetector
59 * @brief Per-IP abuse detector combining static lists with sliding-window request counting.
60 * @details Instances classify requests as whitelisted, blacklisted, rate-limited, banned or
61 * allowed. State is kept in several maps, each guarded by its own mutex, and a
62 * background cleanup thread periodically prunes expired timestamps and block entries.
63 * The detector is shared process-wide through Store and consulted by the RateLimit
64 * filter via GateKeeper::isDosAttack. Configuration and the clock are injectable for
65 * deterministic tests without changing production behaviour.
66 * @note Thread-safety: per-map mutexes serialize access to the corresponding state; matcher
67 * lists are compiled once at construction and are thereafter immutable. The detector is
68 * non-copyable and non-movable because it owns a background thread and mutexes.
69 * @see GateKeeper::isDosAttack, Filters::RateLimit
70 * @details For a beginner: imagine a bouncer with three lists. The whitelist never gets counted,
71 * the blacklist is refused immediately, and everyone else is counted. If an IP sends
72 * many *different* requests quickly it is rate-limited; if it repeats the *same*
73 * request too often it is banned. Separate locks protect separate lists so different
74 * threads can check different lists at the same time. The "injectable clock" simply
75 * means tests can supply a fake time source instead of the real one.
76 */

100 /**
101 * @brief Hashes a range of key/value pairs into a single header fingerprint.
102 * @details Only the values are hashed, and the per-value XXH3 digests are combined with XOR,
103 * so the result is independent of insertion order and of header names. Callers must
104 * keep the underlying value storage alive for the duration of the call.
105 * @tparam Range Range of pairs whose second element is convertible to a byte span.
106 * @param[in] headers Header collection (for example Drogon's request headers).
107 * @return Combined 64-bit hash (zero for an empty range).
108 * @details XOR is used to combine the digests because a XOR b equals b XOR a; that makes the
109 * result order-independent, which is useful because HTTP header order is not
110 * meaningful. It also means duplicate headers cancel each other out.
111 */
112 template <typename Range>
113 static std::uint64_t hashHeaders(const Range& headers)
114 {
115 std::uint64_t h = 0; // Start at zero; XOR-ing values into zero just yields those values.
116 for (const auto& kv : headers) // Visit every header in the collection.
117 {
118 h ^= XXH3_64bits(kv.second.data(), kv.second.size()); // Hash only the value (kv.second) and fold it in with XOR.
119 }
120 return h; // The combined fingerprint (zero if there were no headers).
121 }
