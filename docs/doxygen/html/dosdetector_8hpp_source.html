2 * @file dosdetector.hpp
3 * @brief Per-IP abuse detector combining static lists with sliding-window
4 * request counting.
5 * @details This header declares DOSDetector, a class that decides whether an
6 * incoming request should be allowed, is on a whitelist/blacklist, or is part
7 * of abusive traffic. It counts recent requests per IP address and per
8 * "fingerprint" (a hash of the request's headers and body) inside a moving time
9 * window. Too many different fingerprints means "rate limited"; too many
10 * repeats of one fingerprint means "banned". A background thread periodically
11 * removes counters and blocks that have expired.
12 *
13 * WHY THIS FILE MATTERS IN THE SERVER:
14 * This is the defence against denial-of-service and brute-force traffic. A
15 * Drogon filter (Filters::RateLimit) captures each request and calls
16 * GateKeeper::isDosAttack, which forwards to this detector's is_dos_attack().
17 * Based on the returned Status the filter either lets the request through or
18 * sends an error. The detector is one shared object in Store, so all request
19 * threads see the same counters. Without it the server would have no way to
20 * notice or slow an attacker flooding it with requests.
21 *
22 * CONCEPTS TO LEARN (for beginners):
23 * - Mutex/lock (protecting shared data from simultaneous threads):
24 * https://en.cppreference.com/w/cpp/thread/mutex
25 * - Condition variable (a thread sleeping until told to wake):
26 * https://en.cppreference.com/w/cpp/thread/condition_variable
27 * - std::async / std::future (running a task in the background):
28 * https://en.cppreference.com/w/cpp/thread/async
29 * - std::atomic (a variable safe to read/write from many threads):
30 * https://en.cppreference.com/w/cpp/atomic/atomic
31 * - Sliding window / rate limiting: https://en.wikipedia.org/wiki/Rate_limiting
32 * - Denial-of-service attack:
33 * https://en.wikipedia.org/wiki/Denial-of-service_attack
34 * - Hash function (turning data into a fixed-size number):
35 * https://en.wikipedia.org/wiki/Hash_function
36 * - xxHash (the fast hash used here): https://github.com/Cyan4973/xxHash
37 * - Regular expression: https://en.cppreference.com/w/cpp/regex
38 * - CIDR notation (IP address + network prefix):
39 * https://en.wikipedia.org/wiki/Classless_Inter-Domain_Routing
40 *
41 * @author Amr Osman <dr3mro@gmail.com>
42 * @date 2026-11-16
43 */

77/**
78 * @class DOSDetector
79 * @brief Per-IP abuse detector combining static lists with sliding-window
80 * request counting.
81 * @details Instances classify requests as whitelisted, blacklisted,
82 * rate-limited, banned or allowed. State is kept in several maps, each guarded
83 * by its own mutex, and a background cleanup thread periodically prunes expired
84 * timestamps and block entries. The detector is shared process-wide through
85 * Store and consulted by the RateLimit filter via GateKeeper::isDosAttack.
86 * Configuration and the clock are injectable for deterministic tests without
87 * changing production behaviour.
88 * @note Thread-safety: per-map mutexes serialize access to the corresponding
89 * state; matcher lists are compiled once at construction and are thereafter
90 * immutable. The detector is non-copyable and non-movable because it owns a
91 * background thread and mutexes.
92 * @see GateKeeper::isDosAttack, Filters::RateLimit
93 * @details For a beginner: imagine a bouncer with three lists. The whitelist
94 * never gets counted, the blacklist is refused immediately, and everyone else
95 * is counted. If an IP sends many *different* requests quickly it is
96 * rate-limited; if it repeats the *same* request too often it is banned.
97 * Separate locks protect separate lists so different threads can check
98 * different lists at the same time. The "injectable clock" simply means tests
99 * can supply a fake time source instead of the real one.
100 */

134 /**
135 * @brief Hashes a range of key/value pairs into a single header
136 * fingerprint.
137 * @details Only the values are hashed, and the per-value XXH3 digests are
138 * combined with XOR, so the result is independent of insertion order and of
139 * header names. Callers must keep the underlying value storage alive for
140 * the duration of the call.
141 * @tparam Range Range of pairs whose second element is convertible to a
142 * byte span.
143 * @param[in] headers Header collection (for example Drogon's request
144 * headers).
145 * @return Combined 64-bit hash (zero for an empty range).
146 * @details XOR is used to combine the digests because a XOR b equals b XOR
147 * a; that makes the result order-independent, which is useful because HTTP
148 * header order is not meaningful. It also means duplicate headers cancel
149 * each other out.
150 */
151 template <typename Range>
152 static std::uint64_t hashHeaders(const Range& headers) {
153 std::uint64_t h = 0; // Start at zero; XOR-ing values into zero just
154 // yields those values.
155 // Visit every header in the collection.
156 for (const auto& kv : headers) {
157 h ^= XXH3_64bits(kv.second.data(),
158 kv.second.size()); // Hash only the value (kv.second)
159 // and fold it in with XOR.
160 }
161 return h; // The combined fingerprint (zero if there were no headers).
162 }
