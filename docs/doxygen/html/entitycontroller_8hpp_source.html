2 * @file entitycontroller.hpp
3 * @brief Generic request-facing CRUDS handler: validates and authorizes a request, then delegates persistence to Controller.
4 * @details Declares `EntityController<T>`, the class that turns an HTTP request body into a validated, authorized
5 * entity and then hands it to the lower-level Controller for persistence. For each of the ten operations it
6 * follows the same recipe: parse JSON, validate against the entity schema, ask GateKeeper for permission,
7 * build the entity, and call the matching Controller method. The .cpp file holds the definitions.
8 *
9 * WHY THIS FILE MATTERS IN THE SERVER:
10 * This is the bridge between "a request came in" and "a row was written". The generic ClientController and
11 * ClinicController both inherit from it, reusing its Read/Search/Update flows. Without this class each entity type
12 * would need its own copy of the parse-validate-authorize-delegate pipeline, and validation/security rules would drift.
13 *

19 * - std::shared_ptr (sharing the GateKeeper service): https://en.cppreference.com/w/cpp/memory/shared_ptr
20 * - Callback / std::function: https://en.cppreference.com/w/cpp/utility/functional/function

45/**
46 * @class EntityController
47 * @brief Generic request-facing CRUDS handler: validates and authorizes a request, then delegates persistence to Controller.
48 * @details Combines the persistence engine (Controller) with the abstract CRUDS interface (EntityControllerBase).
49 * Each operation follows the same pipeline: parse/validate the JSON body against the entity's database
50 * schema, ask GateKeeper whether @p requester may perform the action, construct the entity from the
51 * appropriate Types data carrier, and call the matching Controller method (or its coroutine counterpart).
52 * Failure at any stage answers through @p callback and returns early, so no database connection is taken
53 * for a request that fails validation or authorization.
54 *
55 * @tparam T Entity type whose static `getTableName()` and data-carrier constructors (Create_t/Read_t/Update_t/
56 * Delete_t/Search_t) define the schema used for validation and persistence.
57 * @note All operations are `override` implementations of EntityControllerBase. Coroutine variants borrow their
58 * arguments and must be awaited while those arguments (and the controller) remain alive.
59 * @see EntityControllerBase, Controller, GateKeeper
60 */
61template <typename T>
62class EntityController : public Controller, public EntityControllerBase
63{
64 public:
65 EntityController() = default; // Uses the base GateKeeper initializer.
66 EntityController(const EntityController&) = default; // Copying shares the GateKeeper handle.
67 EntityController(EntityController&&) = default; // Moving transfers the GateKeeper handle.
68 EntityController& operator=(const EntityController&) = default; // Copy assignment shares the handle.
69 EntityController& operator=(EntityController&&) = default; // Move assignment transfers the handle.
70 ~EntityController() override = default; // Virtual via both bases; no explicit cleanup needed.
