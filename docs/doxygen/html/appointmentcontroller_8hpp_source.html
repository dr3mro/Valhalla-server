1/**
2 * @file appointmentcontroller.hpp
3 * @brief Appointment-entity controller that adapts @ref EntityController to
4 * @ref AppointmentControllerBase.
5 * @details In plain words, this file defines a small "adapter" class for each
6 * kind of appointment (clinic appointment, pharmacy appointment, laboratory
7 * appointment, radiology-center appointment). An adapter is a thin wrapper that
8 * passes a request straight through to another class that does the real work —
9 * here @ref EntityController. Every job below (create, read, update, delete,
10 * search and their coroutine versions) simply forwards to the matching method
11 * of `EntityController<T>`. This class adds no behaviour of its own:
12 * validation, permission checks, building the database query, turning
13 * results into JSON and mapping errors to HTTP codes all happen in that base
14 * class.
15 *
16 * WHY THIS FILE MATTERS IN THE SERVER:
17 * It gives appointment entities their own interface, separate from service
18 * entities, so the route registry can pick the right controller family by name.
19 * The HTTP layer calls these methods through
20 * @ref AppointmentControllerBase (using a `std::variant`), and each call lands
21 * here and is handed to
22 * @ref EntityController. If this file were missing, there would be no concrete
23 * class satisfying the appointment interface and no way to route an appointment
24 * request to the real CRUD+S code.
25 *
26 * CONCEPTS TO LEARN (for beginners):
27 * - Templates (writing one class that works for many types):
28 * https://en.cppreference.com/w/cpp/language/templates
29 * - C++20 concepts / requires (compile-time checks on template arguments):
30 * https://en.cppreference.com/w/cpp/language/constraints
31 * - C++20 coroutines (functions that pause and resume with co_await/co_return):
32 * https://en.cppreference.com/w/cpp/language/coroutines
33 *
34 * @author Amr Osman <dr3mro@gmail.com>
35 * @date 2026-11-16
36 */

61/**
62 * @class AppointmentController
63 * @brief Appointment-entity controller that adapts @ref EntityController to
64 * @ref AppointmentControllerBase.
65 * @tparam T Appointment entity type; must satisfy @ref Appointment_t (derived
66 * from `Appointment`).
67 * @details A thin, stateless adapter: each CRUD+S entry point forwards to the
68 * same-named method of `EntityController<T>`. Schema validation, permission
69 * checks, entity construction, SQL execution, JSON marshalling and error→HTTP
70 * mapping are therefore inherited rather than reimplemented here; `T` supplies
71 * the table name, SQL statements and permission queries. The distinct base
72 * interface lets the appointments route registry select appointment controllers
73 * independently of service controllers.
74 *
75 * Plain-language version: `T` is whichever appointment class we are
76 * handling (say `ClinicAppointment`). The `Appointment_t` after `template` is a
77 * "concept" — a compile-time check that refuses to build this class unless `T`
78 * is really an appointment type. Because this class stores no data
79 * ("stateless"), its only job is to hand the arguments to `EntityController<T>`
80 * and let that base do everything.
81 *
82 * Explicit instantiations exist for `ClinicAppointment`,
83 * `PharmacyAppointment`, `LaboratoryAppointment` and
84 * `RadiologyCenterAppointment`.
85 * @note Copy and move are permitted, matching the value semantics of @ref
86 * EntityController; the route registry nonetheless holds controllers as shared
87 * pointers.
88 * @see EntityController, AppointmentControllerBase, Appointment_t
89 */
