1/**
2 * @file appointmentcontroller.hpp
3 * @brief Appointment-entity controller that adapts @ref EntityController to @ref AppointmentControllerBase.
4 * @details In plain words, this file defines a small "adapter" class for each kind of appointment
5 * (clinic appointment, pharmacy appointment, laboratory appointment, radiology-center
6 * appointment). An adapter is a thin wrapper that passes a request straight through to
7 * another class that does the real work — here @ref EntityController. Every job below
8 * (create, read, update, delete, search and their coroutine versions) simply forwards to the
9 * matching method of `EntityController<T>`. This class adds no behaviour of its own:
10 * validation, permission checks, building the database query, turning results into JSON and
11 * mapping errors to HTTP codes all happen in that base class.
12 *
13 * WHY THIS FILE MATTERS IN THE SERVER:
14 * It gives appointment entities their own interface, separate from service entities, so the route
15 * registry can pick the right controller family by name. The HTTP layer calls these methods through
16 * @ref AppointmentControllerBase (using a `std::variant`), and each call lands here and is handed to
17 * @ref EntityController. If this file were missing, there would be no concrete class satisfying the
18 * appointment interface and no way to route an appointment request to the real CRUD+S code.
19 *
20 * CONCEPTS TO LEARN (for beginners):
21 * - Templates (writing one class that works for many types): https://en.cppreference.com/w/cpp/language/templates
22 * - C++20 concepts / requires (compile-time checks on template arguments): https://en.cppreference.com/w/cpp/language/constraints
23 * - C++20 coroutines (functions that pause and resume with co_await/co_return): https://en.cppreference.com/w/cpp/language/coroutines
24 *
25 * @author Amr Osman <dr3mro@gmail.com>
26 * @date 2026-11-16
27 */

41/**
42 * @class AppointmentController
43 * @brief Appointment-entity controller that adapts @ref EntityController to @ref AppointmentControllerBase.
44 * @tparam T Appointment entity type; must satisfy @ref Appointment_t (derived from `Appointment`).
45 * @details A thin, stateless adapter: each CRUD+S entry point forwards to the same-named method of
46 * `EntityController<T>`. Schema validation, permission checks, entity construction, SQL
47 * execution, JSON marshalling and error→HTTP mapping are therefore inherited rather than
48 * reimplemented here; `T` supplies the table name, SQL statements and permission queries.
49 * The distinct base interface lets the appointments route registry select appointment
50 * controllers independently of service controllers.
51 *
52 * Plain-language version: `T` is whichever appointment class we are handling (say
53 * `ClinicAppointment`). The `Appointment_t` after `template` is a "concept" — a compile-time
54 * check that refuses to build this class unless `T` is really an appointment type. Because
55 * this class stores no data ("stateless"), its only job is to hand the arguments to
56 * `EntityController<T>` and let that base do everything.
57 *
58 * Explicit instantiations exist for `ClinicAppointment`, `PharmacyAppointment`,
59 * `LaboratoryAppointment` and `RadiologyCenterAppointment`.
60 * @note Copy and move are permitted, matching the value semantics of @ref EntityController;
61 * the route registry nonetheless holds controllers as shared pointers.
62 * @see EntityController, AppointmentControllerBase, Appointment_t
63 */
