Detailed Description

Background health monitor for the pooled database connections.

On construction it starts a background work thread that periodically leases one connection, checks it, and reconnects it if the link is lost (also triggering a reconnect of all idle connections through the pool). The monitor flag is atomic so the destructor can signal shutdown and then join the thread. Non-copyable and non-movable.

Note
The destructor may block for up to one check interval while the thread wakes up.
See also
DatabaseHanndler, DatabaseConnectionPool::reconnect_all

WatchDog::WatchDog ( )

Starts the monitoring thread.

Starts the monitoring thread that periodically checks a pooled connection.

Exceptions
std::logic_errorIf a monitor thread appears already joinable (a fresh object has none, so this guard is effectively inactive on construction).

The loop leases a connection through a DatabaseHanndler (so it is returned on scope exit), checks it, and on failure reconnects it and then asks the pool to reconnect all idle connections. DatabaseBusy, a lost connection and any other exception are logged (or warned) and followed by an interval sleep, so one bad cycle cannot spin the loop. The thread reads the atomic stop flag each iteration.

Exceptions
std::logic_errorIf a monitor thread is already joinable.

Signals the monitor thread to stop and joins it before returning.

Stops the monitor and waits for its thread to finish.

The atomic flag is cleared first so the loop exits at its next iteration; join then guarantees the thread is no longer using this before destruction. This must happen before the pool the thread borrows from is torn down.
