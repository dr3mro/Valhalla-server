1/**
2 * @file configurator.cpp
3 * @brief Explicit Configurator::get<T>() specializations that expose each
4 * configuration section.
5 * @details The Configurator class declares a generic get<T>() accessor but does
6 * not define its behaviour for any particular type. This file supplies one
7 * explicit specialization per configuration section. Each one simply returns
8 * the matching private member stored in the Configurator object. In plain
9 * words: this file is the lookup table that maps a type name, such as
10 * ServerConfig, to the actual settings object of that type held by the
11 * Configurator.
12 *
13 * WHY THIS FILE MATTERS IN THE SERVER:
14 * Code throughout the server asks for its settings by type, for example
15 * `store.config().get<Configurator::ServerConfig>()`. Those calls only link
16 * successfully because this file defines each specialization. Without it, the
17 * compiler accepts the calls but the linker reports undefined references, so
18 * the server cannot obtain any of its configuration sections at runtime.
19 * Keeping the definitions here (not in the header) also means adding a new
20 * section requires updating this single mapping.
21 *
22 * CONCEPTS TO LEARN (for beginners):
23 * - C++ concepts and constraints:
24 * https://en.cppreference.com/w/cpp/language/constraints
25 * - Explicit (full) template specialization:
26 * https://en.cppreference.com/w/cpp/language/template_specialization
27 * - Function templates:
28 * https://en.cppreference.com/w/cpp/language/function_template
29 *
30 * @author Amr Osman <dr3mro@gmail.com>
31 * @date 2026-11-16
32 */
