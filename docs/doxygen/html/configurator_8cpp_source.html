1/**
2 * @file configurator.cpp
3 * @brief Explicit Configurator::get<T>() specializations that expose each configuration section.
4 * @details The Configurator class declares a generic get<T>() accessor but does not define its
5 * behaviour for any particular type. This file supplies one explicit specialization per
6 * configuration section. Each one simply returns the matching private member stored in the
7 * Configurator object. In plain words: this file is the lookup table that maps a type name,
8 * such as ServerConfig, to the actual settings object of that type held by the Configurator.
9 *
10 * WHY THIS FILE MATTERS IN THE SERVER:
11 * Code throughout the server asks for its settings by type, for example
12 * `store.config().get<Configurator::ServerConfig>()`. Those calls only link successfully
13 * because this file defines each specialization. Without it, the compiler accepts the calls
14 * but the linker reports undefined references, so the server cannot obtain any of its
15 * configuration sections at runtime. Keeping the definitions here (not in the header) also
16 * means adding a new section requires updating this single mapping.
17 *
18 * CONCEPTS TO LEARN (for beginners):
19 * - C++ concepts and constraints: https://en.cppreference.com/w/cpp/language/constraints
20 * - Explicit (full) template specialization: https://en.cppreference.com/w/cpp/language/template_specialization
21 * - Function templates: https://en.cppreference.com/w/cpp/language/function_template
22 *
23 * @author Amr Osman <dr3mro@gmail.com>
24 * @date 2026-11-16
25 */
