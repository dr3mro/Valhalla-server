Detailed Description

Definitions for StaffController and its explicit template instantiations.

Unlike the other controller adapters, this file contains real logic: request parsing, staff-management authorisation, and either a staff SQL statement or an outbound invite POST to the email-sender daemon.

In plain words, each function here does the same three-step dance: (1) read the JSON request body, (2) ask GateKeeper whether the caller is allowed to manage this service's staff, and (3) only if allowed, actually do the work — run SQL to add/remove a member, or POST an invitation to the email daemon. If anything goes wrong, the catch block turns the exception into an HTTP error reply. The macros at the end build a concrete version of the class for each service entity type so the route layer can link to it.

WHY THIS FILE MATTERS IN THE SERVER: This is the implementation behind the staff HTTP routes: it is where permission is actually enforced before any staff change is made and where invitations are sent. It is called through StaffControllerBase by the route layer, and it calls into Controller (for SQL), GateKeeper (for permission) and Communicate (for the email POST). Without it, the staff interface would have no behaviour and no one could add, remove or invite staff.
