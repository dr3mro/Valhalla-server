1/**
2 * @file store.hpp
3 * @brief Process-wide service locator keyed by C++ type.
4 * @details This file declares Store, the one place in the server that keeps a single shared object for each C++ type.
5 * Callers ask for an object by its type (for example "the database client"), and Store either hands back the
6 * object it already made or builds it the first time. It also offers a cheap per-thread cache for busy request
7 * code and a way to swap an object for a fake one during tests.
8 *
9 * WHY THIS FILE MATTERS IN THE SERVER:
10 * Store is the server's service locator. Controllers and other long-lived objects call Store::getObject<T>() or
11 * Store::cachedObject<T>() to get shared helpers such as the database client instead of building their own. Because the
12 * object is built only once, expensive resources are never duplicated. Tests call replaceObject<T>() to install a fake
13 * without changing production code. Without Store, every caller would have to pass the same helper around by hand and
14 * could easily end up with a different copy.
15 *
16 * CONCEPTS TO LEARN (for beginners):
17 * - Service locator: one well-known place you ask for shared objects, by type instead of by name. https://en.wikipedia.org/wiki/Service_locator_pattern
18 * - thread_local: storage that has one separate copy per running thread. https://en.cppreference.com/w/cpp/language/storage_duration
19 * - Atomic memory order: rules saying when one thread's writes become visible to another thread. https://en.cppreference.com/w/cpp/atomic/memory_order
20 * - RAII: using a small local object to lock a mutex and unlock it automatically at the end of a scope. https://en.cppreference.com/w/cpp/language/raii
21 *
22 * @author Amr Osman <dr3mro@gmail.com>
23 * @date 2026-11-16
24 */

37/**
38 * @class Store
39 * @brief Process-wide service locator that maps a type to one shared instance.
40 *
41 * @details The class has no non-static state; the actual registry is a set of file-scope static members defined in
42 * store.cpp. Access is guarded by a single mutex, and a separate atomic generation counter lets per-thread
43 * caches notice replacements. Objects are owned through shared_ptr<void> and recovered by static_pointer_cast
44 * using typeid(T) as the key, so a lookup by type resolves to the concrete pointer stored for that type.
45 *
46 * In plain words: a "singleton" is one single object shared by the entire program. You never create a Store
47 * object; you just call its static functions. A shared_ptr is a smart pointer that keeps its object alive for
48 * as long as anyone still holds it, then destroys it automatically when the last holder lets go, so no manual
49 * delete is needed. typeid(T) is a small tag that identifies a C++ type while the program runs, which lets the
50 * map be keyed by type instead of by a name. A mutex is a lock that only one thread may hold at a time, which
51 * stops two threads from changing the map at once and corrupting it. static_pointer_cast simply relabels the
52 * generic stored pointer as a T pointer; it performs no runtime type check.
53 * @note registerObject refuses duplicates; getObject lazily constructs on first use; replaceObject overwrites without
54 * throwing and is intended for injecting test doubles. ("Lazily" means the object is not built until somebody
55 * actually asks for it; a "test double" is a fake object used in place of the real one during tests.)
56 * @see tests/support/fake_db.hpp
57 */

90 /**
91 * @brief Explicitly creates and registers a singleton, rejecting a type that is already registered.
92 *
93 * @details The duplicate check and the insertion use separate lock scopes so T's constructor runs without the
94 * mutex held. That keeps arbitrary constructor code, which may re-enter Store, from deadlocking on the
95 * inventory lock. ("Deadlock" means two operations waiting on each other forever.)
96 * @tparam T Type to register; used as the inventory key.
97 * @tparam Args Constructor argument types for T.
98 * @param[in] args Arguments forwarded to T's constructor (passed on unchanged).
99 * @return A shared_ptr owning the newly created object, so the caller can use it too.
100 * @throws std::runtime_error if an object of type T is already registered.
101 */
102 template <typename T, typename... Args>
103 static std::shared_ptr<T> registerObject(Args&&... args)
104 {
105 {
106 std::scoped_lock lock(inventoryMutex); // lock only for the check, then release at the closing brace
107 if (inventory.find(typeid(T)) != inventory.end()) // end() means "not found", so anything else means a duplicate
108 {
109 throw std::runtime_error("Object type already registered." + std::string(typeid(T).name())); // refuse: there may be only one per type
110 }
111 }
112
113 auto object = std::make_shared<T>(std::forward<Args>(args)...); // build outside the lock: constructors may be slow or call back into Store
114
115 {
116 std::scoped_lock lock(inventoryMutex); // lock again briefly, now only to publish the finished object
117 inventory[typeid(T)] = object; // operator[] inserts the new entry under this type's key
118 }
119
120 return object; // caller gets shared ownership; the registry keeps its own copy alive too
121 }

123 /**
124 * @brief Returns the singleton for T, constructing it on first use.
125 *
126 * @details The fast path looks up the type under the mutex and returns the existing instance. On a miss the object
127 * is constructed outside the lock (see the inline comment below) and then re-checked under the lock before
128 * being published, so concurrent first calls cannot install two different instances. Constructor arguments
129 * are therefore only used on the first successful construction and ignored on later calls.
130 * @tparam T Type to look up or create; its type_index is the inventory key.
131 * @tparam Args Constructor argument types for T.
132 * @param[in] args Arguments forwarded to T's constructor when a new object is needed.
133 * @return A shared_ptr to the registered singleton; ownership is shared with all other callers and with the Store.
134 * @note Marked nodiscard because callers are expected to use the shared instance; the Store itself retains a strong
135 * reference in the inventory. ("Strong reference" means a shared_ptr that keeps the object alive.)
136 * @see registerObject(), cachedObject(), replaceObject()
137 */
138 template <typename T, typename... Args>
139 [[nodiscard("Warning: You should never discard the returned object")]] static std::shared_ptr<T> getObject(Args&&... args)
140 {
141 {
142 std::scoped_lock lock(inventoryMutex); // hold the lock only while searching the shared map
143 auto object = inventory.find(typeid(T)); // find gives an iterator pointing at the entry, or end()
144 if (object != inventory.end()) // found: somebody already registered this type
145 {
146 return std::static_pointer_cast<T>(object->second); // relabel the stored void pointer as T and return it
147 }
148 }
149
150 // Construct outside the lock (construction may be expensive), but
151 // re-check under the lock before publishing so concurrent first access
152 // cannot install two different instances or throw "already registered".
153 auto candidate = std::make_shared<T>(std::forward<Args>(args)...); // build a possible new instance without blocking other threads
154
155 {
156 std::scoped_lock lock(inventoryMutex); // re-check while locked: another thread may have won the race
157 auto object = inventory.find(typeid(T)); // look for the type again
158 if (object != inventory.end()) // another thread published one first
159 {
160 return std::static_pointer_cast<T>(object->second); // return their instance; our candidate is discarded
161 }
162 inventory[typeid(T)] = candidate; // no one else did, so publish ours
163 }
164 return candidate; // return the object we created; the registry also holds a copy
165 }

167 /**
168 * @brief Thread-local cached lookup of T, refreshed only when the Store generation changes.
169 *
170 * @details Each thread keeps its own shared_ptr and the generation value it last saw. The generation is loaded with
171 * acquire semantics, pairing with the release fetch_add in replaceObject(), so a thread that observes a new
172 * generation also observes the replacement. A mismatch or an empty cache triggers a full getObject<T>()
173 * lookup; otherwise the cached pointer is returned without touching the mutex.
174 *
175 * In plain words: looking in the registry needs a lock, which is too slow to do for every web request. So
176 * each thread remembers the pointer it got last time. "Acquire" and "release" are a pair of promises: after
177 * replaceObject() publishes a new pointer with "release", any thread that reads the new number with
178 * "acquire" is also guaranteed to see that new pointer, not a stale one. This is cheap because a normal
179 * read of the counter is enough most of the time; the lock is only used when something actually changed.
180 * @tparam T Type to look up; on first use it must be constructible by getObject<T>() with no arguments.
181 * @return A shared_ptr to the current singleton for T.
182 * @note The returned pointer is nodiscard; callers should use it instead of re-fetching through getObject().
183 * @see getObject(), replaceObject()
184 */
185 // Like getObject<T>(), but cheap enough for the request path: each thread keeps its own pointer and only goes back to the
186 // Store (mutex + type lookup) after replaceObject() has changed something. Use it where an object is looked up for every
187 // request (member initializers of objects built per request); long-lived objects can keep calling getObject<T>() once.
188 template <typename T>
189 [[nodiscard]] static std::shared_ptr<T> cachedObject()
190 {
191 thread_local std::shared_ptr<T> cached; // one copy per thread, so reading it needs no lock at all
192 thread_local uint64_t seen = 0; // the generation this thread last saw; 0 means "never checked yet"
193 const uint64_t now = generation.load(std::memory_order_acquire); // acquire: pairs with release in replaceObject()
194 if (!cached || seen != now) // empty cache, or the registry was changed since last time
195 {
196 cached = getObject<T>(); // pay for the full locked lookup and remember the answer
197 seen = now; // mark our cache as up to date with the current generation
198 }
199 return cached; // fast path: hand back this thread's own pointer without touching the mutex
200 }

202 /**
203 * @brief Overwrites the singleton registered for T and invalidates every thread-local cache.
204 *
205 * @details Uses operator[] on the inventory, so it works whether or not T was registered before. The generation is
206 * incremented with release semantics so threads that acquire it in cachedObject() see the new pointer and
207 * re-fetch from the Store. ("Invalidates" means it makes every thread's saved pointer out of date.)
208 * @tparam T Type whose registered instance is replaced.
209 * @param[in] obj New instance to register; may be null, in which case the key maps to an empty shared_ptr.
210 * @note Does not throw: this is intended for test harnesses injecting fakes.
211 * @see cachedObject()
212 */
213 // Replace an already-registered singleton without throwing.
214 // Used by test harnesses to inject fakes (see tests/support/fake_db.hpp).
215 template <typename T>
216 static void replaceObject(std::shared_ptr<T> obj)
217 {
218 std::scoped_lock lock(inventoryMutex); // only one thread may change the registry at a time
219 inventory[typeid(T)] = obj; // overwrite, or insert if there was no entry before
220 generation.fetch_add(1, std::memory_order_release); // makes every thread's cachedObject<T>() look again; release publishes the new pointer
221 }
