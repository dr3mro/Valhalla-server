Detailed Description

Shared base for session/token managers offering session-table and JWT helpers.

KeeprBase centralizes the SQL and JWT logic used by both SessionManager and TokenManager: reading/updating session rows, formatting UTC timestamps, decoding and verifying JWTs, and loading password hashes. It is stateless apart from a cached copy of TokenManagerParameters; database access goes through a cached DatabaseController obtained from Store, so instances share the same pool.

Note
Assignment is disabled because the token parameters are cached at construction; copying/moving is allowed so derived managers can use normal value semantics.
See also
SessionManager, TokenManager

For a beginner: this is a "toolbox base class". The two managers inherit it so they automatically have all these helpers. It caches the token settings once at construction, which is why assignment is removed - assigning could silently replace those cached settings. Copy/move construction is fine because it just carries the settings and the shared config handle along.

Validates a decoded JWT against current session state and its signature/claims.

Checks the "llodt" logout claim against the stored value, the account active flag, then verifies the token with createTokenVerifier().

Parameters

[out]messageFailure reason.
[in,out]decodedTokenToken to verify.
Returns
True if the token is still valid.
Exceptions
DatabaseBusyPropagated to callers.

Verifies a decoded JWT against live session state and its signature/claims. The "llodt" claim is compared with the stored last logout time so tokens issued before a logout are invalidated, and suspended accounts are rejected. The return value of the session read is not consulted here; the loaded fields are used directly. clientLoginData: Identity/state accumulator; session fields are refreshed. message: Failure reason. decodedToken: Token to verify. Returns True if the token remains valid. Throws DatabaseBusy: When the database is busy.
