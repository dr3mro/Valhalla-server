Detailed Description

Drogon filter that validates the Bearer token and identifies the requester.

This file defines the Auth filter, the last step of the SECURE filter chain. It reads the Authorization header, checks that it starts with "Bearer ", and asks GateKeeper whether the token is valid. It supports two modes: a normal blocking check and an asynchronous coroutine check chosen by the database configuration. On success it writes "clientID" and "clientGroup" onto the request so controllers know who is calling; on failure it sends a JSON 401 (or a 503 when the database is too busy).

WHY THIS FILE MATTERS IN THE SERVER: This is the gatekeeper of the whole protected API. Drogon calls it before any SECURE route handler, so it is the component that turns an anonymous HTTP request into an identified, permission-checkable one. Downstream controllers (clients, clinics, staff and so on) read the identity attributes it sets and would have no idea who the caller was without it. It calls GateKeeper for validation and the Store/service locator to find shared objects. Without this file every protected route would be open to anyone.
