1/**
2 * @file all_routes.hpp
3 * @brief Single inclusion point that registers every API v2 Drogon controller.
4 * @details Drogon discovers controllers through the static registration performed by each
5 * included header's METHOD_LIST macros; this aggregator has no logic of its own. Include it
6 * where the whole v2 route set must be linked in (e.g. application startup), and rely on the
7 * per-controller METHOD_ADD declarations for paths, verbs and filter chains. The IWYU pragmas
8 * keep the headers as explicit dependencies even though no symbol from them is named here.
9 *
10 * WHY THIS FILE MATTERS IN THE SERVER:
11 * This is the "one-stop shop" for the whole version-2 HTTP API. When the server starts, including
12 * this single header pulls in every route controller (appointments, clients, clinics, docs, hello,
13 * services and staff). Drogon registers each controller automatically just because its header is
14 * seen, so this file is what makes all those URLs actually exist. Without it, none of the v2
15 * endpoints would be reachable and the API would be empty.
16 *
17 * CONCEPTS TO LEARN (for beginners):
18 * - Static registration: simply including a header can register code with a framework, without
19 * calling any function yourself.
20 * - HTTP filters/middleware: https://drogon.docsforge.com/master/filter/
21 * - CORS: https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS
22 *
23 * @author Amr Osman <dr3mro@gmail.com>
24 * @date 2026-11-16
25 */
