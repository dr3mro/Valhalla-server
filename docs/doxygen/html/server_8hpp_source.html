1/**
2 * @file server.hpp
3 * @brief Declaration of Server, the application-level owner of Drogon setup and startup/shutdown sequencing.
4 *
5 * @details This header declares the Server class. The class gathers everything needed to start the application: a
6 * snapshot of the configuration, the shared singletons, and the small filter/middleware objects used by the
7 * two global request hooks. Its constructor caches those objects; run() performs the actual Drogon setup,
8 * blocks in the event loop, and then shuts the worker pools down in a safe order.
9 *
10 * WHY THIS FILE MATTERS IN THE SERVER:
11 * Server is the single coordinator between the tiny main() function and the rest of the application. main() only
12 * creates a Server and calls run(); everything else — printing the banner, choosing the listening port and thread
13 * count, adding CORS and method checks to requests, and draining the database and password workers on exit — is
14 * either done here or started from here. Without this header there would be no agreed interface for main() to call,
15 * and the startup/shutdown ordering rules would have nowhere to live.
16 *
17 * CONCEPTS TO LEARN (for beginners):
18 * - Smart pointers and ownership (shared_ptr): https://en.cppreference.com/w/cpp/memory/shared_ptr
19 * - RAII (resources tied to object lifetime): https://en.cppreference.com/w/cpp/language/raii
20 * - The Rule of Five (copy/move special members): https://en.cppreference.com/w/cpp/language/rule_of_three
21 *
22 * @author Amr Osman <dr3mro@gmail.com>
23 * @date 2026-11-16
24 */

41/**
42 * @class Server
43 * @brief Owns application startup: configuration, banner, Drogon wiring, and post-run executor shutdown.
44 *
45 * @details The constructor resolves long-lived singletons from the Store and copies the server and database
46 * configuration by value, so later changes to the Configurator are not seen through those copies. run()
47 * configures and starts the Drogon application, installs the pre-routing and pre-sending advice (method
48 * filtering and CORS), and blocks until the event loops stop. Only then does it shut the worker pools down,
49 * while the Store singletons they depend on are still alive. The filter and middleware members are created
50 * eagerly so one instance is reused. Registration of the included Drogon components (including the route
51 * headers brought in by all_routes.hpp) is handled by Drogon itself, outside this class.
52 * @note Not copyable. Move construction is defaulted; move assignment is deleted.
53 * @see Cors, Store, Configurator
54 */
