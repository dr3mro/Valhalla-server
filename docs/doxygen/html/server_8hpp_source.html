1/**
2 * @file server.hpp
3 * @brief Declaration of Server, the application-level owner of Drogon setup and
4 * startup/shutdown sequencing.
5 *
6 * @details This header declares the Server class. The class gathers everything
7 * needed to start the application: a snapshot of the configuration, the shared
8 * singletons, and the small filter/middleware objects used by the two global
9 * request hooks. Its constructor caches those objects; run() performs the
10 * actual Drogon setup, blocks in the event loop, and then shuts the worker
11 * pools down in a safe order.
12 *
13 * WHY THIS FILE MATTERS IN THE SERVER:
14 * Server is the single coordinator between the tiny main() function and the
15 * rest of the application. main() only creates a Server and calls run();
16 * everything else — printing the banner, choosing the listening port and thread
17 * count, adding CORS and method checks to requests, and draining the database
18 * and password workers on exit — is either done here or started from here.
19 * Without this header there would be no agreed interface for main() to call,
20 * and the startup/shutdown ordering rules would have nowhere to live.
21 *
22 * CONCEPTS TO LEARN (for beginners):
23 * - Smart pointers and ownership (shared_ptr):
24 * https://en.cppreference.com/w/cpp/memory/shared_ptr
25 * - RAII (resources tied to object lifetime):
26 * https://en.cppreference.com/w/cpp/language/raii
27 * - The Rule of Five (copy/move special members):
28 * https://en.cppreference.com/w/cpp/language/rule_of_three
29 *
30 * @author Amr Osman <dr3mro@gmail.com>
31 * @date 2026-11-16
32 */

59/**
60 * @class Server
61 * @brief Owns application startup: configuration, banner, Drogon wiring, and
62 * post-run executor shutdown.
63 *
64 * @details The constructor resolves long-lived singletons from the Store and
65 * copies the server and database configuration by value, so later changes to
66 * the Configurator are not seen through those copies. run() configures and
67 * starts the Drogon application, installs the pre-routing and pre-sending
68 * advice (method filtering and CORS), and blocks until the event loops stop.
69 * Only then does it shut the worker pools down, while the Store singletons they
70 * depend on are still alive. The filter and middleware members are created
71 * eagerly so one instance is reused. Registration of the included
72 * Drogon components (including the route headers brought in by all_routes.hpp)
73 * is handled by Drogon itself, outside this class.
74 * @note Not copyable. Move construction is defaulted; move assignment is
75 * deleted.
76 * @see Cors, Store, Configurator
77 */
