Detailed Description

Stateless collection of checks applied to client JSON before it reaches the database.

Entity controllers call these helpers with the parsed request body, the target table name and a Rule describing per-key exceptions. Validation is performed against a cached snapshot of the database schema (DatabaseSchema), not against a live query, so the helpers are cheap enough for the request path. Every entry point is static and reports failures by filling an api::v2::Http::Error (code + message) and returning false rather than throwing; exceptions from the JSON layer are caught and converted to 400 responses.

Note
All members are static; Validator carries no state and needs no lifetime management.
Warning
The cached schema must have been populated before these helpers are used, otherwise table lookups fail and the validators return false.
See also
Rule, DatabaseSchema, api::v2::Http::Error

Applies field-specific regex rules to client-supplied entity data.

Parameters
[in]dataJSON object whose fields are validated by name (username, password, phone, email, dob, gender). Fields without a rule are passed through if they are non-empty strings.
[out]errorFilled with 400 and a descriptive message on the first bad field.
[out]db_dataReceives the validated (key, value) pairs ready for a database call.
Returns
True when all fields pass; false on the first invalid or empty value.

Regexes are compiled once into a function-local static map because compiling std::regex per request is expensive. A field with a validator must be a string, non-empty and match its pattern; an unvalidated field is copied only when it is a non-empty string.

Note
Entries already present in db_data are preserved; results are inserted, not assigned.

See Validator::clientRegexValidation. Fields with a registered regex must be non-empty strings matching that pattern; unrecognised fields are accepted only if they are non-empty strings. The first offending field stops processing and fills error. Accepted pairs are inserted into db_data.

Validates a create (INSERT) request body against a table's schema.

Parameters
[in]tablenameTarget table used for the schema lookup.
[in]dataParsed JSON body; must be a non-empty object.
[out]errorFilled with code/message on failure; HTTP 400 for malformed input or missing/non-nullable columns, HTTP 400 for an unknown table.
[in]rulePer-key exceptions (e.g. ignore a server-generated "id").
Returns
True when the body satisfies all schema constraints.

Runs null/empty check, schema lookup, per-column type and nullability checks (checkColumns), and key-presence/prohibition checks (ensureAllKeysExist). Exceptions from jsoncons (such as a non-object body) are caught and reported as BAD_REQUEST, since these inputs are client errors rather than server faults.

See also
validateDatabaseUpdateSchema, checkColumns, ensureAllKeysExist

See Validator::validateDatabaseCreateSchema. Processing order: reject null/empty input, resolve the table schema, validate present columns' types and missing non-nullable columns, then enforce per-key rules. The duplicated-key check is intentionally disabled because jsoncons parsing already rejects duplicate keys upstream.
