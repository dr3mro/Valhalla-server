Detailed Description

Implementation for gatekeeper.

This file turns the GateKeeper declarations into working code. Login parses the request, looks up the stored password hash, then moves the slow hashing, the session write and the token creation onto a password-worker thread so the server's IO threads stay free. Authentication first tries a cached session and only falls back to verifying the JWT when there is no live session. All permission helpers are one-line forwarders to PermissionManager, and a set of explicit template instantiations generates those helpers for every supported entity type.

WHY THIS FILE MATTERS IN THE SERVER: This is where the security facade actually does its job. Controllers call login(), logout() and the can*() helpers; filters call isDosAttack(); the authentication filter calls isAuthenticationValid(). This file wires those calls to SessionManager, TokenManager, DOSDetector, PermissionManager and PasswordWorker. If it were missing, the declared GateKeeper interface would have no implementation and nothing security-related would link or run. The macro block at the bottom is what makes the permission helpers exist for concrete types like User, Patient and ClinicAppointment.
