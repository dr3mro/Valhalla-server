Detailed Description

Routes Drogon/Trantor log records through an asynchronous spdlog logger.

Owns one spdlog async_logger writing to a rotating file sink and/or a colour console sink, selected from Configurator's ServerConfig. Construction initialises spdlog's shared thread pool, registers the logger by name, and installs it as both spdlog's default logger and Trantor's spdlog backend, so framework, utility and application records all use the same sink configuration.

Intended as a process-wide singleton created by Server through Store; spdlog registration is global, so more than one instance would try to register the same name twice. Logging itself is thread-safe via spdlog's sinks and worker pool.

Note
The file path is log_dir concatenated with log_file from ServerConfig; rotation occurs at MAX_LOG_SIZE bytes across MAX_LOG_FILES files.

◆ Logger()

Logger::Logger ( )

Builds, configures and globally registers the asynchronous logger.

Reads ServerConfig from Configurator (via Store), initialises the spdlog thread pool (queue size THREADPOOL, THREADS workers), builds the console and rotating-file sinks with a shared pattern, adds only the sinks enabled by log_to_console / log_to_file, then registers the logger as "Project Valhalla" and enables Trantor's spdlog forwarding.

Postcondition
spdlog has a registered default logger and Trantor routes to it.
Warning
On spdlog_ex (e.g. a duplicate registration) the error is printed to stdout and construction succeeds with logger_ unset; later log() calls would then dereference a null pointer. Construct once, before any component starts logging.
