Detailed Description

Mutable accumulator that carries a client's identity through login and authentication.

The same object is passed from GateKeeper into SessionManager, TokenManager and KeeprBase helpers. Fields are optional because they are populated at different stages: some arrive from the request (group, ip_address), some are read from the database (is_active, lastLogoutTime), and some are produced by token generation (token, expireTime). Call sites value-initialize this struct (for example ClientLoginData{}), so the non-optional scalar members start zero-initialized and are only meaningful once the corresponding helper sets them.

Note
passwordHash and passwordMatch are declared here but are never assigned in src/; the login flow carries the hash as a separate local value.
Identity claims (username, clientId, group, ip_address, lastLogoutTime) are bound into the JWT and re-checked on validation, so changing one invalidates the token.

In everyday terms, think of this struct as a "passport application form" that gets stamped at each desk. It begins nearly empty, the HTTP request fills in the group and IP, the database fills in the active flag and last logout time, and the token generator fills in the token and its expiry. std::optional is used for each field because "not filled in yet" is a normal state, not an error, and it lets helpers check has_value() before using a field. The two plain bool fields are not optional, so they start as false after ClientLoginData{} and must be explicitly set from the database before they mean anything.
