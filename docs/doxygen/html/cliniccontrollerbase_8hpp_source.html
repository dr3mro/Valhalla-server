2 * @file cliniccontrollerbase.hpp
3 * @brief Abstract contract for clinic-service entity handlers (patients,
4 * visits, reports, prescriptions, ...).
5 * @details Declares `ClinicControllerBase`, a pure interface for clinical data.
6 * It keeps the subset of CRUDS that makes sense for medical records and adds
7 * GetVisits for a patient's visit history. As with the other bases, every
8 * operation is pure virtual (`= 0`) and answers through a CALLBACK_.
9 *
10 * WHY THIS FILE MATTERS IN THE SERVER:
11 * Clinical entities do not all support the same actions: for example, only
12 * Patient and Visits can be deleted, and only Patient supports search and visit
13 * lookup. This interface defines the common surface the HTTP layer can rely on,
14 * while letting the concrete ClinicController return a clear "not implemented"
15 * for unsupported actions. Without it, clinic endpoints would have no uniform
16 * contract.
17 *
18 * CONCEPTS TO LEARN (for beginners):
19 * - Virtual functions / abstract classes:
20 * https://en.cppreference.com/w/cpp/language/abstract_class
21 * - Callback / std::function:
22 * https://en.cppreference.com/w/cpp/utility/functional/function
23 * - Coroutines (co_await / drogon::Task):
24 * https://en.cppreference.com/w/cpp/language/coroutines
25 * - std::optional (an id that may be missing):
26 * https://en.cppreference.com/w/cpp/utility/optional
27 * - Namespaces and `using namespace`:
28 * https://en.cppreference.com/w/cpp/language/namespace
29 *
30 * @author Amr Osman <dr3mro@gmail.com>
31 * @date 2026-11-16
32 */

50 * visits, reports, prescriptions, ...).
51 * @details Defines the subset of CRUDS operations meaningful for clinic
52 * entities plus patient visit retrieval. Implementations (ClinicController)
53 * specialize behaviour per entity type: for example only Patient/Visits support
54 * Delete, only Patient supports Search and GetVisits. `CALLBACK_` is
55 * `std::function<void(int, const std::string&)>`; implementations
56 * answer exactly once with an HTTP status code and body on every completing
57 * path, including "not implemented" rejections.

59 * contract; Update and Search are synchronous only.
