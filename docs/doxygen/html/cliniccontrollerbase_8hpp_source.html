1/**
2 * @file cliniccontrollerbase.hpp
3 * @brief Abstract contract for clinic-service entity handlers (patients, visits, reports, prescriptions, ...).
4 * @details Declares `ClinicControllerBase`, a pure interface for clinical data. It keeps the subset of CRUDS that
5 * makes sense for medical records and adds GetVisits for a patient's visit history. As with the other bases,
6 * every operation is pure virtual (`= 0`) and answers through a CALLBACK_.
7 *
8 * WHY THIS FILE MATTERS IN THE SERVER:
9 * Clinical entities do not all support the same actions: for example, only Patient and Visits can be deleted, and
10 * only Patient supports search and visit lookup. This interface defines the common surface the HTTP layer can rely
11 * on, while letting the concrete ClinicController return a clear "not implemented" for unsupported actions. Without
12 * it, clinic endpoints would have no uniform contract.
13 *
14 * CONCEPTS TO LEARN (for beginners):
15 * - Virtual functions / abstract classes: https://en.cppreference.com/w/cpp/language/abstract_class
16 * - Callback / std::function: https://en.cppreference.com/w/cpp/utility/functional/function
17 * - Coroutines (co_await / drogon::Task): https://en.cppreference.com/w/cpp/language/coroutines
18 * - std::optional (an id that may be missing): https://en.cppreference.com/w/cpp/utility/optional
19 * - Namespaces and `using namespace`: https://en.cppreference.com/w/cpp/language/namespace
20 *
21 * @author Amr Osman <dr3mro@gmail.com>
22 * @date 2026-11-16
23 */

35/**

37 * @brief Abstract contract for clinic-service entity handlers (patients, visits, reports, prescriptions, ...).
38 * @details Defines the subset of CRUDS operations meaningful for clinic entities plus patient visit retrieval.
39 * Implementations (ClinicController) specialize behaviour per entity type: for example only Patient/Visits
40 * support Delete, only Patient supports Search and GetVisits. `CALLBACK_` is
41 * `std::function<void(int, const std::string&)>`; implementations answer exactly once with an HTTP status
42 * code and body on every completing path, including "not implemented" rejections.
43 * @note Only Create, Read, Delete and GetVisits have coroutine forms in this contract; Update and Search are
44 * synchronous only.
45 * @see ClinicController, EntityControllerBase
