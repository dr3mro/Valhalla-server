Detailed Description

Username column name used by Client::exists() and the client validation layer.

This header defines the Client entity for "people" tables such as users and providers. It replaces the generic JSON-based create and update builders from Entity with versions that consume already-validated (column, value) pairs, so untrusted JSON never reaches SQL generation. It also builds the UPDATE that toggles the active flag (suspend/activate), and can check whether a username is already taken in the table.

WHY THIS FILE MATTERS IN THE SERVER: User and provider accounts need stricter handling than ordinary records: their input is validated and password-hashed before insertion, they can be suspended, and usernames must be unique. Controllers use Client (via User and Provider) to produce those specialised statements while reusing read/delete/search from Entity. Without it, account creation would bypass validation and there would be no safe way to suspend a client.

CONCEPTS TO LEARN (for beginners):

  • std::optional: https://en.cppreference.com/w/cpp/utility/optional
  • C++ concept: a named compile-time requirement on a template type; here it restricts Client helpers to payload types that really carry client data or an id.
  • SQL parameter binding: put $1, $2, ... markers in the SQL and pass the real values separately; see https://en.cppreference.com/w/cpp or the libpqxx documentation.
  • "final" on a virtual function means subclasses may not override it again - a guard that keeps the validated create/update path from being bypassed.
