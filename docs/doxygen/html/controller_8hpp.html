Detailed Description

Reusable persistence engine for the API's CRUDS (Create/Read/Update/Delete/Search) operations.

This header defines the Controller class, a template-heavy helper that turns an entity object into SQL and turns the database's answer into an HTTP status plus a response body. It offers both ordinary blocking methods (Create, Read, ...) and coroutine versions (CreateAsync, ReadAsync, ...) for the async server loop. It is meant to be read from top to bottom: first the constructor, then the public CRUDS helpers, then the two shared cruds/crudsAsync implementations near the bottom.

WHY THIS FILE MATTERS IN THE SERVER: It is the storage engine that sits underneath the request-facing handlers. When an HTTP request arrives, Drogon routes it to an EntityController / ClientController / ClinicController, and those classes call this Controller to do the actual work. This class in turn calls DatabaseController (see databasecontroller.hpp) to run parameterized SQL against PostgreSQL. Without this file the handlers would have no way to insert, read, update, delete or search rows, and the callback that finally answers the client would never be invoked.
