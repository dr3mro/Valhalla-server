Detailed Description

template<Service_t T>
class ServiceController< T >

Service-entity controller that adapts EntityController to ServiceControllerBase.

Template Parameters
TService entity type; must satisfy Service_t (derived from Service).

A thin, stateless adapter: every CRUD+S entry point simply forwards to the same-named method of EntityController<T>, so validation, authorisation, entity construction, SQL execution, JSON marshalling and error→HTTP mapping all live in that base. The template parameter supplies the table name, SQL statements and permission queries used there. This class exists to give service entities a distinct interface (and therefore a distinct entry in the route registry) from appointment entities.

Plain-language version: T is whichever entity class we are handling (say Clinics). The Service_t after template is a "concept" — a compile-time check that refuses to build this class unless T is really a service type. Because this class stores no data ("stateless"), its only job is to hand the arguments to EntityController<T> and let that base do everything. 

     Explicit instantiations are provided for `Clinics`, `Pharmacies`,

Laboratories and RadiologyCenters; the route layer stores shared_ptr<ServiceController<T>> values in a variant and dispatches to them through ServiceControllerBase.

Note
Copy and move are disabled so each registered controller has a single identity.
