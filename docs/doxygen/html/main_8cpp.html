Detailed Description

Process entry point: build the Server and translate uncaught exceptions into a failure exit status.

This file contains nothing but the program's main() function. It creates a single Server object on the heap using a smart pointer, then hands control to Server::run(). If anything throws a C++ exception during setup or shutdown, it prints a short reason to standard error and exits with a failure status.

WHY THIS FILE MATTERS IN THE SERVER: This is where the whole process begins. The operating system calls main() first; main() creates the Server, and the Server in turn configures and runs Drogon (the web framework) together with all the routes, filters and database helpers. Without this file there would be no starting point, so nothing would ever listen for HTTP requests. main() is also the last line of defence: it turns an uncaught exception into a readable error message and a non-zero exit code, which is what process supervisors and Docker expect when a program fails.

CONCEPTS TO LEARN (for beginners):

  • Exceptions and try/catch: https://en.cppreference.com/w/cpp/language/exceptions

Constructs the Server and transfers control to it.

There is no command-line parsing: every setting is read from the environment by Configurator while the Server is constructed. The unique_ptr owns the Server for the whole process; because Server::run() blocks until the event loops stop, the object survives long enough to finish its post-run shutdown sequence.
