Detailed Description

Environment-driven configuration sections and typed accessors for the server.

This header defines Configurator, a container that owns one settings object for each part of the server. Every settings object reads its values from environment variables when it is created, using hard-coded defaults from the Defaults namespace when a variable is missing or invalid. Callers retrieve a settings object by asking for its type, for example get<Configurator::ServerConfig>(). Most values are logged on startup with secrets hidden, and a few counts are automatically sized from the machine's CPU count.

WHY THIS FILE MATTERS IN THE SERVER: This is the single home for ALL runtime settings. The Store owns one Configurator and builds it before the Drogon IO threads start; then the server, database, gatekeeper and worker components pull their settings from it through get<T>(). Nothing else reads environment variables directly for these options. Without this file, settings would be scattered and inconsistent, and there would be no central place to print or override them. Note that values are captured once at construction, so changing the environment later has no effect.
