1/**
2 * @file tokenmanager.hpp
3 * @brief Creates and checks the signed tokens used to authenticate clients.
4 * (Originally: "Issues and validates the HS256 JWTs that authenticate
5 * clients.")
6 * @details This header declares TokenManager. It builds a JWT (a signed,
7 * self-contained credential) from the client's identity, and checks
8 * tokens that clients send back. A coroutine variant performs the
9 * checks without blocking web request threads.
10 *
11 * WHY THIS FILE MATTERS IN THE SERVER:
12 * After a successful login, the client receives one of these tokens and sends
13 * it with later requests. TokenManager is what turns that string back into a
14 * trusted identity. Without it, the server could not recognize returning users.
15 *
16 * CONCEPTS TO LEARN (for beginners):
17 * - JWT (JSON Web Token): https://jwt.io/introduction
18 * - HMAC / HS256 signing: https://en.wikipedia.org/wiki/HMAC
19 * - Coroutines in C++: https://en.cppreference.com/w/cpp/language/coroutines
20 * - std::optional: https://en.cppreference.com/w/cpp/utility/optional
21 *
22 * @author Amr Osman <dr3mro@gmail.com>
23 * @date 2026-11-16
24 */

36 /**
37 * @class TokenManager
38 * @brief Issues and validates the HS256 JWTs that authenticate clients.
39 * @details Token parameters (issuer, type, validity and secret) come
40 * from the Configurator via KeeprBase. Generated tokens carry identity
41 * claims and last-logout time so a later logout can be detected.
42 * Validation first decodes the token into the ClientLoginData, then
43 * verifies it with KeeprBase::validateToken; the coroutine form awaits
44 * the async variant.
45 * @see KeeprBase
46 * In everyday words: this class is like a badge printer and badge
47 * checker. It stamps a badge with the user's identity and an expiry,
48 * and later checks that a presented badge is genuine and still current.
49 */
