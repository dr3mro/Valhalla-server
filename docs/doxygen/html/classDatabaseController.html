Detailed Description

Single gateway through which controllers execute SQL, in both blocking and coroutine form.

Owns no query logic of its own: it acquires a connection (synchronously through a DatabaseConnectionPool and DatabaseHanndler, or asynchronously through AsyncDbClient), invokes the matching Database/ asyncdb helper, and returns an std::optional result that is empty when the database is unavailable, a connection cannot be acquired, or the query fails. Every public method is virtual so tests can inject fakes through Store::replaceObject.

Backend construction is lazy (see ensureBackends): the pool constructor terminates the process when PostgreSQL is unreachable, which would otherwise make the class unconstructible in hermetic tests. The double-checked backendsReady_ flag makes that init a single atomic load on the hot path. In hermetic test mode the pool is never created and all query paths deterministically return std::nullopt.

Query results are returned as JSON objects/arrays or plain scalars. Identifiers (table/column names) cannot be bound as parameters, so the few methods that interpolate them accept only fixed, trusted names.

Note
Non-copyable and non-movable: the singleton is shared through Store, never duplicated.
Warning
Pool exhaustion is not a query failure: DatabaseBusy is propagated so callers can answer 503 with Retry-After instead of 500.
See also
Controller, Store, DatabaseBusy
