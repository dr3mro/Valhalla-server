1/**
2 * @file clientcontrollerbase.hpp
3 * @brief Abstract contract for client (User/Provider) handlers: CRUDS plus
4 * session and account-state operations.
5 * @details Declares `ClientControllerBase`, a pure interface for accounts that
6 * can log in. It starts with the usual CRUDS set and adds authentication
7 * (Login/Logout), account state (Suspend/Activate), password reset and service
8 * lookup. Every method is pure virtual (`= 0`), so a concrete class must
9 * implement all of them.
10 *
11 * WHY THIS FILE MATTERS IN THE SERVER:
12 * Clients (users and providers) need more than plain record storage: they need
13 * sessions and a logged-in state. This interface is what the HTTP routing layer
14 * programs against for those endpoints. The concrete ClientController (see
15 * clientcontroller.hpp) implements it by reusing EntityController for the
16 * storage part and delegating sessions to GateKeeper. Without this contract the
17 * auth endpoints and the generic entity endpoints would not line up.
18 *
19 * CONCEPTS TO LEARN (for beginners):
20 * - Virtual functions / abstract classes:
21 * https://en.cppreference.com/w/cpp/language/abstract_class
22 * - Callback / std::function:
23 * https://en.cppreference.com/w/cpp/utility/functional/function
24 * - Coroutines (co_await / drogon::Task):
25 * https://en.cppreference.com/w/cpp/language/coroutines
26 * - std::optional (a token or id that may be absent):
27 * https://en.cppreference.com/w/cpp/utility/optional
28 * - Worker threads / concurrency:
29 * https://en.cppreference.com/w/cpp/thread/thread
30 *
31 * @author Amr Osman <dr3mro@gmail.com>
32 * @date 2026-11-16
33 */

52/**
53 * @class ClientControllerBase
54 * @brief Abstract contract for client (User/Provider) handlers: CRUDS plus
55 * session and account-state operations.
56 * @details Extends the entity-style CRUDS surface with authentication
57 * (Login/Logout), account suspension state (Suspend/Activate), password reset
58 * and service lookup. Implementations (ClientController) authorize via
59 * GateKeeper and, for Create/Update, move the expensive password
60 * hashing to a dedicated worker pool. `CALLBACK_` is `std::function<void(int,
61 * const std::string&)>`; implementations answer exactly once with an HTTP
62 * status code and body on every path that completes. Coroutine variants borrow
63 * their arguments and must be awaited while those arguments and the controller
64 * are alive.
65 * @note Not every operation has a coroutine variant: Logout and ResetPassword
66 * are synchronous only in this contract. The `ip_address` argument is used by
67 * GateKeeper for login/logout bookkeeping.
68 * @see ClientController, EntityControllerBase
69 */
