1/**
2 * @file asyncsqlbinder.hpp
3 * @brief Adapter between the pqxx::params produced by entity SQL builders and Drogon's incremental SQL binder.
4 * @details This header declares three functions that bridge two database libraries. Entity code already builds its
5 * query parameters with libpqxx's pqxx::params; these functions copy those parameters into Drogon's binder
6 * so the same entity code works on both the synchronous and the asynchronous database path. One function
7 * also exposes the parameters as plain text, which is handy for tests that have no real database client.
8 *
9 * WHY THIS FILE MATTERS IN THE SERVER:
10 * Whenever a controller runs SQL asynchronously it calls asyncdb::execSqlCoro() from this module. That function is
11 * the only way the SQL text and its bound values reach Drogon, so this file is the seam that lets the existing
12 * entity SQL builders keep producing pqxx::params unchanged. It protects the server from SQL injection because
13 * values are bound separately from the statement text, and it preserves binary data by copying exact byte lengths.
14 * Without this adapter, every entity builder would have to be rewritten for the async path, and binary values or
15 * nulls could easily be corrupted as they cross between the two libraries.
16 *
17 * CONCEPTS TO LEARN (for beginners):
18 * - Drogon DbClient and SQL binding: https://drogon.docsforge.com/master/database/
19 * - C++20 coroutines and co_await: https://en.cppreference.com/w/cpp/language/co_await
20 * - libpqxx parameters (pqxx::params): https://pqxx.org/
21 * - std::optional (a value that may be absent): https://en.cppreference.com/w/cpp/utility/optional
22 * - Parameterised queries and SQL injection: https://owasp.org/www-community/attacks/SQL_Injection
23 *
24 * @author Amr Osman <dr3mro@gmail.com>
25 * @date 2026-11-16
26 */

58 /**
59 * @brief Binds a pqxx parameter list into an already-created Drogon SQL binder.
60 * @details Nulls are bound as SQL NULL; binary-format parameters are bound as a `RawParameter` whose bytes are held in a
61 * `shared_ptr`-owned buffer so they stay valid after this call; everything else is bound as a text string.
62 * Values are bound in append order.
63 * @param[in,out] binder Binder that already holds the statement text.
64 * @param[in] params Parameters to bind; not modified.
65 * @pre The number and order of parameters match the placeholders in `binder`'s statement; this function does not check.
66 */
67 void bindParams(drogon::orm::internal::SqlBinder& binder, const pqxx::params& params); // `binder` is changed in place; `params` is only read.

69 /**
70 * @brief Prepares a parameterised statement on a Drogon client and returns its awaiter.
71 * @details Creates a binder with `client << sql`, binds `params` in append order via `bindParams`, then moves the binder
72 * into an `SqlAwaiter`. The statement executes when the caller co_awaits the returned awaiter, which owns the
73 * binder and its bound parameters until then.
74 * @param[in] client Drogon client to execute on; must outlive the awaited operation.
75 * @param[in] sql Statement using `$1`, `$2`, ... placeholders.
76 * @param[in] params Values for those placeholders.
77 * @return Awaiter that performs the statement when awaited.
78 * @note Calling this function alone does not execute SQL; the return value must be co_awaited.
79 */
80 [[nodiscard]] drogon::orm::internal::SqlAwaiter execSqlCoro(drogon::orm::DbClient& client, const std::string& sql, // The client reference must stay alive; the SQL text uses numbered placeholders such as $1.
81 const pqxx::params& params); // The values for those placeholders, in the exact order they were appended.
82} // namespace asyncdb
