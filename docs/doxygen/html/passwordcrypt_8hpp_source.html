1/**
2 * @file passwordcrypt.hpp
3 * @brief A small wrapper around libsodium's password-hashing functions.
4 * (Originally: "Thin wrapper around libsodium's password-hashing primitives used by the password workers.")
5 * @details This header declares a class that turns a plain-text password into a
6 * stored hash, and that checks a plain-text password against a stored
7 * hash. New hashes use the Argon2id recipe, but older scrypt hashes are
8 * still understood so existing accounts keep working. The class holds
9 * almost no data of its own; its main job is to make sure libsodium is
10 * ready before any hashing happens.
11 *
12 * WHY THIS FILE MATTERS IN THE SERVER:
13 * Checking passwords is the first line of defence for every login. The session
14 * manager calls PasswordCrypt (through PasswordWorker) to verify passwords off
15 * the web request threads. Without this file there would be no safe way to store
16 * or check passwords, so nobody could log in to Valhalla.
17 *
18 * CONCEPTS TO LEARN (for beginners):
19 * - Password hashing (Argon2/scrypt): https://doc.libsodium.org/password_hashing/
20 * - OWASP password storage advice: https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html
21 * - std::optional (a value that may be missing): https://en.cppreference.com/w/cpp/utility/optional
22 * - Threads and concurrency in C++: https://en.cppreference.com/w/cpp/thread
23 *
24 * @author Amr Osman <dr3mro@gmail.com>
25 * @date 2026-11-16
26 */

32/**
33 * @class PasswordCrypt
34 * @brief Thin wrapper around libsodium's password-hashing primitives used by the password workers.
35 * @details Owns no per-instance state beyond ensuring libsodium is initialized in the constructor.
36 * Hashing uses Argon2id at OWASP's minimum recommended cost; verification also accepts
37 * hashes produced by the legacy scrypt scheme so existing accounts remain valid.
38 * The stored hash is self-describing (algorithm, cost, salt and digest), which is how
39 * verifyPassword selects the algorithm without any extra metadata.
40 *
41 * In everyday words: a "hash" is a one-way, deliberately slow, scrambled version
42 * of a password. We store the hash and never the real password. "Argon2id" and
43 * "scrypt" are the names of the recipes used to scramble it. "Self-describing"
44 * means the hash string itself records the recipe and the amount of work used,
45 * so verification needs no separate note. A "salt" is random data mixed in so
46 * two people with the same password still get different hashes.
47 * @warning The hashes are intentionally expensive; callers must run hashPassword()/verifyPassword()
48 * on a PasswordWorker, never on a Drogon IO thread. See runOnPasswordWorker().
49 */

68 * @brief Produces a self-describing Argon2id hash string for @p password.
69 * @details Uses a random salt generated by libsodium. The cost parameters are deliberately
70 * low enough for the dedicated worker pool but meet OWASP's minimum recommendations.

79 */

82 /**
83 * @brief Verifies @p password against a stored self-describing hash.
84 * @details Selects the algorithm from the hash prefix: Argon2id (`$argon2...`) or the
85 * legacy scrypt format (`$7$`). An unrecognized prefix yields `false` rather
86 * than an exception.
87 * In everyday words: the stored hash begins with a short label that
88 * says which recipe made it. We read that label, run the matching
89 * check, and return true only for a real match. Anything we do not
90 * understand is safely treated as a failed login, not a crash.
91 * @param[in] password Plaintext password to check.
92 * @param[in] hash Stored hash string produced by hashPassword() or by the legacy scheme.
93 * @return `true` only if the password matches the hash; `false` on mismatch, unknown
94 * algorithm, or malformed hash.
95 */
96 [[nodiscard]] bool verifyPassword(const std::string& password, const std::string& hash); // [[nodiscard]] makes the compiler warn if a caller ignores this true/false answer.
