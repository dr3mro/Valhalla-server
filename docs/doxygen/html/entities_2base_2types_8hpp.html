Detailed Description

CRUD operation payload types and the EntityType variant used by entity builders.

This header declares the small value objects that describe every operation the API can request: Create_t, Read_t, Update_t, Delete_t, plus Search_t, client payloads, suspend and staff data. Most of them derive from a shared Entity_t template that stores a payload and an optional id. At the bottom, EntityType lists them all as one std::variant, which is how an Entity keeps track of which operation it represents. Several types also validate and sanitise input before the SQL builders ever see it.

WHY THIS FILE MATTERS IN THE SERVER: These are the data carriers between controllers and the entity layer. A controller parses an HTTP body into one of these types, and the Entity/Client/Service builders read it back to produce SQL. Validation lives here (for example Search_t rejects unsafe column names), so bad input is stopped in one place instead of being trusted by every SQL builder. Without this file the builders would have no typed, validated description of what the client asked for.

CONCEPTS TO LEARN (for beginners):

  • std::variant: https://en.cppreference.com/w/cpp/utility/variant
  • std::optional: https://en.cppreference.com/w/cpp/utility/optional
  • SQL parameter binding: put $1, $2, ... markers in the SQL and pass the real values separately; see https://en.cppreference.com/w/cpp or the libpqxx documentation.
  • A "template" is a blueprint for a class that works with many types. Here the blueprint takes a type parameter named S, and the compiler generates a separate class for each S that is used.
