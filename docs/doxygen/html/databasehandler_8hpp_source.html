1/**
2 * @file databasehandler.hpp
3 * @brief RAII lease of a single pooled Database connection.
4 * @details This header declares DatabaseHanndler (spelled exactly that way in this codebase).
5 * Its constructor leases one connection from a DatabaseConnectionPool, waiting up to
6 * the configured timeout, and its destructor returns that connection. That makes it
7 * a small RAII guard: as long as the handler object lives, the caller owns a valid
8 * database connection, and it is released automatically on every exit path.
9 *
10 * WHY THIS FILE MATTERS IN THE SERVER:
11 * This class is the bridge between the connection pool and the code that actually runs SQL.
12 * Controllers and the watchdog create one on the stack per request or health check; they call
13 * get_connection() to reach the Database and run queries, then simply let the handler go out
14 * of scope. Because returning happens in the destructor, a thrown query exception cannot leak
15 * a connection. Without this guard, callers would have to remember to return every lease by
16 * hand, and one forgotten path would starve the pool.
17 *
18 * CONCEPTS TO LEARN (for beginners):
19 * - RAII (resource acquisition is initialisation): https://en.cppreference.com/w/cpp/language/raii
20 * - std::shared_ptr (shared ownership): https://en.cppreference.com/w/cpp/memory/shared_ptr
21 * - std::move (transferring ownership instead of copying): https://en.cppreference.com/w/cpp/utility/move
22 * - Stack allocation and object lifetime: https://en.cppreference.com/w/cpp/language/storage_duration
23 *
24 * @author Amr Osman <dr3mro@gmail.com>
25 * @date 2026-11-16
26 */
