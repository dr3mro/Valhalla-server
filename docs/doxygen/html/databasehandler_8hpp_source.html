1/**
2 * @file databasehandler.hpp
3 * @brief RAII lease of a single pooled Database connection.
4 * @details This header declares DatabaseHanndler (spelled exactly that way in
5 * this codebase). Its constructor leases one connection from a
6 * DatabaseConnectionPool, waiting up to the configured timeout, and its
7 * destructor returns that connection. That makes it a small RAII guard: as long
8 * as the handler object lives, the caller owns a valid database connection, and
9 * it is released automatically on every exit path.
10 *
11 * WHY THIS FILE MATTERS IN THE SERVER:
12 * This class is the bridge between the connection pool and the code that
13 * actually runs SQL. Controllers and the watchdog create one on the stack per
14 * request or health check; they call get_connection() to reach the Database and
15 * run queries, then simply let the handler go out of scope. Because returning
16 * happens in the destructor, a thrown query exception cannot leak a connection.
17 * Without this guard, callers would have to remember to return every lease by
18 * hand, and one forgotten path would starve the pool.
19 *
20 * CONCEPTS TO LEARN (for beginners):
21 * - RAII (resource acquisition is initialisation):
22 * https://en.cppreference.com/w/cpp/language/raii
23 * - std::shared_ptr (shared ownership):
24 * https://en.cppreference.com/w/cpp/memory/shared_ptr
25 * - std::move (transferring ownership instead of copying):
26 * https://en.cppreference.com/w/cpp/utility/move
27 * - Stack allocation and object lifetime:
28 * https://en.cppreference.com/w/cpp/language/storage_duration
29 *
30 * @author Amr Osman <dr3mro@gmail.com>
31 * @date 2026-11-16
32 */
