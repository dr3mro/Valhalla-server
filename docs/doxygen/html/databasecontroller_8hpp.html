Detailed Description

Single gateway through which controllers execute SQL, in both blocking and coroutine form.

Declares DatabaseController, the one class that knows how to run a SQL statement and map the result to JSON. It offers a blocking family (executeQuery, executeReadQuery, executeSearchQuery, ...) backed by a connection pool, and an async family (executeQueryCoro, ...) backed by Drogon's AsyncDbClient. Every method is virtual so tests can swap in a fake, and every one returns an std::optional that is empty when the database is unavailable or the query fails.

WHY THIS FILE MATTERS IN THE SERVER: It is the single choke point between the application and PostgreSQL. The Controller class calls these methods, so connection handling, transaction rules and error mapping (including the special DatabaseBusy signal) live in one place. Without it, every caller would have to manage connections itself, and "database down" could not be handled consistently as a 503 instead of a crash.

CONCEPTS TO LEARN (for beginners):

  • Virtual functions / polymorphism (all methods are virtual for test injection): https://en.cppreference.com/w/cpp/language/virtual
  • Connection pooling and lazy initialization: https://en.cppreference.com/w/cpp/language/raii
  • std::optional (empty means "no result"): https://en.cppreference.com/w/cpp/utility/optional
  • std::atomic (thread-safe flag): https://en.cppreference.com/w/cpp/atomic/atomic
  • std::shared_ptr / std::unique_ptr (ownership of backends and connections): https://en.cppreference.com/w/cpp/memory/shared_ptr
  • Coroutines (co_await / drogon::Task): https://en.cppreference.com/w/cpp/language/coroutines
