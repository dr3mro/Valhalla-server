1/**
2 * @file doc.hpp
3 * @brief Serves the Swagger UI page that documents the API.
4 * @details This file defines the Doc controller with a single endpoint. That
5 * endpoint returns an HTML page containing the Swagger UI, an interactive
6 * documentation viewer for the REST API. The HTML is embedded into the program
7 * at build time from docs/api.html, so the running server does not need to read
8 * any file from disk. The handler simply builds a 200 HTML response and hands
9 * it to the callback; there is no per-request state or authentication.
10 *
11 * WHY THIS FILE MATTERS IN THE SERVER:
12 * This is the human-facing documentation endpoint of the API. Developers and
13 * testers open it in a browser to see every available route, its parameters and
14 * its response format. Drogon calls it at the /api/v2/doc URL; it uses no
15 * database and no controllers. Because it goes through the INSECURE chain it is
16 * rate-limited and timed but needs no token, so anyone can read the public
17 * docs.
18 *
19 * CONCEPTS TO LEARN (for beginners):
20 * - Swagger / OpenAPI: a standard way to describe REST APIs
21 * (https://swagger.io/).
22 * - HTTP GET and status 200:
23 * https://developer.mozilla.org/en-US/docs/Web/HTTP/Methods
24 * - CORS: https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS
25 *
26 * @author Amr Osman <dr3mro@gmail.com>
27 * @date 2026-11-16
28 */
