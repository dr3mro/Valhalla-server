1/**
2 * @file entitycontrollerbase.hpp
3 * @brief Abstract contract for the request-facing CRUDS handlers exposed for
4 * every entity type.
5 * @details This header declares `EntityControllerBase`, a pure interface: it
6 * lists the ten operations (Create/Read/ Update/Delete/Search and their Async
7 * twins) that every ordinary entity handler must provide. It contains no
8 * implementation at all - each method ends in `= 0`, meaning "derived classes
9 * must fill this in".
10 *
11 * WHY THIS FILE MATTERS IN THE SERVER:
12 * It is the contract between the HTTP routing layer and the concrete
13 * EntityController<T>. Drogon handlers program against this base type, so they
14 * can treat a User, a Patient or a Report uniformly. Without this interface the
15 * router would have to know every entity type, and there would be no single
16 * place guaranteeing that all entities expose the same CRUDS operations. The
17 * real work is done by EntityController (see entitycontroller.hpp), which
18 * implements everything declared here.
19 *
20 * CONCEPTS TO LEARN (for beginners):
21 * - Virtual functions / polymorphism:
22 * https://en.cppreference.com/w/cpp/language/virtual
23 * - Abstract classes and pure virtual functions (`= 0`):
24 * https://en.cppreference.com/w/cpp/language/abstract_class
25 * - Callback / std::function:
26 * https://en.cppreference.com/w/cpp/utility/functional/function
27 * - Coroutines (co_await / drogon::Task):
28 * https://en.cppreference.com/w/cpp/language/coroutines
29 * - std::optional and std::string_view:
30 * https://en.cppreference.com/w/cpp/utility/optional
31 *
32 * @author Amr Osman <dr3mro@gmail.com>
33 * @date 2026-11-16
34 */

55/**
56 * @class EntityControllerBase
57 * @brief Abstract contract for the request-facing CRUDS handlers exposed for
58 * every entity type.
59 * @details Declares five operations (Create, Read, Update, Delete, Search),
60 * each in a synchronous callback form and in a `drogon::Task` coroutine form.
61 * Implementations (see EntityController) are expected to parse and validate @p
62 * data, authorize the action with @p requester, construct the entity and
63 * delegate persistence to the lower-level Controller. The callback is
64 * `CALLBACK_` = `std::function<void(int, const std::string&)>`: implementations
65 * invoke it once with an HTTP status code and a response body, including on
66 * error paths.
67 *
68 * The interface itself does not own or store any state; derived
69 * controllers supply the collaborators. The lifetime of @p callback, @p
70 * requester and @p data (and of the owning controller) must extend until the
71 * coroutine variants complete, because they are borrowed by the
72 * coroutine frame.
73 * @note The `const Requester&&` parameter is passed by rvalue reference by the
74 * existing callers; treat it as a borrowed, immutable principal rather than
75 * assuming ownership is transferred.
76 * @see EntityController, Controller
77 */
