2 * @file entitycontrollerbase.hpp
3 * @brief Abstract contract for the request-facing CRUDS handlers exposed for every entity type.
4 * @details This header declares `EntityControllerBase`, a pure interface: it lists the ten operations (Create/Read/
5 * Update/Delete/Search and their Async twins) that every ordinary entity handler must provide. It contains
6 * no implementation at all - each method ends in `= 0`, meaning "derived classes must fill this in".
7 *
8 * WHY THIS FILE MATTERS IN THE SERVER:
9 * It is the contract between the HTTP routing layer and the concrete EntityController<T>. Drogon handlers program
10 * against this base type, so they can treat a User, a Patient or a Report uniformly. Without this interface the
11 * router would have to know every entity type, and there would be no single place guaranteeing that all entities
12 * expose the same CRUDS operations. The real work is done by EntityController (see entitycontroller.hpp), which
13 * implements everything declared here.
14 *
15 * CONCEPTS TO LEARN (for beginners):
16 * - Virtual functions / polymorphism: https://en.cppreference.com/w/cpp/language/virtual
17 * - Abstract classes and pure virtual functions (`= 0`): https://en.cppreference.com/w/cpp/language/abstract_class
18 * - Callback / std::function: https://en.cppreference.com/w/cpp/utility/functional/function
19 * - Coroutines (co_await / drogon::Task): https://en.cppreference.com/w/cpp/language/coroutines
20 * - std::optional and std::string_view: https://en.cppreference.com/w/cpp/utility/optional
21 *
22 * @author Amr Osman <dr3mro@gmail.com>
23 * @date 2026-11-16
24 */

39/**
40 * @class EntityControllerBase
41 * @brief Abstract contract for the request-facing CRUDS handlers exposed for every entity type.
42 * @details Declares five operations (Create, Read, Update, Delete, Search), each in a synchronous callback form and
43 * in a `drogon::Task` coroutine form. Implementations (see EntityController) are expected to parse and
44 * validate @p data, authorize the action with @p requester, construct the entity and delegate persistence
45 * to the lower-level Controller. The callback is `CALLBACK_` = `std::function<void(int, const std::string&)>`:
46 * implementations invoke it once with an HTTP status code and a response body, including on error paths.
47 *
48 * The interface itself does not own or store any state; derived controllers supply the collaborators. The
49 * lifetime of @p callback, @p requester and @p data (and of the owning controller) must extend until the
50 * coroutine variants complete, because they are borrowed by the coroutine frame.
51 * @note The `const Requester&&` parameter is passed by rvalue reference by the existing callers; treat it as a
52 * borrowed, immutable principal rather than assuming ownership is transferred.
53 * @see EntityController, Controller
54 */
55class EntityControllerBase
56{
57 public:
58 explicit EntityControllerBase() = default; // Nothing to initialize; the interface holds no state.
59 EntityControllerBase(const EntityControllerBase&) = default; // Copyable because there is no state to duplicate.
60 EntityControllerBase(EntityControllerBase&&) = default; // Movable for the same reason.
61 EntityControllerBase& operator=(const EntityControllerBase&) = default; // Assignment is a no-op copy of no state.
62 EntityControllerBase& operator=(EntityControllerBase&&) = default; // Move assignment is likewise a no-op.
