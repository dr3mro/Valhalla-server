Detailed Description

Owns application startup: configuration, banner, Drogon wiring, and post-run executor shutdown.

The constructor resolves long-lived singletons from the Store and copies the server and database configuration by value, so later changes to the Configurator are not seen through those copies. run() configures and starts the Drogon application, installs the pre-routing and pre-sending advice (method filtering and CORS), and blocks until the event loops stop. Only then does it shut the worker pools down, while the Store singletons they depend on are still alive. The filter and middleware members are created eagerly so one instance is reused. Registration of the included Drogon components (including the route headers brought in by all_routes.hpp) is handled by Drogon itself, outside this class.

Note
Not copyable. Move construction is defaulted; move assignment is deleted.

Cors, Store, Configurator

◆ run()

int Server::run ( )

Prints the banner, configures and runs Drogon, then drains the worker pools.

Configures and runs the Drogon application, then drains the worker pools.

Blocks in Drogon's run() until the event loops stop. On the way out it shuts down DbExecutor first and PasswordWorker second, because database tasks may hand work to the password worker. Any std::exception from setup or teardown is reported through Message and turned into EXIT_FAILURE.

Returns
EXIT_SUCCESS after a clean run and shutdown, EXIT_FAILURE on a reported exception.
Note
SIGTERM handling is disabled (see the .disableSigtermHandling() call in the implementation), so shutdown is driven by the framework event loops stopping rather than by Drogon's own signal handler.
See also
print_banner(), Store, DbExecutor, PasswordWorker

Registers the listener, thread count, upload path, log level, a custom 404 page and two global advice hooks: the pre-routing hook short-circuits OPTIONS and rejects uncommon methods, and the pre-sending hook applies CORS headers to every response. When db_config_.async is set, an AsyncDbClient is registered in the Store before the event loops start. Control returns from drogon::app().run() only after the event loops stop.

Returns
EXIT_SUCCESS on a clean run and shutdown, EXIT_FAILURE if setup or shutdown throws std::exception.
Note
The post-run shutdown order is deliberate: DbExecutor is drained before PasswordWorker because database tasks may enqueue password work. Both happen here, while the Store singletons still exist, rather than in static destructors.
See also
print_banner(), Cors::apply(), Store::getObject()
