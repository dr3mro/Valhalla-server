1/**
2 * @file base.hpp
3 * @brief Default construction; the interface itself carries no state.
4 * @details Base is the shared blueprint (an "abstract base class") for every
5 * entity in the server. It declares the five SQL statement builders that each
6 * concrete entity must supply: create, read, update, delete and search. It also
7 * provides a small helper called Binder that safely turns values into numbered
8 * placeholders, so data is never pasted into SQL text. The class stores no data
9 * of its own; it only fixes the shape that all derived entity classes follow.
10 *
11 * WHY THIS FILE MATTERS IN THE SERVER:
12 * This is the bottom contract of the whole entity layer. Controllers call the
13 * five getSql* functions through a Base reference without caring which concrete
14 * table is involved, and every concrete entity (Entity, Client, Service,
15 * Appointment, Case and friends) inherits from Base. Without it there would be
16 * no single way to ask "give me the SQL for this operation", and the safe
17 * binding pattern would have to be copied into every table class by hand.
18 *
19 * CONCEPTS TO LEARN (for beginners):
20 * - std::optional: https://en.cppreference.com/w/cpp/utility/optional
21 * - Abstract base class / pure virtual function: a function ending in "= 0"
22 * forces every child class to implement it, so callers can use one common
23 * interface for all of them.
24 * - SQL parameter binding: put $1, $2, ... markers in the SQL and pass the real
25 * values separately, so user data can never change the meaning of the query;
26 * see https://en.cppreference.com/w/cpp or the libpqxx documentation.
27 *
28 * @author Amr Osman <dr3mro@gmail.com>
29 * @date 2026-11-16
30 */

48/**
49 * Base class for all entities in the application.
50 * Provides common functionality for creating, reading, updating, deleting, and
51 * searching entities. Derived classes must implement the virtual functions to
52 * provide the SQL statements for each operation.
53 *
54 * @details The interface separates deciding what SQL to run from executing it:
55 * a caller asks an entity for a statement plus its bound parameters and hands
56 * both to the database layer. Every builder returns SQL containing only $1, $2,
57 * ... placeholders and appends the actual values to the caller-supplied
58 * pqxx::params, so column values are never written into the SQL text. A builder
59 * returns std::nullopt when it cannot produce a usable statement.
60 * @note The destructor is virtual because entities are used polymorphically
61 * through this interface.
62 * @see Entity, Binder
63 * @note For a beginner: "virtual" means the call is decided at runtime, so a
64 * Base pointer can reach the correct derived-class version of each function. "=
65 * 0" means this class gives no body and forces children to provide one; that is
66 * what makes Base abstract (not instantiable).
67 */
68class Base {
69 public:
70 /**
71 * @brief Default construction; the interface itself carries no state.
72 */
73 explicit Base() = default; // "explicit" with no arguments simply documents
74 // that this is a deliberate default constructor.
75
76 /**
77 * @brief Permits safe deletion through a Base pointer.
78 */
79 virtual ~Base() = default; // Virtual so deleting a derived object through
80 // a Base* calls the right destructor.

83 // values in params; values are never written into the SQL text.
84 /**
85 * @brief Builds the INSERT statement for the entity's payload.
86 * @param[out] params Receives the values for the returned placeholders;
87 * builders clear it first.

90 * @note Values are bound rather than embedded in the returned text.
91 */

140 // A builder asks the binder how each value is written into the query:
141 // bind(value) stores it in params and returns its placeholder ($1, $2,
142 // ...).
143 /**
144 * @brief Appends values to a pqxx::params and hands back the matching SQL
145 * placeholders.
146 * @details Construction clears the supplied container, so each fresh Binder
147 * restarts numbering at $1 for one statement. Routing every value through
148 * bind() is what keeps callers from concatenating untrusted data into SQL
149 * text.
150 * @note Holds a borrowed reference to the params container and must not
151 * outlive it.
152 * @note For a beginner: this is a helper struct that derived builders
153 * create on the stack for one SQL statement. It remembers a running counter
154 * so the first value becomes $1, the second $2, and so on, which is exactly
155 * what PostgreSQL expects in the prepared query.
156 */
157 struct Binder {
158 /**
159 * @brief Binds to p and clears it so the first bind() produces $1.
160 */
161 explicit Binder(pqxx::params& p) : params(p) {
162 params = {};
163 } // Keep a reference to the caller's container and empty it so
164 // placeholders start fresh at $1.
165
166 /**
167 * @brief Appends a value to the parameter container and returns its
168 * placeholder.
169 * @tparam T A type accepted by pqxx::params::append.
170 * @param[in] value The value to bind; copied into the container by
171 * pqxx.
172 * @return A placeholder of the form "$n", with n increasing in call
173 * order from 1.
174 */
175 // A template so any value type pqxx
176 // understands can be bound the same way.
177 template <typename T>
178 std::string bind(const T& value) {
179 params.append(value); // Store the real value separately from the
180 // SQL text (safe binding).
181 return fmt::format("${}",
182 ++index); // Bump the counter first, then return $1,
183 // $2, ... in that order.
184 }
185
186 private:
187 /**
188 * @brief The borrowed parameter container that receives appended
189 * values.
190 */
191 pqxx::params& params; // A reference, not a copy: we fill the caller's
192 // container directly; it must outlive this Binder.
193
194 /**
195 * @brief Count of values bound so far; drives the $n placeholder
196 * numbering.
197 */
198 size_t index = 0; // Starts at zero so the first ++index yields 1; this
199 // is the $n counter.
200 };
201};
