1/**
2 * @file configurator.hpp
3 * @brief Environment-driven configuration sections and typed accessors for the
4 * server.
5 * @details This header defines Configurator, a container that owns one settings
6 * object for each part of the server. Every settings object reads its values
7 * from environment variables when it is created, using hard-coded defaults from
8 * the Defaults namespace when a variable is missing or invalid. Callers
9 * retrieve a settings object by asking for its type, for example
10 * get<Configurator::ServerConfig>(). Most values are logged on startup with
11 * secrets hidden, and a few counts are automatically sized from the machine's
12 * CPU count.
13 *
14 * WHY THIS FILE MATTERS IN THE SERVER:
15 * This is the single home for ALL runtime settings. The Store owns one
16 * Configurator and builds it before the Drogon IO threads start; then the
17 * server, database, gatekeeper and worker components pull their settings from
18 * it through get<T>(). Nothing else reads environment variables directly for
19 * these options. Without this file, settings would be scattered and
20 * inconsistent, and there would be no central place to print or override them.
21 * Note that values are captured once at construction, so changing the
22 * environment later has no effect.
23 *
24 * CONCEPTS TO LEARN (for beginners):
25 * - Environment variables: https://man7.org/linux/man-pages/man7/environ.7.html
26 * - C++ concepts and constraints:
27 * https://en.cppreference.com/w/cpp/language/constraints
28 * - Function templates:
29 * https://en.cppreference.com/w/cpp/language/function_template
30 * - std::chrono durations (lengths of time):
31 * https://en.cppreference.com/w/cpp/chrono/duration
32 * - std::unordered_set (a collection of unique values):
33 * https://en.cppreference.com/w/cpp/container/unordered_set
34 *
35 * @author Amr Osman <dr3mro@gmail.com>
36 * @date 2026-11-16
37 */

92/**
93 * @class Configurator
94 * @brief Owning aggregate of all runtime configuration sections.
95 *
96 * @details Holds one instance per configuration domain (server, database, DoS
97 * detection, tokens, frontend, email sender, caches and workers) plus a testing
98 * section. Every section derives from EnvLoader and reads its values from the
99 * process environment in its constructor, falling back to the constants in the
100 * @ref Defaults namespace when a variable is absent or invalid. The
101 * Configurator is intended to be a single process-wide object owned by Store
102 * and fully constructed before the Drogon IO threads start; sections are
103 * retrieved by type through get<T>().
104 *
105 * @note Values are snapshotted at construction time, so later changes to the
106 * environment do not affect an already-built Configurator.
107 * @warning get() returns a non-const reference and performs no locking. Treat
108 * sections as read-only once construction is complete; unsynchronized
109 * concurrent mutation is unsafe.
110 * @see EnvLoader, Defaults, Store
111 */

113// then read by the rest of the server.

115 public: // Everything below is Configurator's public interface, callable by
116 // other code.
117 /** @brief Default-constructs every configuration section (each reads the
118 * environment). */
119 Configurator() = default; // Let each member's own constructor run; that is
120 // where the environment is read.
121 /** @brief Virtual destructor; derived configurators may extend the section
122 * set. */
123 virtual ~Configurator() =
124 default; // Virtual so a Configurator subclass can be destroyed
125 // correctly through a base pointer.
