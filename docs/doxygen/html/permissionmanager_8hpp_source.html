1/**
2 * @file permissionmanager.hpp
3 * @brief The single place that answers "may this person do this thing to this record?".
4 * (Originally: "Central authorization facade: answers "may this requester perform this operation on this entity?".")
5 * @details This header declares PermissionManager, a class full of `canCreate`,
6 * `canRead`, `canUpdate` and `canDelete` checks. Each check is written
7 * once as a template and works for several entity types. Every check
8 * also has an `Async` coroutine twin used by the non-blocking routes.
9 *
10 * WHY THIS FILE MATTERS IN THE SERVER:
11 * Controllers call these checks before changing or returning data, so this is
12 * the gate that stops one client reading another client's records. It decides
13 * who may manage staff, view services, and edit cases or appointments. Without
14 * it, authorization rules would be scattered and easy to get wrong.
15 *
16 * CONCEPTS TO LEARN (for beginners):
17 * - Authorization vs authentication: https://en.wikipedia.org/wiki/Authorization
18 * - C++ templates: https://en.cppreference.com/w/cpp/language/templates
19 * - Concepts (constraints on template arguments): https://en.cppreference.com/w/cpp/language/constraints
20 * - Coroutines in C++: https://en.cppreference.com/w/cpp/language/coroutines
21 *
22 * @author Amr Osman <dr3mro@gmail.com>
23 * @date 2026-11-16
24 */

39 /**
40 * @class PermissionManager
41 * @brief Central authorization facade: answers "may this requester perform this operation on this entity?".
42 * @details Overloads are grouped by the concept constraining the entity type (Client_t,
43 * Service_t, Case_t, Appointment_t). Most checks load the entity's permission JSON
44 * (through PermissionManagerPrivate::getPermissionsOfEntity) and apply the service
45 * owner/admin/staff rules; the plain client checks only assert that the requester's
46 * group and id match the target client. Every `*Async` overload is the coroutine
47 * counterpart of a synchronous check; those needing permission data use the async
48 * (database/cached) lookup. On denial, @p error receives a status and reason.
49 * @note Each overload is explicitly instantiated for the supported entity types at the
50 * bottom of permissionmanager.cpp; this header only declares them.
51 * In everyday words: think of this class as a receptionist who checks
52 * ID before letting someone do something. It does not fetch data itself;
53 * it asks PermissionManagerPrivate for the facts and then decides.
54 */
55 class PermissionManager // A facade: one simple entry point hiding the detailed checks.
